Compose PhoneNumberField's country picker from the library `Combobox.Content/List/Item/Empty` instead of a hand-built copy of the same popup, and simplify the state hook (phone-number-field.md §8.15–§8.17).

The popup now takes the family's chrome, so its rendered output changes. The popup loses `p-2` and `max-w-72` and gains `relative group/combobox-content max-h-(--available-height) max-w-(--available-width) overflow-hidden`; its search box takes the shared compact chrome instead of a local `mb-2`; the list takes the shared height clamp, which fixes a clamp that was inert because its `calc()` was missing the whitespace CSS requires — the popup used to grow to the height of every country row; the empty row takes the shared hidden/flex pair; and options pick up the `[&_svg:not([class*='size-'])]:size-4` and `data-highlighted:**:text-accent-foreground` rules the copy had missed. `Combobox.Content` pins an anchored popup's minimum width to the anchor, so the popup is now the width of the field. Each option also loses a wrapper `div` and renders its check indicator last rather than first, and new `data-slot` values appear on the popup, list, options, and empty row. The field root, InputGroup, flag trigger, positioner, search input and addon, item indicator, and number input emit exactly the classes they did before.

A keystroke now runs one libphonenumber parse rather than 2–4 depending on `outputFormat`, an international paste runs three rather than six, and country names resolve once per locale rather than once per row per render. One behaviour changes with it: in `international` mode under a controlled `value`, the field shows what was entered instead of rewriting itself to the E.164 output once the number became valid, matching what an uncontrolled field always did. `onChange`, the hidden input, and every other configuration are unchanged. No public API changes.
