# @elmeragroup/fuse-figma

Syncs the Fuse design tokens into a Figma file's local variables. The repository is the master for theming data, so the sync writes code into Figma and never reads design decisions back. It is a private workspace package with no build step. Node runs the TypeScript directly.

It also builds the Fuse components plugin, a proof of concept that creates the Button, Confirm button, Toggle, Badge, Kbd, Radio icon button, Radio, Checkbox, Switch, Separator, Skeleton, Loader, Label, Field description, Field error, Field legend, Field title, Input, Textarea, Avatar, Meter, Pagination link, Pagination edge, Pagination ellipsis, Breadcrumb link, Breadcrumb page, Breadcrumb ellipsis, Breadcrumb separator, Select trigger, Empty, Calendar day, Link, Item, Item link and Alert component sets from their recipes and an icon library from Fuse's icons. [Components plugin](#components-plugin) describes it.

## What lands in Figma

The sync owns six variable collections, matched by name.

| Collection        | Modes                          | Variables                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Fuse tokens`     | `Light`, `Dark`                | 135 variables. Designers bind one per contract token such as `primary` or `radius`, one per radius rung such as `radius-md`, one per role tint such as `error/10`, and one per formula over tokens such as `radius-compact`. Three more per formula over tokens and density metrics, such as `radius-inner/lg-pad-sm/dense`, are hidden from pickers. |
| `Fuse variant`    | `Internal`, `External`         | 312 variables: `<scheme>/<token>` for each `Fuse tokens` variable, and `density/<metric>` for each density metric and each formula over metrics alone. Hidden from pickers.                                                                                                                                                                           |
| `Fuse segment`    | `Private`, `Company`           | 540 variables, `<scheme>/<variant>/<token>` for each `Fuse tokens` variable. Hidden from pickers.                                                                                                                                                                                                                                                     |
| `Fuse brand`      | One per brand, 7               | 1080 variables, `<scheme>/<variant>/<segment>/<token>` for each `Fuse tokens` variable. They hold the theme values. Hidden from pickers.                                                                                                                                                                                                              |
| `Fuse primitives` | `Value`                        | 25 variables, the neutral ramp and the brand accents. They hold the same value in every theme. The neutral ramp is hidden from pickers, and the brand accents stay bindable.                                                                                                                                                                          |
| `Fuse density`    | `Auto`, `Dense`, `Comfortable` | 48 variables, one per density metric: control (`control-h-md`), row (`row-h`), surface (`surface-pad-lg`, `surface-gap-md`) and label (`label-text`), and one per formula over metrics, such as `empty-pad-desktop`, or over tokens and metrics, such as `radius-inner/lg-pad-sm`. Designers bind these.                                              |

Each theme axis is one collection, so a designer previews a theme by picking each axis in the frame's Appearance panel, as in the docs theme picker. `Fuse tokens` gets `Light` or `Dark`, `Fuse variant` gets `Internal` or `External`, `Fuse segment` gets `Private` or `Company`, and `Fuse brand` gets the brand, such as `Fjordkraft`. A frame that sets no mode for a collection gets its first mode, so an unset frame shows internal Fjordkraft private in light. Figma resolves an alias that crosses into another collection with the frame's mode for the target collection, inherited from any ancestor. A child frame can therefore change one axis and keep the others.

Every `Fuse tokens` variable takes the same four hops. `primary` in `Light` aliases `light/primary` in `Fuse variant`, which aliases `light/external/primary` in `Fuse segment` under `External`, which aliases `light/external/company/primary` in `Fuse brand` under `Company`. That variable holds each brand's value for the external company theme. The path segments are the lowercase code values, so the hidden variables keep their names whichever axes a token varies on.

A brand mode is the brand's display name. Telinet allows only the private segment and Fjordkraft Företag only the company segment, so their modes read `Telinet (private only)` and `Fjordkraft Företag (company only)`. Figma cannot disable a mode, so such a brand holds its only segment's values under the other segment too: Telinet in `Company` shows Telinet private. The docs picker moves the segment instead.

`Fuse density` defaults to `Auto` in a file the sync creates. `Auto` aliases `density/<metric>` in `Fuse variant`, which holds the metric in the variant's default density, so a frame follows its variant the way apps do: internal themes dense and external themes comfortable. `Dense` and `Comfortable` hold their own pixels for frames that pin a density.

A file synced before `Auto` existed already has `Dense` and `Comfortable`. The REST API appends a new mode and cannot reorder modes or change the default, so `Auto` lands last there and `Dense` stays the default. Figma's default mode is the left-most column of the variables view, so move the `Auto` column all the way to the left, by dragging its header or through the header's right-click menu, to make it the default.

Earlier syncs wrote a `Fuse themes` collection with one mode per theme slug, such as `external-fkas-private`. The sync deletes a local collection with that name, and `check` reports it as drift. Frames pinned to a `Fuse themes` mode lose that pin, and designers set the four axis modes instead. The sync never deletes a library collection or a collection extension with that name.

The token values come from `resolveThemeCatalog` in `@elmeragroup/fuse/theme-catalog`. It resolves every theme in both schemes from `composeTheme`, the same composition that generates `themes.css`, and hands the sync each value already read: an sRGB color, a length in pixels, a font family or a font weight, plus the one `var()` hop when the value is a reference. The catalog throws on a token value it cannot read, because token values are Fuse source, and a Fuse test resolves every theme and scheme so CI catches such a value first. The sync maps the resolved values as follows.

- A color becomes an sRGB color, with alpha kept and the channels unrounded. The tokens write `oklch()` or `#rrggbb` literals, and the catalog reads exactly those two forms through `@elmeragroup/color`, which clips a color outside the sRGB gamut.
- `var(--name)` becomes an alias to the matching variable. A role reference points at the role with the same scheme, variant and segment in `Fuse brand`, and a primitive reference points into `Fuse primitives`.
- A `rem` length becomes the catalog's pixels at a 16px root.
- A radius rung becomes the pixels `fuse.css` computes for it, such as `--radius-md: calc(var(--radius) - var(--radius-step, 0px))`, because Figma variables cannot compute. The catalog computes each rung per theme from the theme's `radius` and `radius-step` and the rung's step count, and the sync writes those pixels per brand mode. Internal themes step 0px, so every rung equals `radius`. External themes step 2px, so `external-fkas-private` with a 12px radius gets 6, 8, 10, 12 and 16px from `radius-xs` to `radius-xl`. CSS clamps a negative `border-radius` to 0, and so does the catalog. The sync leaves out `radius-popover`, because no component uses that rung and Fuse popups use `radius-md`.
- A density metric comes from the catalog in pixels per density, read from the same metrics the `fuse.css` density blocks must equal. Heights, including `row-h`, get the width and height picker. Paddings, including the `row-px`, `row-py` and `surface-pad-*` paddings, and gaps, including the `surface-gap-*` tiers, get the gap picker. The type pairs, `control-text` and `control-leading` for controls and `label-text` and `label-leading` for labels such as selection row text, get the font size and line height pickers.
- A font stack becomes its first family name, which the catalog reads.
- A font weight, such as `selection-title-weight`, becomes its number, from 1 to 1000, and gets the font weight picker. The sync sends that picker as `FONT_STYLE`. Figma's REST documentation lists `FONT_WEIGHT` for number variables, but a real file stores `FONT_WEIGHT` as `FONT_STYLE`, so a sync that sent it would never read back what it wrote.
- A derived role, such as `secondary-hover`, becomes the literal color that composition computes, because Figma variables cannot mix colors.
- A role tint, such as `error/10`, holds its role's color at the tint's alpha in every theme. A Figma paint takes its opacity from the alpha of the variable it binds, so a component cannot bind `error` at 10%, and `bg-error/10` binds `error/10` instead. The tint's code syntax is the `color-mix(in oklab, var(--error) 10%, transparent)` that Tailwind compiles the utility to. `ROLE_TINTS` in `fuse-variable-set.ts` lists the tints the component kit binds. A tint appears in its role's pickers, and its description names the role and the percent, since the catalog has no entry for it.
- A formula variable holds what a recipe's formula over theme tokens or density metrics gives. Figma variables cannot compute, so `FORMULA_VARIABLES` in `fuse-variable-set.ts` computes each one, and its code syntax is the formula as Tailwind compiles the recipe's class, which the kit binds. The kit's builder reads Tailwind's own theme variables as their values, so the code syntax writes `var(--spacing)` as `0.25rem` and `var(--leading-snug)` as `1.375`.
  - What a formula reads decides where it lands. A formula over tokens alone lands in `Fuse tokens` with a value for each theme. A formula over metrics alone lands in `Fuse density` as a metric does: `Dense` and `Comfortable` hold its pixels, and `Auto` reads `density/<name>` in `Fuse variant`. A formula over tokens and metrics lands in `Fuse density` too, but each of its modes aliases a hidden `Fuse tokens` variable, `<name>/auto`, `<name>/dense` or `<name>/comfortable`. That variable takes the four hops of every `Fuse tokens` variable and holds what the formula gives for each theme at its density, and `auto` holds each theme at its variant's default density. Figma resolves each hop with the frame's mode for that collection, so one bound variable follows both the frame's theme and its density. A formula that reads a metric lands in `Fuse density` even when the metric holds one value at both densities, so a later density change cannot move its variable to another collection, which would unbind the layers that use it.
  - The outline Button's shadow lengths, `button-outline-shadow-blur` and `button-outline-shadow-spread`, hold what `max(0px, 4px - 2 * var(--button-outline-width, 1px))` and `min(0px, 2px - 2 * var(--button-outline-width, 1px))` give for each theme's outline width: blur 2 and spread 0 at the internal 1px outline, which is Tailwind's `shadow-xs`, and blur 0 and spread -2 at the external 2px outline, which paints nothing outside the border. They get the effect picker.
  - The compact corner, `radius-compact`, holds what `compactCornerClass` in `corner-radius.ts` gives, `min(radius-md, max(10px, radius - 1000 * radius-step))`. Internal themes step 0px, so it equals `radius`, 8px for Fjordkraft. External themes step 2px, so it is `radius - 2px` capped at 10px: 4px for Elmera's 6px radius and 10px for TrøndelagKraft's 16px. The xs Toggle rounds with it, and it gets the corner radius picker.
  - The checkbox corner, `radius-checkbox`, holds what `checkboxCornerClass` in `corner-radius.ts` gives, `min(radius-md, 4px)`. Every theme's `radius-md` is at least 4px, so it holds 4px in each. The Checkbox box rounds with it, and it gets the corner radius picker.
  - The field box corner, `radius-field-box`, holds what `fieldCornerClass` in `corner-radius.ts` gives, `clamp(radius - 1000 * radius-step, radius-field, radius + 1000 * radius-step)`. Internal themes step 0px, so both bounds equal `radius` and it holds `radius`, 8px for Fjordkraft. External themes step 2px, so the bounds lie 4000px apart and it holds `radius-field`. Every theme sets `radius-field` to `var(--radius)`, so that is 6px for Elmera and 16px for TrøndelagKraft. Fuse rounds Input, Textarea and the other field boxes with that class, and the variable gets the corner radius picker.
  - An inner corner is the `--shell-inner` that a shell in `inner-corner/` publishes and `rounded-inner` reads, `max(0px, rung - border - padding)`. Shells of several components compile to the same formula, and the kit binds by code syntax, so each corner is named for its shell's rung, border and padding. `radius-inner/lg-pad-8px` reads tokens alone: a floating Sidebar's group in the icon rail pads 8px inside `radius-lg`, which leaves 0 in internal themes, 4px for Fjordkraft's external 12px radius and 8px for TrøndelagKraft's 16px. The others read `surface-pad-md` or `surface-pad-sm` too: `radius-inner/sm-pad-md` inside a default Accordion item, `radius-inner/lg-pad-md` inside a Toast or an Accordion item with the lg radius, `radius-inner/xl-pad-md` inside an Accordion item with the xl radius, `radius-inner/lg-border-pad-md` inside a card Accordion item or a SelectionItem, `radius-inner/xl-border-pad-md` inside a card Accordion item with the xl radius, and `radius-inner/lg-pad-sm` inside a floating Sidebar's header, footer or group, or a Select group. TrøndelagKraft's external theme gives `radius-inner/xl-border-pad-md` 7px dense and 3px comfortable. They get the corner radius picker.
  - Empty's desktop padding, `empty-pad-desktop`, is twice `surface-pad-lg`, 32px dense and 48px comfortable. The space above an open Accordion panel's text, `accordion-panel-pt`, is `surface-gap-lg` plus 6px, 22px and 30px. Both get the gap picker. One snug line of label text, `label-line-snug`, is `label-text` times 1.375, 19.25px and 22px, which is how tall an Alert's icon box is beside a description. It gets the width and height picker. Item's own media line reads `text-sm` and `leading-snug`, two Tailwind theme values every theme shares, so the kit's builder reads it as a literal 19.25px and the sync holds no variable for it.
- The variables designers bind in `Fuse tokens`, `Fuse primitives` and `Fuse density` carry web code syntax. A token, primitive or metric carries its `var()`, such as `var(--primary)`. A radius rung carries the `calc()` that `fuse.css` declares, such as `calc(var(--radius) - 3 * var(--radius-step, 0px))`. `fuse.css` declares the rungs in `@theme inline`, so Tailwind inlines them into its utilities, and the built CSS declares no `--radius-sm` property. A test requires every `var()` in the code syntax to name a property that the built `styles.css` or `themes.css` declares.
- A color appears only in the pickers for where Fuse paints it. The catalog gives each color role and primitive its paints from `TOKEN_PAINTS` and `PRIMITIVE_PAINTS` in `@elmeragroup/fuse`, and a source contract holds the library's own color classes to them. A `surface` gets the frame and shape fill pickers, an `ink` gets the text fill, shape fill and stroke pickers, because icons take the text color, and a `line` gets the stroke picker. A role with every fill gets `ALL_FILLS`. `feature-foreground` is a surface only, so the text fill picker leaves it out.
- The neutral ramp gets no picker scope. It holds one value in every theme and scheme, so a layer bound to it breaks dark mode and brand switching. It stays an alias target, as the hidden collections do. The brand accents keep the fill pickers and their foregrounds the text pickers, for artwork that shows several brands.
- Font families get the font family picker. Figma's REST documentation says scopes currently apply only to FLOAT and COLOR variables, but a real file keeps `FONT_FAMILY` on a STRING variable.
- Each length token names its picker scope in a table in `fuse-variable-set.ts`, so a new length token does not compile until someone picks one. `radius`, `radius-button`, `radius-field` and the radius rungs get the corner radius picker, and `button-outline-width` gets the stroke picker.
- `radius-step` gets no picker scope. It is a length, but it spaces the radius rungs and switches between the internal and external variants, so no layer rounds with it. It keeps its code syntax, `var(--radius-step)`.
- Every variable designers bind in `Fuse tokens`, `Fuse primitives` and `Fuse density` carries the catalog's description, which Figma shows when a designer hovers the variable. The descriptions live beside the tokens in `@elmeragroup/fuse`, and the docs tokens page shows the same text. The hidden variables carry an empty description. A real file stored `&`, `<`, `>`, `"` and `'` in a description HTML-escaped on 2026-10-19, through the REST API and the Plugin API alike, so the sync refuses a description that holds one of them.

## Running it

The Variables REST API needs an Enterprise plan. Create a personal access token under Settings → Security in Figma. The token needs the `file_variables:read` and `file_variables:write` scopes and belongs to a Full seat with edit access to the target file. Figma caps these tokens at 90 days, and a plan access token cannot write variables.

Copy `packages/fuse-figma/.env.example` to `packages/fuse-figma/.env`, which git ignores, and fill in the token and the file key:

```sh
FIGMA_TOKEN=figd_...
FIGMA_FILE_KEY=AbCdEf123   # the part after /design/ in the file URL
```

Then run one of these commands from the repository root:

```sh
pnpm --filter @elmeragroup/fuse-figma figma:check   # print the plan, write nothing, exit 2 when Figma differs
pnpm --filter @elmeragroup/fuse-figma figma:sync    # apply the plan
```

`--file-key <key>` overrides `FIGMA_FILE_KEY`, and a branch key targets a Figma branch. `figma --help` lists every flag.

`check` exits 2 when the file differs from the tokens and 1 when it cannot run, for example when the token has expired, so a CI job can tell the two apart. It groups the plan by collection and kind of change. A group of up to 10 changes lists each variable and mode, and a larger group prints its count.

The token travels in the `X-Figma-Token` header. The sync masks that header on the trace spans Effect's HTTP client records, and a failed request keeps only its method and URL.

After a sync, publish the library in Figma. The REST API cannot publish, so consuming files see the new values only after someone publishes by hand.

## How a sync decides what to write

The sync reads the file, plans one change batch and sends it. Figma applies a batch completely or rejects all of it. The sync then reads the file again and fails unless the plan is now empty, so a successful run means the file was checked.

- It matches collections, modes and variables by name and updates them in place. Ids survive, so every layer bound to a Fuse variable stays bound.
- A mode keeps its id only while the tokens keep its name. The sync deletes a mode the tokens no longer name and creates the modes they add, and it never renames one into another, because a dropped brand and an added one are unrelated. Frames pinned to a deleted mode lose that pin. Renaming a brand's display name in code is therefore a delete and a create in Figma, and designers repin the frames that used the old name.
- Mode order does not matter to the plan. A collection whose modes the file holds in another order than the tokens counts as in sync, because the REST API cannot reorder them.
- The sync orders mode changes so that no collection goes over Figma's 40 modes or runs out of modes while the batch applies. It deletes the stale modes before creating new ones. When no existing mode survives, it keeps the last stale mode until the first new mode exists. The only mode it renames is the one Figma gives a new collection, which becomes the collection's first mode.
- Inside the six Fuse collections, the tokens are authoritative. The sync deletes any mode or variable the tokens do not define, and the next sync resets any value a designer edited.
- It never touches another collection in the file, except that it deletes a local collection named `Fuse themes`, which earlier syncs wrote. The sync skips library collections, collection extensions and deleted variables that layers still reference, even when their names match.
- It refuses to change a variable's type, because Figma can only do that by deleting the variable and unbinding every layer that uses it. The error names the variable to delete by hand.
- Renaming a token in code is a delete and a create in Figma, so layers bound to the old name lose their binding.
- It refuses to sync tokens whose aliases form a cycle. A cycle counts even when each alias closes it in a different mode, because the modes a layer combines decide whether Figma would loop.
- It writes the values of each alias target before the values that alias it. Figma applies values in order and refuses a batch that passes through a cycle after any one value, even when the batch ends without one. This order never passes through a cycle, even when the tokens reverse an alias.
- A value shape or variable type newer than the sync does not stop a read. A variable the sync owns gets such a value rewritten, and a type it does not know is a type conflict.
- It owns every variable's description, so the next sync resets a description a designer wrote. It sets web code syntax on the variables designers bind in `Fuse tokens`, `Fuse primitives` and `Fuse density`, and sends no code syntax for the hidden values in `Fuse tokens` or for the `Fuse variant`, `Fuse segment` and `Fuse brand` variables, which only feed aliases. An update replaces a variable's code syntax, so when the sync sets the web entry, it sends the file's Android and iOS entries with it.
- The sync retries a read that hits a rate limit, a server error or a network failure. It waits as long as `Retry-After` asks and logs a warning for each retry. It retries a write only after a 429, because a write that failed on the server may still have been applied. When `Retry-After` asks for more than 60 seconds, the sync fails at once and reports the wait.

The alternative was kumo-figma's approach, which deletes every variable and recreates it on each run. That gives every variable a new id and breaks the bindings in existing designs.

## Components plugin

The plugin creates two component sets from the Button recipe and one from the Confirm button recipe on a page named `Button`, two from the Toggle recipe on a page named `Toggle`, one from the Badge recipe on a page named `Badge`, one from the Kbd recipe on a page named `Kbd`, one from the Radio icon button recipe and one from the Radio recipe on a page named `Radio`, one from the Checkbox recipe on a page named `Checkbox`, one from the Switch recipe on a page named `Switch`, one from the Separator recipe on a page named `Separator`, one from the Skeleton recipe on a page named `Skeleton`, one from the Loader recipe on a page named `Loader`, one from the Field label recipe and four from the Field recipe's description, error, legend and title on a page named `Field`, one from the Input recipe on a page named `Input`, one from the Textarea recipe on a page named `Textarea`, one from the Avatar recipe on a page named `Avatar`, one from the Meter recipe on a page named `Meter`, three from the Pagination recipe on a page named `Pagination`, four from the Breadcrumb recipe on a page named `Breadcrumb`, one from the Select trigger recipe on a page named `Select`, one from the Empty recipe on a page named `Empty`, one from the React Aria Calendar's day cell recipe on a page named `Calendar`, one from the React Aria Link recipe on a page named `Link`, two from the Item recipe on a page named `Item`, one from the Alert recipe on a page named `Alert`, and an icon library on a page named `Icons`. It edits them in place on every later run, and binds each field it can to the variables `figma:sync` writes.

- The `Icons` frame holds one 16px component per icon `@elmeragroup/fuse/icons` publishes that takes the color of the text around it: the 130 Phosphor icons in their bold default weight and the 5 bespoke icons that paint with `currentColor`. The other bespoke icons are artwork with colors of their own, such as the Vipps mark and the Signing illustration, which read as blots at 16px or vanish on a light fill, so they stay out with the brand logos.
- `Button` holds every variant the recipe declares at the default, xs, sm and lg sizes, in 5 states (rest, hover, focus, disabled and pending) and with no icon, a start icon or an end icon: 420 variants. Its `Label` text property sets the label, and its `Start icon` and `End icon` swap properties pick the icons, Plus and ArrowRight to begin with.
- `Icon button` holds every variant at the four square sizes in the same 5 states, 140 variants, each an icon with no label, which its `Icon` swap property picks.
- `icon-inline` stays out, because it takes its size from the surrounding text line.
- `Confirm button` holds the destructive and success variants, the two `confirmButtonVariants` gives an armed face, at the default, xs, sm and lg sizes, in 4 states (rest, hover, focus and disabled), armed off and on: 64 variants. Its `armed` property sits beside `state`. A disarmed cell draws the Button of its variant, size and state. An armed one fills with `error` or `success` and draws its label in `error-foreground` or `success-foreground` inside the `/20` border. `data-[armed=true]:` weighs (0,2,0) and `enabled-hover:` (0,1,0), so on hover an armed button keeps its fill and only its border turns to the role. Disabling a ConfirmButton disarms it, so a disabled cell draws disarmed at `armed=on` too. Pending disarms it as well, and the set draws no pending state. Its `Label` text property sets the label, `Delete` to begin with, the resting label of the docs' Destructive demo. The demos swap in a label while armed, such as `Confirm delete`, and a designer types it on an armed instance, since a text property holds one default. The set has no icons, since no docs demo places one on a ConfirmButton with a label.
- `Toggle` holds both variants the recipe declares at the default, xs, sm and lg sizes, in 4 states (rest, hover, focus and disabled), off and on, and with no icon, a start icon or an end icon: 192 variants. Its `pressed` property sits beside `state`. Its `Label` text property sets the label, and its `Start icon` and `End icon` swap properties pick the icons, Star on both sides to begin with, as the docs place it.
- `Icon toggle` holds the same variants, sizes, states and pressed values, 64 variants, each one icon with no label, which its `Icon` swap property picks. The icon carries `data-icon="inline-start"`, as in the docs, so it takes the start icon's inset.
- `Badge` holds every variant the recipe declares at the default, sm and lg sizes: 57 variants. A Badge is not interactive, so the set has no state axis, and its columns are the sizes. Its `Label` text property sets the label. It has no icons, since no docs demo places one.
- `Kbd` holds a text cap and an icon cap: 2 variants. The recipe declares no axes, so the set's one property, `content`, says what the cap holds, `text` or `icon`, and its columns are those values. Its `Label` text property sets the text cap's label, `K` to begin with. Its `Icon` swap property picks the icon cap's 12px icon, Backspace to begin with, because the roster has no Command icon. Kbd group, which lays out caps in a row, waits until kit components can hold instances.
- `Radio icon button` holds the recipe's five square sizes, icon, icon-xxs, icon-xs, icon-sm and icon-lg, off and on, in 5 states (rest, hover, focus, disabled and invalid): 50 variants. Its `checked` property sits beside `state`. Each variant is one icon with no label, which its `Icon` swap property picks, List to begin with, as the docs demo places it. icon-xxs and icon-xs share the xs square and differ by icon size, 12px and 14px. The invalid state draws the `error` border and ring of a radio inside an invalid field.
- `Radio` holds the circle off and on, in 4 states (rest, focus, disabled and invalid): 8 variants. The recipe has no hover face. Its `checked` property sits beside `state`. The circle is 16px at both densities. A checked circle fills with `primary` and holds the 16px `radio-group-indicator` frame, which centers the 8px `primary-foreground` dot. An off circle has no indicator, as Base UI mounts it only while checked. The invalid state draws the `error` ring, and the border stays `primary` only on a checked circle.
- `Checkbox` holds the box off, on and mixed, in 4 states (rest, focus, disabled and invalid): 12 variants. The recipe has no hover face. Its `checked` property sits beside `state`. The box is 16px at both densities. A checked or mixed box fills with `primary` and holds the `checkbox-indicator` frame around a 14px `Check` or `Minus`, which the state picks, so the set has no swap property. An off box has no indicator, as Base UI mounts it only while checked or mixed. The invalid state draws the `error` ring, and the border stays `primary` only on a checked box.
- `Switch` holds the track at the default and sm sizes, off and on, in 4 states (rest, focus, disabled and invalid): 16 variants. The recipe has no hover face. Its `size` and `checked` properties sit beside `state`. The track is 32px by 18.4px at default and 24px by 14px at sm, at both densities. It holds the `switch-thumb` frame, a transparent 16px or 12px slot, which centers a `dot` frame. Off, the track is a `muted-foreground` outline, and the slot sits at the start and holds a 12px or 9px `muted-foreground` dot. On, the track fills with `primary`, and the slot sits flush with the end and holds a 16px or 12px `background` dot. The invalid state draws the `error` border and ring.
- `Separator` holds a horizontal and a vertical line: 2 variants. A Separator is not interactive, so the set has no state axis, and its columns are the orientations. The line is 1px thick and fills with `border`. The recipe takes the line's length from its container, which the kit does not draw, so each cell passes a docs demo's length as consumer classes, merged over the recipe as Separator merges its `className`: `data-horizontal:w-64` makes the horizontal line 256px long, and `data-vertical:h-4 data-vertical:self-auto` makes the vertical one 16px.

2. Build the plugin from the repository root:

   ```sh
   pnpm --filter @elmeragroup/fuse-figma figma:plugin
   ```

   The build writes `plugin/dist/code.js`, the kit spec `plugin/dist/spec.json` and the coverage table `plugin/dist/coverage.md`. Build in the checkout whose `plugin/manifest.json` Figma imported, and run `pnpm install` first after a pull that adds dependencies. On 2026-10-21 the plugin failed to load with ENOENT on `plugin/dist/code.js` for that reason.

3. In the Figma desktop app, open the file, choose Plugins → Development → Import plugin from manifest, and pick `packages/fuse-figma/plugin/manifest.json`. Figma runs a development plugin only in the desktop app.
4. Run the plugin and press Plan. It lists every change an apply would make, and writes nothing.
5. Press Apply. The plugin writes the changes, then plans again and shows any change that remains. A clean run shows none.
6. Publish the library by hand, as for the variables.

### How the spec is built

The build calls each recipe from the workspace-only `@elmeragroup/fuse/recipe-catalog` entry for each cell of its matrix. It sorts every class by its variants and maps them onto the cells as the component renders them. `fuse.css` and Tailwind fix most of what a variant means, so one shared table in `components/state-table.ts` holds that meaning for every component set. A definition such as `button-kit.ts`, `confirm-button-kit.ts`, `toggle-kit.ts`, `badge-kit.ts`, `kbd-kit.ts`, `radio-icon-button-kit.ts`, `radio-kit.ts`, `checkbox-kit.ts`, `switch-kit.ts`, `separator-kit.ts`, `skeleton-kit.ts`, `loader-kit.ts`, `label-kit.ts`, `field-text-kit.ts`, `input-kit.ts`, `textarea-kit.ts`, `avatar-kit.ts`, `meter-kit.ts`, `pagination-kit.ts`, `breadcrumb-kit.ts`, `select-trigger-kit.ts`, `empty-kit.ts`, `calendar-day-kit.ts`, `link-kit.ts`, `item-kit.ts` or `alert-kit.ts` adds only the variants its own states render, facts for variants only it uses, and its own omissions. The build stops when a definition gives a shared variant a second meaning. A definition also names the cells that show its label, so the Kbd's icon cap drops the text classes as a cell with no text. A set can draw a component that wraps another. ConfirmButton passes `confirmButtonVariants` to Button as its `className`, which Button merges after `buttonVariants` with `cn`, so `confirm-button-kit.ts` merges the two recipes the same way and imports Button's label sizes and omissions from `button-kit.ts`. A set can also draw a component that borrows another's recipe. Pagination's link and edges are `<a>` elements that `pagination.tsx` styles with `buttonVariants` and `paginationVariants`, so `pagination-kit.ts` merges the two recipes as that file does and imports Button's omissions. A component can style an element through a `className` function that React Aria calls with its render props, as `Calendar` styles each day with `cellVariants`, and as `Link` adds the state focus ring and the rac-target disabled face to `linkVariants`. Its definition's `classesFor` gives each cell the classes that function returns for the render props of the cell's state, such as `isFocusVisible` in the focus cells.

A definition can declare parts below its root, such as a checkbox's indicator. A part has its own classes, the cells it appears in, and its own parts, icons and label. Its layer takes its `data-slot` as its name, or its key when the element has none, as Radio's dot does. A part's children sit in DOM order: its parts first, then the start icons, the label and the end icons. Each part becomes a frame layer and cascades its own classes. It inherits its parent's computed `color`, `font-family`, `font-size`, `font-weight`, `font-style`, `line-height`, `letter-spacing`, `white-space`, `text-align` and `text-wrap`, and every custom property whose `@property` does not say `inherits: false`, at the rank the host page has on the root. Tailwind registers every `--tw-*` property with `inherits: false`, so a part takes their initial values. An icon inherits from the part that holds it the same way, so it takes its glyph color from the part's text color, and a size the part gives through a custom property reaches it. A box's `*:data-[slot=x]:` classes style each child part whose `data-slot` is `x`, as Select's trigger lays out its value. Tailwind compiles them to `:is(.… > *)[data-slot="x"]`, at (0,2,0), so they cascade with the part's own classes by that specificity and beat a bare class of the part's own. A slot no part of the definition carries, a bare `*:` and a variant after the slot stay unmapped, and a definition that omits `*`, as Label omits the Field card it can wrap, drops them. A box's `[&_img]:` classes style each `<img>` part below it, at any depth, a part with no `data-slot` whose `element` names the `img` tag, as Item's image media sizes and fits the picture a consumer puts in it. Tailwind compiles them to `.… img` at (0,1,1), so they cascade with the part's own classes by that specificity. Where no such part sits below the box, they stay unmapped. `color: currentcolor` computes to the color the part inherits, so the checkbox indicator's `text-current` keeps the root's `primary-foreground`, and the coverage table records the class with what it resolved to. A flex box's `flex-direction` sets its direction. `row`, or none, makes a horizontal auto layout, and `column` a vertical one. Any other direction stays unmapped. A part's alignment comes from its own classes. `items-start`, `items-center` and `items-end` set the counter axis to MIN, CENTER or MAX. `justify-start`, `justify-center` and `justify-end` set the primary axis, and `justify-between` sets it to SPACE_BETWEEN, which puts the first and last layer flush with the ends and the spare room between the layers. Any other alignment stays unmapped. In a row an unset alignment stays centered, as every published row was drawn. A part's own `align-self` places it across a row in place of the row's `align-items`. Figma aligns all of a row's layers one way, so a row whose parts ask for one alignment takes it, as Item's media and content top the row beside a description. A part that asks for none stretches across the row's height where it draws the same stretched: a flex row that sets no height or margin, paints nothing, pads the same above and below, and places its own layers across as the row's `align-items` would place it, as Item's `flex items-center` actions do. A set whose `state` axis lacks the value can omit the variant instead, as Item omits `focus-visible:`, `disabled:` and `aria-disabled:`, the faces of a row its `<div>` never takes, which Item link draws. A set with no invalid state drops `aria-invalid:` and `data-invalid:` instead, as every set drops `enabled-active:` and `aria-expanded:`, which describe states no standalone component shows. Every set also drops `[&>a]:` and `[&>a:hover]:`, which style a link inside a box's text, as a description underlines one, since the kit draws the text without the link. The build also drops Button's group corners and Badge's `[&>span]`, which styles a span around the label where the kit's label is the root's own text. Confirm button drops Button's group corners too, and the `aria-disabled:` and `data-[pending-indicator]:` arms that only Button's pending state renders, since it draws no pending state. Pagination link and Pagination edge drop the group corners, those pending arms, and the `disabled:` and `data-disabled:` arms, since an `<a>` never matches `:disabled` and Pagination stamps no disabled or pending attribute on one. Calendar day drops `aria-pressed:`, which React Aria never stamps on a day cell. Item link drops `disabled:`, since an `<a>` never matches `:disabled`. A definition can omit a pseudo-element with a reason, which the coverage table shows for each of its classes. Checkbox, Radio and Switch omit `after`, whose classes draw a hit area around the control that paints nothing. Input omits `file`, whose classes style the button of a file input, which the kit does not draw. The omission stays per definition, since a later set may paint an `after:` underline. A definition can also omit, with a reason, the variants that style it inside a composition the kit does not draw. Label omits `has-[>[data-slot=field]]`, `*`, `has-[>[data-slot=checkbox]]` and `has-data-checked`, whose classes style a label that wraps a Field card or a Checkbox. That is Field composition, which waits for wave 3. Field description omits `group-has-data-horizontal/field`, which balances its lines in a Field that holds a horizontal Field, `last`, which takes its place among a Field's parts, and `[[data-variant=legend]+&]`, which pulls it up after a legend in a Field set. Item omits `[a]`, the row as a link, which Item link draws, and both Item sets omit `in-data-[slot=dropdown-menu-content]`, an xs row inside a DropdownMenu, and `[&+[data-slot=item-content]]`, which styles a second content column. A definition can also omit, with a reason, a media variant whose condition the kit does not draw, as Meter and Calendar day omit `forced-colors:`, since the kit draws the normal colors. A class with any other variant is unmapped. A class whose variants each hold somewhere but never in one cell together, such as Radio icon button's `aria-invalid:focus-visible:` ring, lands as dropped, because a cell draws one value of the `state` axis and the kit does not draw invalid and focus at once. So does a class whose one variant never holds in a cell that gives it the class, as `cellVariants` gives `hover:bg-transparent` only to a disabled day, which no cell hovers, and as Confirm button's icon paddings meet no cell with an icon. A child selector styles the icons it reaches, each with its own cascade. A child selector on a part reaches the icons of that part and of every part below it. `[&_svg]` reaches every one of them. `[&>svg]` reaches an icon that is a direct child of the part that carries the class, as the checkbox indicator sizes its glyph. `[&>svg:not([data-icon=inline-end])]` reaches only a leading icon that is a direct child of the part that carries the class. On Button that is the root's own leading icon, which `hidden` leaves out while pending, so the spinner takes its place and an end icon stays. An icon can also carry classes of its own, as the `<svg>` does in the markup, such as the recipe's `icon` slot on Loader's spinner, `animate-spin size-4`. They cascade with the child selectors that reach the icon, each by its specificity, so a box's `[&_svg]:size-4` (0,1,1) beats the icon's own `size-6` (0,1,0). `[&_svg:not([class*='size-'])]` skips an icon whose own classes hold `size-`. The coverage table lists an icon's own classes under the icon's layer name.

Tailwind's own compiler compiles each class and its bare utility against `fuse.css`, and the build reads the rules from the syntax tree Tailwind returns. The build applies the classes that hold in a cell as the browser applies rules in one cascade layer: by the specificity of the full class's compiled selector, then by its place in Tailwind's output. `components/specificity.ts` counts specificity as CSS Selectors Level 4 does, where `:where()` adds nothing and `:is()`, `:not()` and `:has()` add their most specific argument. A variant does not always add specificity. `aria-invalid:` adds an attribute, and `fuse.css` wraps the attribute of `data-checked:` in `:where()`, so a checked invalid Radio icon button strokes with the `error` of `aria-invalid:` and `data-invalid:`, though Tailwind emits `data-checked:border-primary` later. `fuse.css`'s `item-described:` puts the class after a parent context, `:where(:has( > [data-slot="item-content"] > [data-slot="item-description"])) > .class`, so the rule weighs what the class alone weighs, (0,1,0), and the build places the class where that rule sits in the output. A value that equals the web code syntax of a synced variable binds that variable, so `px-(--control-px-button-md)` binds both side paddings to `control-px-button-md`. A radius rung compiles to the same `calc()` that the sync writes as its code syntax, so it binds too, and the compact and checkbox corners compile to the `min()` of `radius-compact` and `radius-checkbox`. A box's own custom property substitutes into its other values, so the field box's `rounded-(--field-corner)` reads the `clamp()` its `[--field-corner:…]` class declares, which binds `radius-field-box`. `rounded-full` compiles to `calc(infinity * 1px)`. CSS scales down corner radii whose sum exceeds a side, so it draws any radius above half the box's shorter side as that half. The build writes that half as a literal when both sides are fixed, 8px on Radio's 16px circle and 4px on its 8px dot. On 2026-10-22 a real file drew a 100px radius on a 16 × 16 frame and on a 64 × 16 frame the same as an 8px one, and stored 100 (probe P10), so Figma draws a radius above half the shorter side as that half, as CSS does. When one side is fixed and the other hugs or fills, the build therefore writes half the fixed side, and Figma draws it as CSS does whichever side ends up shorter. A box that fixes neither side has no length to halve, so its `rounded-full` stays unmapped. A `color-mix()` toward `transparent` binds the role tint whose code syntax it equals, so `bg-error/10` binds `error/10`, and Item's muted row binds `muted/50`. A mix of a variable without a synced tint stays unmapped, and a mix of a literal color reads as that color at the mix's share of its alpha. A length that depends on a percentage, such as `calc(4px + 100%)` in either operand order, stays unmapped too, since a Figma number field cannot hold a share of the containing block. Only a width or height of exactly `100%` reads, as a sizing. `w-fit` compiles to `width: fit-content`, the width of what the box holds when its container has room to spare, which a kit frame always has, so Label's `w-fit` reads as a hug. A `w-fit` box that holds only its text in a column's stretch fills it instead, as the parts paragraph says. A `max()` of a variable and a length binds the variable when the variable holds at least that length in every mode, and a percentage floor never binds. xs uses `max(var(--control-h-xs), 24px)` as its 24px target floor, and `control-h-xs` is 24px or more at both densities, so it binds `control-h-xs`. A shadow's blur and spread bind the same way, so the outline shadow binds the two outline shadow lengths. Values compare with the fallbacks of synced variables dropped, as Tailwind's own substitution leaves them. A background that is a literal color at alpha 0, such as `bg-transparent`, becomes no fill, because it paints nothing in CSS, and the coverage table records it as a literal. Any other value must evaluate to a number or a color, or it stays unmapped. `@elmeragroup/color` reads both the comma form of `rgb()` and the space form Tailwind compiles an arbitrary color to, such as `rgb(0 0 0/0.05)`.

The root inherits the text color and font family of the host page. The build applies the `font-sans text-foreground` that the docs layout sets on `<body>` before any recipe class, so the outline Button's label binds `foreground`. A definition names what sits between the page and the root in a cell in two ways. An element a Fuse recipe styles is named in `ancestorsFor`, outermost first, by its `data-slot` and the classes its recipe gives it, so the kit follows the recipe. A host default with no class is named in `inheritedFor` by its declarations. Button's `icon` square sets no type, so Pagination link names the browser's `medium` font size, 16px, and Tailwind preflight's `line-height: 1.5` on `<html>`, which the docs and the compare page both load, and its number draws at 16/24px. React Aria's Link sets no type size either, so it names the same two declarations. The page's and the host's declarations compute a style of their own, the host's after the page's. Each ancestor then cascades its classes over what it inherits from the element outside it, with the cell's states and facts, as the root's classes do. The root inherits the innermost computed values as a part inherits its parent's. So an ancestor's `var()` resolves against its own custom properties, a nearer ancestor's own declaration beats what it inherits whatever the specificity of the farther rule, the root's `currentcolor` takes the inherited color, and every class of the root's own beats them. An ancestor's declaration that a nearer element overrides drops and names that element. An ancestor's declaration that does not inherit, such as a flex row or a gap, reaches no drawn layer and drops with the reason its definition gives. A child selector of an ancestor reaches the root's icons as a descendant. The invalid cells of Input and Textarea sit in a Field root, whose `data-invalid:text-error` holds there, so a typed value draws in `error`, while the placeholder's own `placeholder:text-muted-foreground` wins in the placeholder cells. Textarea sits in a Field root in every cell, as its renderer and the docs' Field demo place it, and Input only in its invalid cells. The Field root's child selectors reach the control, so the field box omits `[&>.sr-only]`, which widens a visually hidden child that no cell holds, and the stretch of every other child, which gives the control the width its own `w-full` already takes. The invalid cells of Select trigger sit in a Field root too. There the stretch widens the `w-fit` trigger to the Field's width, which the set does not draw, so Select trigger omits it with that reason and hugs its value, as it does outside a Field. Field description, Field error and Field title sit in a Field root in every cell, and the error's root is invalid. The description and the error fill the Field as block boxes anyway, so each omits the stretch, and the title omits it with Select trigger's reason and hugs its text, as it does in `Field.Content`, where the docs place it. The error's own `text-error` beats the invalid root's. The four Breadcrumb sets sit in `Breadcrumb.List`, and the link, the page and the ellipsis in a `Breadcrumb.Item` inside it, so each draws in the list's 14/20px type and muted color unless its own classes set another, as the page's `text-foreground` does. The list's `wrap-break-word` breaks a word only where the word overflows the list, which a part that hugs its text never does, and the build models no inherited `overflow-wrap`, so it drops with the list's reason. A root that shows no text drops the type the page and its ancestors pass down, since an icon takes only the text color, so the separator and the ellipsis drop the page's `font-sans` and the list's `text-sm`.

Each root and each part also gets the base-layer rule of `fuse.css`, `border-color: var(--border, currentcolor)`, which gives every border the border role. The build reads the rule from Tailwind's compile of `fuse.css`, by its arm for every element except a native form widget without a `data-slot`, and stops when the rule or its `border-color` is gone. Every part is a span, so the arm also matches a part without a `data-slot`. The rule sets the color on the element itself, so the build keeps it apart from the inherited page declarations and applies it after them and before every recipe class, since any utility beats the base layer. The outline Badge sets `border` and no color, so its stroke binds `border`, and `coverage.md` names the rule as `fuse.css base layer`. A root that draws no border drops the rule. A border that neither a class nor the rule colors stays unmapped, so the gate fails instead of the stroke vanishing.

A solid border draws a solid stroke, and a dashed border a stroke whose dash pattern repeats one dash and one gap around the box. CSS leaves those lengths to the browser. On 2026-10-23 the compare run's Chromium drew 3px dashes and 2px gaps along a 1px border, 6px and 4px along a 2px one, and 6px and 3px along a 3px one. So the build writes 3 and 2 times the width below 3px, and 2 times and once the width from 3px. Chromium also stretches each side's gaps by up to half a pixel so the side ends on a dash, where a Figma pattern repeats the same lengths around the whole stroke, so the dashes along a side can drift a few pixels from the browser's. A dashed border whose width binds a variable stays unmapped, since its dashes would take other lengths in each mode, and so does any other border style.

An outline lies outside the border edge, `outline-offset` away from it (CSS Basic UI 4 §5), so a solid outline whose offset is minus its literal width lies over the box's outer pixels, where an inside stroke of that weight lies. On a box with no border it draws as the box's stroke, as Item's image media frames its picture with `outline-1 -outline-offset-1`. A box holds one stroke, so beside a border the outline stays unmapped. The plugin writes the stroke as an inside stroke of that weight and color, as it writes a border's, but with `strokesIncludedInLayout` false, since an outline takes no room in the layout, so the image media's portrait keeps the whole square under it. `outline-black/10` compiles to `color-mix(in oklab, #000 10%, transparent)`, a mix toward `transparent`, which keeps the color's channels and scales its alpha, since a mix interpolates premultiplied colors (CSS Color 5 §2.4). A share outside 0% to 100% stays unmapped. `@elmeragroup/color` parses the color and makes the mixed one, and it has no `color-mix()` parser and no mix toward `transparent`, so the build scales the alpha itself. No synced variable holds black, so the stroke is a literal black at 10%. The build spells Tailwind's shorthand `#000` and `#fff` out to six digits before the shared color parser reads them.

`underline` underlines the label, and `underline-offset-*` sets the underline's offset in pixels. A cell that draws no underline drops the offset.

The icon library comes from the same React components apps render. A bespoke icon renders at its own size, and the plugin scales it to fit 16px. The library keeps an icon only when it paints with `currentColor` alone. Figma cannot read `currentColor`, so the markup paints the icon black and the plugin binds its color.

`coverage.md` lists every declaration with what became of it, and the part whose classes set it, so one class on two parts gives two rows. A declaration a part inherits and reads lands under the part that set it. Each declaration in a computed style names the part and class that set it, and the build settles a cell's coverage once it has mapped every layer, so a class that only a part two levels down reads still counts as read. Bound and literal declarations reached a Figma field. A dropped declaration has no Figma form, such as a cursor, a transition or the animations of Skeleton's `animate-pulse` and Loader's `animate-spin`, or belongs to a state no cell shows. `tabular-nums` sets `font-variant-numeric`, which has no Figma form either. `forced-color-adjust-none` keeps an element's colors in a forced-colors mode, which the kit does not draw, so it drops. The markers `group`, `peer` and their named forms emit no CSS and drop. A custom property draws nothing itself, and a read of it on its box or on a layer below counts on its declaration, so one that nothing reads only passes its value down to layers that never take it. It drops on a box that holds no part or icon, as the field box's `--shell-inner`, `--shell-corner` and `--inner-corner` do on Input and Textarea, and on a box whose parts and icons read none of it, as the same three do on Select's trigger. A local value of a synced variable, such as `[--card:#f00]` beside `bg-card`, stays unmapped too. The browser paints the local value, while the build keeps a synced variable as its `var()` and binds it. Where no layer of the cell reads a value that names the variable, the browser paints the local value nowhere, so it drops, as the warning and info Alerts' `[--ring:…]` reaches only the focus ring of a row that takes no focus. `position: relative` drops, because it only anchors positioned descendants, which auto layout does not need. The centered part and the absolute part at its parent's top left land as literal, and any other position stays unmapped. `align-self: auto` drops on the root, which sits in no flex row, as Separator's `data-vertical:self-auto` does, and any other `align-self` on the root stays unmapped. `flex` drops on the root for the same reason, as Empty's `flex-1` does. `vertical-align` drops on the root, which sits in no line of text, as Avatar's `align-middle` does. A margin drops on the root, which sits alone in its component set, so the margin spaces it from nothing the set draws, as Field legend's `mb-3` does. A block root that takes the preview width is the exception: CSS makes it the preview width less its horizontal margins, which the build does not subtract, so those stay unmapped. A part's `margin-top`, `margin-right`, `margin-bottom` and `margin-left` in a flex parent add to the space around it and never collapse (CSS Flexbox 1 §4.2), so the part draws as a transparent frame that hugs it with the margins as its padding, holding the part's own box as a layer named `box`. The frame keeps the part's name and its BOOLEAN property, so hiding the part takes its margin away too, as Empty's media takes the 8px of its `mb-2`. The cascade splits a shorthand or logical margin, such as `m-0` or `mx-1`, into its physical sides, so each side cascades with the others and a style attribute's `margin: 0` resets a class's `mt-1`. A margin of zero adds no space and drops, as Item's title and description reset a `<p>`'s margins with `m-0`. A negative margin, a margin beside a fill, a margin in a parent that is no flex box, and an `auto` margin, such as `mx-auto`, stay unmapped. `vertical-align` drops on an icon too, since Figma has no line of text and the box's auto layout places the icon. Meter's `align-text-bottom` sets its icon about 0.2px lower in the 14/20px line than the value's row centers it. An icon's `display: inline-block` or `block` reads as shown, and `none` leaves it out. An icon in a flex box is a flex item, which lays out as a block whatever its display (CSS Display 3 §2.7), as Alert's `block size-5` icon does. An outline in a literal color at alpha 0, such as Meter's `outline-transparent`, paints nothing, so its style, width, offset and color drop, as a transparent background becomes no fill. An outline that lies inside the box draws as a stroke, as the stroke paragraph below says. Any other outline stays unmapped. `aspect-ratio` drops when both sides are fixed, as Radio's `aspect-square` is beside its `size-4`, since the ratio then sizes neither side, and stays unmapped otherwise. The plugin typings let a plugin read a text layer's `openTypeFeatures` and give no setter for `TNUM`, so the Kbd label keeps the font's default numerals. An unmapped declaration is one the build cannot express yet, and a test holds the count at zero.

### How the plugin decides what to write

- Plan and Apply run the same planning pass. The pass checks the kit against the file, matches each node and records every write as an operation, and it writes nothing. Plan lists the operations. Apply finishes the pass and loads every font the text writes need, so a duplicate key, a missing variable, a variable of the wrong type or a font this machine cannot load stops the run before any write. Then it performs the operations in order. Plan loads the fonts too, so it fails where Apply would. A label the run creates takes its family from the file's variable, which the pass resolves through the modes the new label will read.
- Each field planner compares the node with the spec and records an operation only when they differ, so a second run over an applied file plans nothing. A fill, stroke or shadow matches only with the `NORMAL` blend mode the plugin writes. A text field counts as bound only when every character binds the variable.
- Writes that depend on each other share one operation. A resize or a width or height binding turns a box's hugging or filling axis fixed, so the operation that writes a length writes both axes' sizing again after it. A label's font write comes first among its writes and needs only the new font, so the plugin can replace a font this machine lacks. The spec sets the style as a literal, so the font write also clears any variable a character binds to `fontStyle` or `fontWeight`. A new node is one operation that creates the node and everything the spec puts inside it, so Plan lists it once. A new page is the exception: Plan lists it, and then each set, preview or icon library the run creates on it, because the plugin plans a page's nodes in the outer pass.
- A bound paint matches by its binding alone, because Figma sets a bound paint's opacity from the variable's alpha. Two runs on a real file, on 2026-10-19, wrote `error` at 10% and read it back at 100%, which is why the kit binds role tints.
- An image paint names its image by a hash, and Figma stores the image apart from the layers. On 2026-10-22 a real file named the stored portrait by the SHA-1 of its bytes, read a written image paint back with that hash and Figma's defaults for every other field, and read the same once that readback was written again (probes P9 and P9b). The spec carries the hash, so a held image paint matches by its hash and its scale mode, besides the visibility, blend mode and opacity every paint is held to, and Plan stores nothing. A designer's filters or rotation on the paint stay. Apply stores the image with `createImage` in the operation that writes the paint, and stops before the write when Figma names it by another hash.
- The kit check holds each image to what Figma stores: a PNG whose signature and IHDR chunk are whole, from 1 to 4096 pixels on a side, the limit Figma's reference states. On 2026-10-22 a real file stored the first 100 bytes of a PNG and refused its 8-byte signature alone with `Image type is unsupported` (P9b), so Figma reads the header, not the whole file. The check also requires the spec's hash to be the SHA-1 of the bytes. A new layer stores its image only when the operation that creates it runs, after earlier writes, so the check refuses such an image before the first write.
- The build makes every variant root clip its content, through the box's `clips`, because Figma draws a drop shadow's spread only from a frame that clips and has a visible fill. A fill at alpha 0 does not count: on 2026-10-20 the focus rings of ghost and link held their 2px spread over one and drew nothing. A root with a spread shadow and no fill therefore gets black at alpha 0.0015, which Figma counts and which changes no 8-bit channel. A transparent background reaches the plugin as no fill, so a Toggle's focus ring gets the clear fill too. The plugin also sets a shadow's geometry again after it binds the shadow's color. Two runs stored the spread as 0, and the third, which did this, kept it.
- A variant root is an auto layout along the spec's `direction` that places its layers as the spec's `primaryAlign` and `counterAlign` say. `SPACE_BETWEEN` along the direction puts the spare room between the layers. On 2026-10-22 a real file kept it through an `itemSpacing` write and a binding, so the plugin writes the spacing after the alignment as before. The typings give the counter alignment no stretch, and allow a baseline only in a row. Every published root is a row. Each centers its layers on both axes, except Switch's, whose thumb's translate places it at the start or the end. A part below the root is a frame layer with the same box fields, and it can hold frames of its own. The build makes such a frame show its overflow unless it sets `overflow: hidden`, as a CSS box does, and the plugin writes `clipsContent` from `clips` on every box. A part gets no clear fill, because no part below a root casts a spread shadow yet.
- A box's `sizing` makes each axis fixed at a length, hugging its content, or filling the room its parent's auto layout gives it. The plugin writes it through `layoutSizingHorizontal` and `layoutSizingVertical`, which Figma reads as a projection of the sizing modes, a text's auto resize and the parent's grow or stretch. On 2026-10-22 the real file's Button roots read hugging across and fixed down, their labels hugging both ways, and the Separator and Switch boxes fixed both ways. The build writes a fill where a part's `100%`, a column's stretch, a `w-fit` text box in that stretch or the one part that grows meets a definite length, and across a hugging row only for a part that stretches beside taller layers that set the row's height, as Item's actions do.
- The plugin writes a box's direction, then its alignments, then its fixed lengths, then its sizing, then its limits. A direction change keeps each sizing mode in its role along or across the direction. On 2026-10-22 a row 40 tall that hugged its width hugged its height once it became a column, and stood 14 tall. So the plan compares the spec with the sizing the box will read in its new direction, and a turn rewrites the box's fixed lengths after it. A turn also moves the fill of each layer inside the box to the other axis, so it rewrites those layers' sizing and fixed lengths too, labels included. On the same file a resize or a width binding turned a filling child fixed, which is why the sizing follows the lengths in their operation. No probe has shown what a box stores in its sizing modes, or how it sizes, when it first gets an auto layout, as every new box does, so a box without one writes its sizing whatever its modes predict.
- A text's `sizing` sets its auto resize. A text that hugs both ways is `WIDTH_AND_HEIGHT`, one whose width fills or is fixed and whose height hugs is `HEIGHT`, and one fixed both ways is `NONE`. The plugin writes, in one operation, the auto resize, then `layoutSizingHorizontal` and `layoutSizingVertical`, then a fixed width or height, then `textTruncation`, then `maxLines`. The label's font comes first, in an operation of its own. On 2026-10-22 a real file turned a `WIDTH_AND_HEIGHT` text that filled a row into `HEIGHT`, kept a filling text `HEIGHT` when asked for `WIDTH_AND_HEIGHT`, and gave a resized `HEIGHT` text a fixed width with its height still on its lines. So a new auto resize moves the text's hug, and the operation writes the sizing and any fixed width or height after it whatever the text reads now, since a hugging text's size also follows a font the run writes first. On the same file a `maxLines` written while truncation was off changed nothing, truncating at the ending alone read one line, and `maxLines` null under the ending showed every line. So the plugin writes the maximum after the truncation, and writes it again whenever the truncation changes. The text's `align` sets `textAlignHorizontal` and `textAlignVertical` after that operation. On 2026-10-22 all 420 labels of a real file's Button and Icon button sets read `textAlignHorizontal` LEFT and `textAlignVertical` TOP, with `WIDTH_AND_HEIGHT` and truncation `DISABLED` (probe P0b). The plugin wrote no alignment when it created those labels, so a new text sets its lines from the top left, and a Plan writes no alignment on a published label.
- A frame's `absolute` takes it out of its parent's auto layout. The plugin writes `layoutPositioning` ABSOLUTE, then the frame's `constraints`, `x` and `y`, in one operation before the frame's size, since Figma refuses FILL on an absolute layer. On 2026-10-22 a real file kept an absolute layer's place, size and constraints, threw `FILL cannot be set on absolute positioned auto-layout children` for it, left it out of a hugging parent's size, and scaled its width and stretched its height with its parent, in a variant and in an instance (P8). The typings say turning a layer absolute or back moves it, so a turn writes its constraints and place whatever they read. A layer the auto layout places goes back to `AUTO`. The kit check refuses an absolute frame that fills an axis. A parent that resizes in a run moves and resizes its absolute layers by their constraints when its resize runs, after the plan compared those layers. So when the plan writes a field that can resize a box, its direction, sizing, lengths, limits, padding, spacing or stroke, or one of a box above it, the box's absolute layers write their constraints, place and size whatever they read, and one Apply converges. A hugging box whose layers change size resizes too, which the plan does not track.
- A frame's or an icon's `rotation` turns it. On 2026-10-22 a real file kept a 16px icon's box in its auto layout slot at 180, with its `absoluteBoundingBox` and its row's size unchanged, while its `x` and `y` moved from 34 and 0 to 50 and 16 with the transform's origin, and came back at 0 (PR). So the plugin writes and matches a layer's `rotation` alone, never its `x` and `y`, and two rotations a whole turn apart match. Figma lays a turned layer out by its turned box: on the same day a 20 × 10 frame at -90 made its hugging row 10 × 20 (PQ), where CSS's `rotate` leaves the layout as it was. So the kit check takes a half turn on any layer and a quarter turn only on a layer with two equal fixed sides, as every icon has, and refuses every other turn and a turned absolute frame, which the plugin places by an `x` and `y` that a turn moves.
- A variant root sits in its component set, which has no auto layout, so it cannot fill. On 2026-10-22 a real file threw `FILL can only be set on children of auto-layout frames` for one. It also threw for hug on a frame without auto layout inside one, and for fill on a frame outside any auto layout. ### Comparing with the browser

`figma:compare` checks the kit against the real Fuse components. It renders every instance in the preview frames with its Fuse component in Chromium and compares the two pictures cell by cell.

1. Build Fuse when `packages/fuse/dist` is missing or older than its sources, with `pnpm --filter @elmeragroup/fuse build`. The comparison renders the components and loads `styles.css` and `themes.css` from that build, and it warns when the sources are newer.
2. Run the plugin and press Export snapshots. The plugin exports each instance in the preview frames of every kit page as a PNG at 2x, cut to its render bounds so that a focus ring outside the box is included. It records each instance's box and render bounds and the modes its preview frame resolves. Figma resolves a mode only for a collection the frame's layers bind or alias into, so the export adds each mode the frame or its page pins, such as the density a Badge preview pins though no Badge layer binds a density variable. The UI downloads the result as `fuse-kit-snapshots.json`. The export writes nothing to the file.
3. Run the comparison. pnpm runs the script in this package's directory, so pass an absolute path:

   ```sh
   pnpm --filter @elmeragroup/fuse-figma figma:compare ~/Downloads/fuse-kit-snapshots.json
   ```

   The report goes to `.cache/figma-compare/` in this package, or to the directory `--out` names. `--threshold` sets pixelmatch's threshold, 0.1 by default. The run needs Playwright's Chromium, which `pnpm --filter @elmeragroup/fuse-figma exec playwright install chromium` installs.

The browser renders one page per preview:

- The page stamps the preview's theme the way Fuse applies one: `data-theme` and `data-density` on `<html>`, and `data-theme-variant`, `data-theme-brand` and `data-theme-segment` on `<body>`. A brand mode maps to its brand by display name, and `Auto` density maps to the variant's default.
- It names the layers in the order `styles.css` declares them, then loads Tailwind's preflight in the `base` layer, Fuse's standalone `styles.css` and `themes.css`, and sets `font-sans text-foreground` on `<body>` as the docs layout does. Roboto comes from `@fontsource/roboto`, which serves Google's Roboto, the family Figma renders. Preflight loads before `styles.css`, as in a Tailwind-source host, because its `border: 0 solid` and Fuse's base border rule share the `base` layer and the later one wins. The run checks every element in a cell that holds text, an input's value or placeholder included, and stops when a face that text uses has not loaded, so the text never falls back to a system font.

To compare a new component set:

1. Add its definition and preview cells to `KIT` in `components/kit-registry.ts`. Name an interactive axis `state`, with `rest` among its values, so the page can force hover and focus and find the resting twin. A set with no state, such as Badge, leaves the axis out, and the page forces nothing on its cells.
2. Add a renderer module beside `compare/button-cell.ts`. It exports a `CellRendering` whose `element(cell)` returns the real Fuse element for a parsed cell. Set the states the markup draws, such as disabled, pressed or checked, through props. Name in `hostClasses` any class the cells pass that Fuse's own source does not use, such as a docs demo's length. Name in `forcedAttributes` what React Aria writes on the measured element in a hover or focus cell, which static markup cannot hold.
3. List the module in `compare/cell-renderers.ts` with the definition's key and the `dist/` entry the module imports. The run checks that the entry exists before it loads the module.
4. Add a markup test beside the renderer whose oracle is the component's public contract, as `compare/button-cell.test.ts` does. `compare/kit-markup.test.ts` checks that every definition has a renderer, and checks the definition against the renderer's markup for every preview cell: the cell renders one measured element, each attribute variant, such as `disabled:` or `aria-pressed:`, holds exactly where the measured element carries the attribute, each attribute variant a part's own classes name holds exactly where that part's element carries it, as Switch's thumb carries `data-checked` and `data-unchecked`, the parts the cell shows match the measured element's descendants, and the `iconsFor` of the root and of each part the cell renders list the measured element's `<svg>` descendants in order. Each icon sits under the part that lists it, its nearest ancestor that is the root or a part, as a child of that part or nested deeper, with its `data-icon`. An icon slot that names classes of its own, as Loader's spinner does, must name the `<svg>`'s `class` attribute exactly. A part with a `data-slot` matches the element that carries it, below its parent part's element. A part with none, such as Radio's dot or Meter's header, matches by place, as the one child element of its parent part beside the parts with a `data-slot` and Base UI's visually hidden `<span role="presentation">`, which is no `<svg>` and carries no `data-slot`. A part with no `data-slot` can name its element in `element` instead, as a root does, and matches the element below its parent part's element that the selector matches. A part with a `styleFor` must carry exactly those declarations in its `style` attribute, in order, and a part without one no `style`, so the fill widths Figma draws are the ones Base UI writes. The elements around the measured element carry each ancestor the definition's `ancestorsFor` names, outermost first, with its `data-slot` and exactly its classes, and no other element with a `data-slot` sits between the outermost of them and the root, so a renderer that drops Textarea's Field root or puts Breadcrumb's separator in an item fails. An element outside the outermost ancestor, such as `Breadcrumb.Root`, which carries no class, is not checked. A group variant holds exactly where an ancestor of the element it styles matches it, as `group-data-disabled/field:` holds below a Field root that carries `data-disabled`. For a variant the root's own classes name that is an ancestor of the measured element, and for one a part or an icon names it can be the measured element itself, as Select's caret turns below its open trigger. The root and each part hold their label's characters where the cell shows the label, as their own text, after a space where the label's `leadingSpace` says so. In a cell where the label's `textAttribute` names an attribute, they hold them there and no text of their own, as an `<input>` holds its placeholder in `placeholder` and its value in `value`. A `<textarea>` holds its placeholder in `placeholder` and its value as its own text. Where the label's `textElement` names a child element, the box holds no text of its own, and the one child that selector matches holds the characters and carries no `class` or `style`, as Pagination edge's bare `<span>` holds `Previous`. Attribute values read with React's entities decoded, as text does. A box that shows an image is an `<img>` whose `src` is a data URI of the image's bytes, and a box that shows none carries no `src`. It fails when a definition's facts, states or recipe conditions name an attribute or group variant its lists lack, so add a new one, such as `data-checked:`, with the attribute it selects. `placeholder:` holds where the element has a placeholder and no value, in `value` or, on a `<textarea>`, as its own text. `invalid:` holds where an element marked `data-rac` carries `data-invalid`. On a root marked `data-rac`, `hover:` and `enabled-hover:` hold exactly where the renderer's `forcedAttributes` carry `data-hovered`.

`report.html` opens from disk. It starts with a summary per preview and then lists every cell worst first. Each cell shows three pictures: Figma's export, the browser's crop, and the diff, which marks differing pixels red and anti-aliasing yellow. Figma's export and the browser's crop sit over the theme's background with the boxes' top-left corners aligned. Filters select a preview, a value of each variant axis, or only the flagged cells. `report.json` holds the same rows.

- Check box sizes first. Δ is Figma's box minus the browser's, in pixels. The `size` flag marks a side that differs by half a pixel or more, and such a cell goes to the top. `subpixel-size` marks a smaller difference, beyond Chromium's 1/64 px layout rounding.
- Mismatch is the percentage of the browser box's area, at 2x, whose pixels differ. The tolerant count leaves out the pixels that pixelmatch takes for anti-aliasing, and the raw count includes them. Figma and Chromium draw text differently, so a matching cell still shows some mismatch along the label. Mismatch away from text and edges points at a real difference.
- A Textarea cell differs in its bottom-right corner, where Chromium draws a resize grip and the kit draws none. That mismatch is expected.
- `png-size` marks an export whose size differs from its render bounds. `state-by-interaction` marks a cell that needed a real hover or focus. `state-missing` marks a cell whose state the browser could not show, so its browser picture is wrong. `no-figma-image` marks an instance Figma drew nothing for.
- A hover or focus cell whose built variant equals its resting twin's is unchanged by design, such as a pressed Toggle on hover, which `aria-pressed:` and `enabled-hover:` paint with the same `muted`. When the browser shows no change for it either, the cell gets no `state-missing` flag, and the report notes it as unchanged by design. The run builds the component sets with `buildComponentSets()` in its own process, so the expectation follows the recipes the browser renders.
- The report lists an instance it cannot render as skipped, such as one whose variant has an axis the comparison does not know.

The first comparison of the test file, on 2026-10-20, covered 756 cells in the 12 previews:

- Every height matched, and every Icon button matched to the pixel apart from anti-aliasing.
- Every Button was wider in Figma, by less than a pixel: 0.41px at 12px type, 0.47px at 14px and 0.61px at 18px. Figma rounds an auto-width text layer up to a whole pixel. Its Roboto matches the browser's, so three labels in a row are 125px wide in Figma and 124.59px in Chromium. The rounding moves the right edge and nothing else. The worst cell differs by 2% of its pixels, all of it that edge and text anti-aliasing.
- A fixed label width could match the fraction, but then the label would not grow when a designer edits it, so the kit keeps auto width.

`figma:compare --self-check` tests the comparison itself. It renders every cell of the kit's preview frames in each of two themes and saves them as a fake snapshot whose render bounds reach 3 pixels past each box, each PNG holding every device pixel its render bounds touch, so a 3px ring on a box of fractional width keeps its last column. It paints a square into the kit's first hover cell and widens the box of its first focus cell by a pixel, in registry order, and then it compares the snapshot with a second render. It passes when those two cells lead the report and every other cell matches exactly.

The tests run the whole command line against `test/in-memory-figma.ts`. That fake file applies batches with the REST API's documented rules, stores numbers as 32-bit floats and resolves aliases the way Figma renders them. Where the documentation is silent, the fake does what a real Enterprise file did on 2026-10-16. It replaces code syntax on an update, it checks for an alias cycle after each value a batch sets, and it refuses any cycle, even one that closes only across modes. It deletes a collection with its modes and variables and keeps an alias into it until a later value in the batch replaces it, as a real Enterprise file did on 2026-10-19 when one batch deleted `Fuse themes` and then rewrote the `Fuse tokens` aliases into it. It also applies the scope rules on the REST API's [variable types page](https://developers.figma.com/docs/rest-api/variables-types/). It rejects a scope the page does not list for the variable's type, such as `GAP` on a color, `ALL_SCOPES` beside another scope, and `ALL_FILLS` beside another fill scope. It follows a real Enterprise file where that file departed from the page on 2026-10-16. It keeps `FONT_STYLE` on a number variable and stores `FONT_WEIGHT` there as `FONT_STYLE`. It stores a description with `&`, `<`, `>`, `"` and `'` HTML-escaped, as a real Enterprise file did on 2026-10-19. Tests can also make it answer with a status, drop a connection, or hold values and types newer than the sync.
