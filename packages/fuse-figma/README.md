# @elmeragroup/fuse-figma

Syncs the Fuse design tokens into a Figma file's local variables. The repository is the master for theming data, so the sync writes code into Figma and never reads design decisions back. It is a private workspace package with no build step. Node runs the TypeScript directly.

It also builds the Fuse components plugin, a proof of concept that creates the Button, Confirm button, Toggle, Badge, Kbd, Radio icon button, Radio, Checkbox, Switch, Separator, Skeleton, Loader, Label, Input, Textarea, Avatar and Meter component sets from their recipes and an icon library from Fuse's icons. [Components plugin](#components-plugin) describes it.

## What lands in Figma

The sync owns six variable collections, matched by name.

| Collection        | Modes                          | Variables                                                                                                                                                                                                                        |
| ----------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Fuse tokens`     | `Light`, `Dark`                | 113 variables: one per contract token such as `primary` or `radius`, one per radius rung such as `radius-md`, one per role tint such as `error/10`, and one per formula variable such as `radius-compact`. Designers bind these. |
| `Fuse variant`    | `Internal`, `External`         | 265 variables: `<scheme>/<token>` for each `Fuse tokens` variable, and `density/<metric>` for each density metric. Hidden from pickers.                                                                                          |
| `Fuse segment`    | `Private`, `Company`           | 452 variables, `<scheme>/<variant>/<token>` for each `Fuse tokens` variable. Hidden from pickers.                                                                                                                                |
| `Fuse brand`      | One per brand, 7               | 904 variables, `<scheme>/<variant>/<segment>/<token>` for each `Fuse tokens` variable. They hold the theme values. Hidden from pickers.                                                                                          |
| `Fuse primitives` | `Value`                        | 25 variables, the neutral ramp and the brand accents. They hold the same value in every theme. The neutral ramp is hidden from pickers, and the brand accents stay bindable.                                                     |
| `Fuse density`    | `Auto`, `Dense`, `Comfortable` | 39 variables, one per density metric: control (`control-h-md`), row (`row-h`), surface (`surface-pad-lg`, `surface-gap-md`) and label (`label-text`). Designers bind these.                                                      |

Each theme axis is one collection, so a designer previews a theme by picking each axis in the frame's Appearance panel, as in the docs theme picker. `Fuse tokens` gets `Light` or `Dark`, `Fuse variant` gets `Internal` or `External`, `Fuse segment` gets `Private` or `Company`, and `Fuse brand` gets the brand, such as `Fjordkraft`. A frame that sets no mode for a collection gets its first mode, so an unset frame shows internal Fjordkraft private in light. Figma resolves an alias that crosses into another collection with the frame's mode for the target collection, inherited from any ancestor. A child frame can therefore change one axis and keep the others.

Every `Fuse tokens` variable takes the same four hops. `primary` in `Light` aliases `light/primary` in `Fuse variant`, which aliases `light/external/primary` in `Fuse segment` under `External`, which aliases `light/external/company/primary` in `Fuse brand` under `Company`. That variable holds each brand's value for the external company theme. The path segments are the lowercase code values, so the hidden variables keep their names whichever axes a token varies on.

A brand mode is the brand's display name. Telinet allows only the private segment and Fjordkraft Företag only the company segment, so their modes read `Telinet (private only)` and `Fjordkraft Företag (company only)`. Figma cannot disable a mode, so such a brand holds its only segment's values under the other segment too: Telinet in `Company` shows Telinet private. The docs picker moves the segment instead.

`Fuse density` defaults to `Auto` in a file the sync creates. `Auto` aliases `density/<metric>` in `Fuse variant`, which holds the metric in the variant's default density, so a frame follows its variant the way apps do: internal themes dense and external themes comfortable. `Dense` and `Comfortable` hold their own pixels for frames that pin a density.

A file synced before `Auto` existed already has `Dense` and `Comfortable`. The REST API appends a new mode and cannot reorder modes or change the default, so `Auto` lands last there and `Dense` stays the default. Figma's default mode is the left-most column of the variables view, so move the `Auto` column all the way to the left, by dragging its header or through the header's right-click menu, to make it the default.

Earlier syncs wrote a `Fuse themes` collection with one mode per theme slug, such as `external-fkas-private`. The sync deletes a local collection with that name, and `check` reports it as drift. Frames pinned to a `Fuse themes` mode lose that pin, and designers set the four axis modes instead. The sync never deletes a library collection or a collection extension with that name.

The token values come from `resolveThemeCatalog` in `@elmeragroup/fuse/theme-catalog`. It resolves every theme in both schemes from `composeTheme`, the same composition that generates `themes.css`, and hands the sync each value already read: an sRGB color, a length in pixels, a font family or a font weight, plus the one `var()` hop when the value is a reference. The catalog throws on a token value it cannot read, because token values are Fuse source, and a Fuse test resolves every theme and scheme so CI catches such a value first. The sync maps the resolved values as follows.

- A color becomes an sRGB color, with alpha kept and the channels unrounded. The tokens write `oklch()` or `#rrggbb` literals, and the catalog reads exactly those two forms through `@elmeragroup/color`, which clips a color outside the sRGB gamut.
- `var(--name)` becomes an alias to the matching variable. A role reference points at the role with the same scheme, variant and segment in `Fuse brand`, and a primitive reference points into `Fuse primitives`.
- A `rem` length becomes the catalog's pixels at a 16px root.
- A radius rung becomes the pixels `fuse.css` computes for it, such as `--radius-md: calc(var(--radius) - var(--radius-step, 0px))`, because Figma variables cannot compute. The catalog computes each rung per theme from the theme's `radius` and `radius-step` and the rung's step count, and the sync writes those pixels per brand mode. Internal themes step 0px, so every rung equals `radius`. External themes step 2px, so `external-fkas-private` with a 12px radius gets 6, 8, 10, 12 and 16px from `radius-xs` to `radius-xl`. CSS clamps a negative `border-radius` to 0, and so does the catalog. The sync leaves out `radius-popover`, because no component uses that rung and Fuse popups use `radius-md`.
- A density metric comes from the catalog in pixels per density, read from the same metrics the `fuse.css` density blocks must equal. Heights, including `row-h`, get the width and height picker. Paddings, including the `row-px`, `row-py` and `surface-pad-*` paddings, and gaps, including the `surface-gap-*` tiers, get the gap picker. The type pairs, `control-text` and `control-leading` for controls and `label-text` and `label-leading` for labels such as selection row text, get the font size and line height pickers.
- A font stack becomes its first family name, which the catalog reads.
- A font weight, such as `selection-title-weight`, becomes its number, from 1 to 1000, and gets the font weight picker. The sync sends that picker as `FONT_STYLE`. Figma's REST documentation lists `FONT_WEIGHT` for number variables, but a real file stores `FONT_WEIGHT` as `FONT_STYLE`, so a sync that sent it would never read back what it wrote.
- A derived role, such as `secondary-hover`, becomes the literal color that composition computes, because Figma variables cannot mix colors.
- A role tint, such as `error/10`, holds its role's color at the tint's alpha in every theme. A Figma paint takes its opacity from the alpha of the variable it binds, so a component cannot bind `error` at 10%, and `bg-error/10` binds `error/10` instead. The tint's code syntax is the `color-mix(in oklab, var(--error) 10%, transparent)` that Tailwind compiles the utility to. `ROLE_TINTS` in `fuse-variable-set.ts` lists the tints the component kit binds. A tint appears in its role's pickers, and its description names the role and the percent, since the catalog has no entry for it.
- A formula variable holds what a recipe's formula over theme tokens gives for each theme. Figma variables cannot compute, so `FORMULA_VARIABLES` in `fuse-variable-set.ts` computes each one, and its code syntax is the formula as Tailwind compiles the recipe's class, which the kit binds.
  - The outline Button's shadow lengths, `button-outline-shadow-blur` and `button-outline-shadow-spread`, hold what `max(0px, 4px - 2 * var(--button-outline-width, 1px))` and `min(0px, 2px - 2 * var(--button-outline-width, 1px))` give for each theme's outline width: blur 2 and spread 0 at the internal 1px outline, which is Tailwind's `shadow-xs`, and blur 0 and spread -2 at the external 2px outline, which paints nothing outside the border. They get the effect picker.
  - The compact corner, `radius-compact`, holds what `compactCornerClass` in `corner-radius.ts` gives, `min(radius-md, max(10px, radius - 1000 * radius-step))`. Internal themes step 0px, so it equals `radius`, 8px for Fjordkraft. External themes step 2px, so it is `radius - 2px` capped at 10px: 4px for Elmera's 6px radius and 10px for TrøndelagKraft's 16px. The xs Toggle rounds with it, and it gets the corner radius picker.
  - The checkbox corner, `radius-checkbox`, holds what `checkboxCornerClass` in `corner-radius.ts` gives, `min(radius-md, 4px)`. Every theme's `radius-md` is at least 4px, so it holds 4px in each. The Checkbox box rounds with it, and it gets the corner radius picker.
  - The field box corner, `radius-field-box`, holds what `fieldCornerClass` in `corner-radius.ts` gives, `clamp(radius - 1000 * radius-step, radius-field, radius + 1000 * radius-step)`. Internal themes step 0px, so both bounds equal `radius` and it holds `radius`, 8px for Fjordkraft. External themes step 2px, so the bounds lie 4000px apart and it holds `radius-field`. Every theme sets `radius-field` to `var(--radius)`, so that is 6px for Elmera and 16px for TrøndelagKraft. Fuse rounds Input, Textarea and the other field boxes with that class, and the variable gets the corner radius picker.
- The `Fuse tokens`, `Fuse primitives` and `Fuse density` variables carry web code syntax. A token, primitive or metric carries its `var()`, such as `var(--primary)`. A radius rung carries the `calc()` that `fuse.css` declares, such as `calc(var(--radius) - 3 * var(--radius-step, 0px))`. `fuse.css` declares the rungs in `@theme inline`, so Tailwind inlines them into its utilities, and the built CSS declares no `--radius-sm` property. A test requires every `var()` in the code syntax to name a property that the built `styles.css` or `themes.css` declares.
- A color appears only in the pickers for where Fuse paints it. The catalog gives each color role and primitive its paints from `TOKEN_PAINTS` and `PRIMITIVE_PAINTS` in `@elmeragroup/fuse`, and a source contract holds the library's own color classes to them. A `surface` gets the frame and shape fill pickers, an `ink` gets the text fill, shape fill and stroke pickers, because icons take the text color, and a `line` gets the stroke picker. A role with every fill gets `ALL_FILLS`. `feature-foreground` is a surface only, so the text fill picker leaves it out.
- The neutral ramp gets no picker scope. It holds one value in every theme and scheme, so a layer bound to it breaks dark mode and brand switching. It stays an alias target, as the hidden collections do. The brand accents keep the fill pickers and their foregrounds the text pickers, for artwork that shows several brands.
- Font families get the font family picker. Figma's REST documentation says scopes currently apply only to FLOAT and COLOR variables, but a real file keeps `FONT_FAMILY` on a STRING variable.
- Each length token names its picker scope in a table in `fuse-variable-set.ts`, so a new length token does not compile until someone picks one. `radius`, `radius-button`, `radius-field` and the radius rungs get the corner radius picker, and `button-outline-width` gets the stroke picker.
- `radius-step` gets no picker scope. It is a length, but it spaces the radius rungs and switches between the internal and external variants, so no layer rounds with it. It keeps its code syntax, `var(--radius-step)`.
- Every `Fuse tokens`, `Fuse primitives` and `Fuse density` variable carries the catalog's description, which Figma shows when a designer hovers the variable. The descriptions live beside the tokens in `@elmeragroup/fuse`, and the docs tokens page shows the same text. The hidden variables carry an empty description. A real file stored `&`, `<`, `>`, `"` and `'` in a description HTML-escaped on 2026-10-19, through the REST API and the Plugin API alike, so the sync refuses a description that holds one of them.

## Running it

The Variables REST API needs an Enterprise plan. Create a personal access token under Settings → Security in Figma. The token needs the `file_variables:read` and `file_variables:write` scopes and belongs to a Full seat with edit access to the target file. Figma caps these tokens at 90 days, and a plan access token cannot write variables.

Copy `packages/fuse-figma/.env.example` to `packages/fuse-figma/.env`, which git ignores, and fill in the token and the file key:

```sh
FIGMA_TOKEN=figd_...
FIGMA_FILE_KEY=AbCdEf123   # the part after /design/ in the file URL
```

Then run one of these commands from the repository root:

```sh
pnpm --filter @elmeragroup/fuse-figma figma:check   # print the plan, write nothing, exit 2 when Figma differs
pnpm --filter @elmeragroup/fuse-figma figma:sync    # apply the plan
```

`--file-key <key>` overrides `FIGMA_FILE_KEY`, and a branch key targets a Figma branch. `figma --help` lists every flag.

`check` exits 2 when the file differs from the tokens and 1 when it cannot run, for example when the token has expired, so a CI job can tell the two apart. It groups the plan by collection and kind of change. A group of up to 10 changes lists each variable and mode, and a larger group prints its count.

The token travels in the `X-Figma-Token` header. The sync masks that header on the trace spans Effect's HTTP client records, and a failed request keeps only its method and URL.

After a sync, publish the library in Figma. The REST API cannot publish, so consuming files see the new values only after someone publishes by hand.

## How a sync decides what to write

The sync reads the file, plans one change batch and sends it. Figma applies a batch completely or rejects all of it. The sync then reads the file again and fails unless the plan is now empty, so a successful run means the file was checked.

- It matches collections, modes and variables by name and updates them in place. Ids survive, so every layer bound to a Fuse variable stays bound.
- A mode keeps its id only while the tokens keep its name. The sync deletes a mode the tokens no longer name and creates the modes they add, and it never renames one into another, because a dropped brand and an added one are unrelated. Frames pinned to a deleted mode lose that pin. Renaming a brand's display name in code is therefore a delete and a create in Figma, and designers repin the frames that used the old name.
- Mode order does not matter to the plan. A collection whose modes the file holds in another order than the tokens counts as in sync, because the REST API cannot reorder them.
- The sync orders mode changes so that no collection goes over Figma's 40 modes or runs out of modes while the batch applies. It deletes the stale modes before creating new ones. When no existing mode survives, it keeps the last stale mode until the first new mode exists. The only mode it renames is the one Figma gives a new collection, which becomes the collection's first mode.
- Inside the six Fuse collections, the tokens are authoritative. The sync deletes any mode or variable the tokens do not define, and the next sync resets any value a designer edited.
- It never touches another collection in the file, except that it deletes a local collection named `Fuse themes`, which earlier syncs wrote. The sync skips library collections, collection extensions and deleted variables that layers still reference, even when their names match.
- It refuses to change a variable's type, because Figma can only do that by deleting the variable and unbinding every layer that uses it. The error names the variable to delete by hand.
- Renaming a token in code is a delete and a create in Figma, so layers bound to the old name lose their binding.
- It refuses to sync tokens whose aliases form a cycle. A cycle counts even when each alias closes it in a different mode, because the modes a layer combines decide whether Figma would loop.
- It writes the values of each alias target before the values that alias it. Figma applies values in order and refuses a batch that passes through a cycle after any one value, even when the batch ends without one. This order never passes through a cycle, even when the tokens reverse an alias.
- A value shape or variable type newer than the sync does not stop a read. A variable the sync owns gets such a value rewritten, and a type it does not know is a type conflict.
- It owns every variable's description, so the next sync resets a description a designer wrote. It sets web code syntax on the `Fuse tokens`, `Fuse primitives` and `Fuse density` variables, and sends no code syntax for the `Fuse variant`, `Fuse segment` and `Fuse brand` variables, which only feed aliases. An update replaces a variable's code syntax, so when the sync sets the web entry, it sends the file's Android and iOS entries with it.
- The sync retries a read that hits a rate limit, a server error or a network failure. It waits as long as `Retry-After` asks and logs a warning for each retry. It retries a write only after a 429, because a write that failed on the server may still have been applied. When `Retry-After` asks for more than 60 seconds, the sync fails at once and reports the wait.

The alternative was kumo-figma's approach, which deletes every variable and recreates it on each run. That gives every variable a new id and breaks the bindings in existing designs.

## Components plugin

The plugin creates two component sets from the Button recipe and one from the Confirm button recipe on a page named `Button`, two from the Toggle recipe on a page named `Toggle`, one from the Badge recipe on a page named `Badge`, one from the Kbd recipe on a page named `Kbd`, one from the Radio icon button recipe and one from the Radio recipe on a page named `Radio`, one from the Checkbox recipe on a page named `Checkbox`, one from the Switch recipe on a page named `Switch`, one from the Separator recipe on a page named `Separator`, one from the Skeleton recipe on a page named `Skeleton`, one from the Loader recipe on a page named `Loader`, one from the Field label recipe on a page named `Label`, one from the Input recipe on a page named `Input`, one from the Textarea recipe on a page named `Textarea`, one from the Avatar recipe on a page named `Avatar`, one from the Meter recipe on a page named `Meter`, and an icon library on a page named `Icons`. It edits them in place on every later run, and binds each field it can to the variables `figma:sync` writes.

- The `Icons` frame holds one 16px component per icon `@elmeragroup/fuse/icons` publishes that takes the color of the text around it: the 130 Phosphor icons in their bold default weight and the 5 bespoke icons that paint with `currentColor`. The other bespoke icons are artwork with colors of their own, such as the Vipps mark and the Signing illustration, which read as blots at 16px or vanish on a light fill, so they stay out with the brand logos.
- `Button` holds every variant the recipe declares at the default, xs, sm and lg sizes, in 5 states (rest, hover, focus, disabled and pending) and with no icon, a start icon or an end icon: 420 variants. Its `Label` text property sets the label, and its `Start icon` and `End icon` swap properties pick the icons, Plus and ArrowRight to begin with.
- `Icon button` holds every variant at the four square sizes in the same 5 states, 140 variants, each an icon with no label, which its `Icon` swap property picks.
- `icon-inline` stays out, because it takes its size from the surrounding text line.
- `Confirm button` holds the destructive and success variants, the two `confirmButtonVariants` gives an armed face, at the default, xs, sm and lg sizes, in 4 states (rest, hover, focus and disabled), armed off and on: 64 variants. Its `armed` property sits beside `state`. A disarmed cell draws the Button of its variant, size and state. An armed one fills with `error` or `success` and draws its label in `error-foreground` or `success-foreground` inside the `/20` border. `data-[armed=true]:` weighs (0,2,0) and `enabled-hover:` (0,1,0), so on hover an armed button keeps its fill and only its border turns to the role. Disabling a ConfirmButton disarms it, so a disabled cell draws disarmed at `armed=on` too. Pending disarms it as well, and the set draws no pending state. Its `Label` text property sets the label, `Delete` to begin with, the resting label of the docs' Destructive demo. The demos swap in a label while armed, such as `Confirm delete`, and a designer types it on an armed instance, since a text property holds one default. The set has no icons, since no docs demo places one on a ConfirmButton with a label.
- `Toggle` holds both variants the recipe declares at the default, xs, sm and lg sizes, in 4 states (rest, hover, focus and disabled), off and on, and with no icon, a start icon or an end icon: 192 variants. Its `pressed` property sits beside `state`. Its `Label` text property sets the label, and its `Start icon` and `End icon` swap properties pick the icons, Star on both sides to begin with, as the docs place it.
- `Icon toggle` holds the same variants, sizes, states and pressed values, 64 variants, each one icon with no label, which its `Icon` swap property picks. The icon carries `data-icon="inline-start"`, as in the docs, so it takes the start icon's inset.
- `Badge` holds every variant the recipe declares at the default, sm and lg sizes: 57 variants. A Badge is not interactive, so the set has no state axis, and its columns are the sizes. Its `Label` text property sets the label. It has no icons, since no docs demo places one.
- `Kbd` holds a text cap and an icon cap: 2 variants. The recipe declares no axes, so the set's one property, `content`, says what the cap holds, `text` or `icon`, and its columns are those values. Its `Label` text property sets the text cap's label, `K` to begin with. Its `Icon` swap property picks the icon cap's 12px icon, Backspace to begin with, because the roster has no Command icon. Kbd group, which lays out caps in a row, waits until kit components can hold instances.
- `Radio icon button` holds the recipe's five square sizes, icon, icon-xxs, icon-xs, icon-sm and icon-lg, off and on, in 5 states (rest, hover, focus, disabled and invalid): 50 variants. Its `checked` property sits beside `state`. Each variant is one icon with no label, which its `Icon` swap property picks, List to begin with, as the docs demo places it. icon-xxs and icon-xs share the xs square and differ by icon size, 12px and 14px. The invalid state draws the `error` border and ring of a radio inside an invalid field.
- `Radio` holds the circle off and on, in 4 states (rest, focus, disabled and invalid): 8 variants. The recipe has no hover face. Its `checked` property sits beside `state`. The circle is 16px at both densities. A checked circle fills with `primary` and holds the 16px `radio-group-indicator` frame, which centers the 8px `primary-foreground` dot. An off circle has no indicator, as Base UI mounts it only while checked. The invalid state draws the `error` ring, and the border stays `primary` only on a checked circle.
- `Checkbox` holds the box off, on and mixed, in 4 states (rest, focus, disabled and invalid): 12 variants. The recipe has no hover face. Its `checked` property sits beside `state`. The box is 16px at both densities. A checked or mixed box fills with `primary` and holds the `checkbox-indicator` frame around a 14px `Check` or `Minus`, which the state picks, so the set has no swap property. An off box has no indicator, as Base UI mounts it only while checked or mixed. The invalid state draws the `error` ring, and the border stays `primary` only on a checked box.
- `Switch` holds the track at the default and sm sizes, off and on, in 4 states (rest, focus, disabled and invalid): 16 variants. The recipe has no hover face. Its `size` and `checked` properties sit beside `state`. The track is 32px by 18.4px at default and 24px by 14px at sm, at both densities. It holds the `switch-thumb` frame, a transparent 16px or 12px slot, which centers a `dot` frame. Off, the track is a `muted-foreground` outline, and the slot sits at the start and holds a 12px or 9px `muted-foreground` dot. On, the track fills with `primary`, and the slot sits flush with the end and holds a 16px or 12px `background` dot. The invalid state draws the `error` border and ring.
- `Separator` holds a horizontal and a vertical line: 2 variants. A Separator is not interactive, so the set has no state axis, and its columns are the orientations. The line is 1px thick and fills with `border`. The recipe takes the line's length from its container, which the kit does not draw, so each cell passes a docs demo's length as consumer classes, merged over the recipe as Separator merges its `className`: `data-horizontal:w-64` makes the horizontal line 256px long, and `data-vertical:h-4 data-vertical:self-auto` makes the vertical one 16px.
- `Skeleton` holds a line and a circle: 2 variants. A Skeleton is not interactive, so the set has no state axis, and its columns are the shapes. The block fills with `muted`. Its pulse drops, as Figma components do not animate. The recipe gives no size, so each cell passes a docs demo's shape as consumer classes, merged over the recipe as Skeleton merges its `className`: `h-4 w-48` makes a 192 × 16 line on the `radius-md` corner, and `size-10 rounded-full` makes a 40px circle, whose `rounded-full` replaces the recipe's `rounded-md`.
- `Loader` holds the spinner at the default, small, medium, large and xl sizes: 5 variants. A Loader has no state axis, and its columns are the sizes. The box hugs a `SpinnerGap` in the `foreground` role with 16px of padding on every side. The spinner is 16, 12, 24, 32 or 40px, so the boxes are 48, 44, 56, 64 and 72px square. Its spin drops, as Figma components do not animate, and the visually hidden label is not drawn.
- `Label` holds the label a form shows above its control, at rest and disabled: 2 variants. Fuse has no standalone Label, so the set draws `Field.Label` from the `label` slot of `fieldVariants`. Its `Label` text property sets the text, `Email` to begin with, as the docs' field label. The label hugs its text, set in the `label-text` and `label-leading` type pair at Medium, which is 14/20px dense and 16/24px comfortable, in the `foreground` the page sets. Disabled draws at 50% opacity. The classes for a label that wraps a Checkbox or a Field card drop, since that is Field composition, which waits for wave 3.
- `Input` holds the field with a placeholder and with a typed value, in 5 states (rest, focus, disabled, read-only and invalid): 10 variants. The recipe has no hover face. Its `content` property sits beside `state`. The box is 384px wide, the docs' `max-w-sm`, at both densities, and `control-h-md` tall, with the `control-px-md` padding on each side. It rounds with the field box corner `radius-field-box`, strokes 1px with `input`, fills with `card` and casts `shadow-xs`. Its `Text` text property sets the text, `name@example.com` to begin with, as the docs' placeholder. The text fills the row between the paddings in the `control-text` and `control-leading` pair at Regular, centered down the box, and ends in an ellipsis after one line. A placeholder draws in `muted-foreground` and a value in `foreground`. Focus draws the 2px `ring`. Disabled draws at 50% opacity on the `input/50` fill, and read-only fills with `muted`. Invalid draws the `error` border and its 3px `error/20` ring, and a value there draws in `error`, the text color an invalid Field passes down.
- `Textarea` holds the field with a placeholder and with a typed value, in Input's 5 states: 10 variants. Its `content` property sits beside `state`. The box is 384px wide at both densities and draws Input's corner, border, fill, shadow and state faces, with the `control-px-md` padding on each side and 8px above and below. `field-sizing-content` makes its height hug the text, and `min-h-16` keeps it at least 64px tall. Its `Text` text property sets the text, `Tell us more…` to begin with, as the docs' placeholder, and the value cells show it on one line too. The text fills the row between the paddings from the top, in the `control-text` and `control-leading` pair at Regular, and wraps, its height following its lines. It draws a placeholder, a value and an invalid value in Input's colors.
- `Avatar` holds the initials and a picture at 32, 24, 40 and 48px: 8 variants. An Avatar is not interactive, so the set has no state axis, and its columns are the sizes, the recipe's 32px first. Its `content` property is `fallback` or `image`. The root is a `muted` circle that clips what it holds. Each cell passes the docs size demo's `size-8`, `size-6`, `size-10` or `size-12` as consumer classes, merged over the recipe's `size-8` as Avatar merges its `className`. The `avatar-fallback` frame fills the circle and centers the initials, `AL` to begin with, in the 14/20px Medium `muted-foreground` text the root sets. Its `Label` text property sets them. The label holds initials and draws them on one line, where a browser would wrap a longer name and the circle would clip it. A designer replaces the picture by changing that fill on an instance. Avatar group, which stacks avatars, waits until kit components can hold instances.

### Running it

1. Run `figma:sync` on the file first. The plugin binds only the variables the sync owns, and it stops before writing anything when one is missing. 2. Build the plugin from the repository root:

   ```sh
   pnpm --filter @elmeragroup/fuse-figma figma:plugin
   ```

   The build writes `plugin/dist/code.js`, the kit spec `plugin/dist/spec.json` and the coverage table `plugin/dist/coverage.md`. Build in the checkout whose `plugin/manifest.json` Figma imported, and run `pnpm install` first after a pull that adds dependencies. On 2026-10-21 the plugin failed to load with ENOENT on `plugin/dist/code.js` for that reason.

3. In the Figma desktop app, open the file, choose Plugins → Development → Import plugin from manifest, and pick `packages/fuse-figma/plugin/manifest.json`. Figma runs a development plugin only in the desktop app.
4. Run the plugin and press Plan. It lists every change an apply would make, and writes nothing.
5. Press Apply. The plugin writes the changes, then plans again and shows any change that remains. A clean run shows none.
6. Publish the library by hand, as for the variables.

### How the spec is built

The build calls each recipe from the workspace-only `@elmeragroup/fuse/recipe-catalog` entry for each cell of its matrix. It sorts every class by its variants and maps them onto the cells as the component renders them. `fuse.css` and Tailwind fix most of what a variant means, so one shared table in `components/state-table.ts` holds that meaning for every component set. A definition such as `button-kit.ts`, `confirm-button-kit.ts`, `toggle-kit.ts`, `badge-kit.ts`, `kbd-kit.ts`, `radio-icon-button-kit.ts`, `radio-kit.ts`, `checkbox-kit.ts`, `switch-kit.ts`, `separator-kit.ts`, `skeleton-kit.ts`, `loader-kit.ts`, `label-kit.ts`, `input-kit.ts`, `textarea-kit.ts`, `avatar-kit.ts` or `meter-kit.ts` adds only the variants its own states render, facts for variants only it uses, and its own omissions. The build stops when a definition gives a shared variant a second meaning. A definition also names the cells that show its label, so the Kbd's icon cap drops the text classes as a cell with no text. A set can draw a component that wraps another. ConfirmButton passes `confirmButtonVariants` to Button as its `className`, which Button merges after `buttonVariants` with `cn`, so `confirm-button-kit.ts` merges the two recipes the same way and imports Button's label sizes and omissions from `button-kit.ts`.

A definition can declare parts below its root, such as a checkbox's indicator. A part has its own classes, the cells it appears in, and its own parts, icons and label. Its layer takes its `data-slot` as its name, or its key when the element has none, as Radio's dot does. A part's children sit in DOM order: its parts first, then the start icons, the label and the end icons. Each part becomes a frame layer and cascades its own classes. It inherits its parent's computed `color`, `font-family`, `font-size`, `font-weight`, `font-style`, `line-height`, `letter-spacing`, `white-space` and `text-align`, and every custom property whose `@property` does not say `inherits: false`, at the rank the host page has on the root. Tailwind registers every `--tw-*` property with `inherits: false`, so a part takes their initial values. An icon inherits from the part that holds it the same way, so it takes its glyph color from the part's text color, and a size the part gives through a custom property reaches it. `color: currentcolor` computes to the color the part inherits, so the checkbox indicator's `text-current` keeps the root's `primary-foreground`, and the coverage table records the class with what it resolved to. A flex box's `flex-direction` sets its direction. `row`, or none, makes a horizontal auto layout, and `column` a vertical one. Any other direction stays unmapped. A part's alignment comes from its own classes. `items-start`, `items-center` and `items-end` set the counter axis to MIN, CENTER or MAX. `justify-start`, `justify-center` and `justify-end` set the primary axis, and `justify-between` sets it to SPACE_BETWEEN, which puts the first and last layer flush with the ends and the spare room between the layers. Any other alignment stays unmapped. In a row an unset alignment stays centered, as every published row was drawn. A column takes CSS's start on both axes. Its unset `align-items` stretches its layers, so a part with no width fills the column's width, while a part whose width is a length or `w-fit` keeps it. Figma shrinks a layer that fills a hugging frame, so a column that hugs its width cannot stretch a part, and the build records the missing `align-items` as unmapped under the column's class. A grid with no template puts each child in a row of its own, so `grid` with `place-content-center` maps to a box centered on both axes only while it holds one layer, as the checkbox indicator holds its glyph. Any other grid stays unmapped. A `block` box with no layers lays nothing out, so it reads as a frame, as Switch's thumb does, and one with layers stays unmapped.

A box's `width` and `height` set the sizing of each axis. A length is fixed, and an unset one hugs, unless a column stretches it. Exactly `100%` fills the axis when the box's parent is a flex box whose length on that axis is definite: fixed, or itself filling a definite length. Along the parent's direction that holds only for the parent's only layer. Beside other layers, CSS sizes the box at the whole length and then shrinks or overflows it with them, while a fill takes only the room they leave, so such a `100%` stays unmapped, and its row names the other layers. In a parent that hugs the axis, the percentage takes a length that depends on the box, and Figma would shrink the box, so it stays unmapped. Any other share of a parent's auto layout, such as `w-1/2`, stays unmapped, since a fill takes no share. A variant root sits in a component set without auto layout, so its percentage width takes the preview width its definition names, as a fixed length, `w-full` the whole of it and `w-1/2` half, and stays unmapped without one. A block-level root, one whose `display` is `block`, `flex`, `grid` or `flow-root`, that sets no width takes the preview width too, as a block box with no width fills its container, so Meter's `flex flex-col` root is 256px wide. Beside a length that hugs or fills, `min-width`, `max-width`, `min-height` and `max-height` become the box's limits. Figma takes only a positive limit, so a maximum of zero or less stays unmapped there. Beside a fixed length, CSS lowers the length to its `max-*` and then raises it to its `min-*` (CSS 2.1 §10.4), and the kit check refuses a limit on a fixed axis, so the build folds the limits into the length: `w-[20px] max-w-[12px]` draws 12px wide. A limit that never moves the length drops, as the checkbox's `max-w-4` beside its `size-4` does. Whether one limit moves the length depends on the length and on the other limit, so when any of them binds a variable or is no literal, every limit on that axis stays unmapped. A fold that leaves a length of zero or less stays unmapped too. A zero minimum, such as `min-w-0`, drops, since Figma takes no zero limit and its auto layout never shrinks a layer. `field-sizing: content` reads as a height that hugs its content. `overflow: hidden` makes a box clip its content. Every root clips already.

A label is its box's own text, which `components/label-layout.ts` maps. In a block box, one that is neither flex nor grid, CSS sets the text in lines across the content width. Where that width is fixed or fills, text that wraps breaks its lines there, so the label fills the width and its height follows its lines. A flex box sets its text as an anonymous flex item, which does not grow, so a short label sits at its own width where the box places it. A label that fills draws the same only where the box places it where the text sets its lines: at the start of a row with its lines at the left, or centered with centered lines. A column with an unset `align-items` stretches its text across a definite width, which a fill always draws. Any other placement, a label that shares a row with other layers, and a label in a grid stay unmapped, and the coverage table says why. A text of ASCII letters and digits alone, such as Avatar's initials `AL`, holds no soft wrap opportunity, since line breaking keeps its classes AL and NU together (UAX #14), so a browser never wraps it. In a flex box such a label sits at its own width wherever the box places it, so where the rules above leave a wrapping label unmapped, it hugs instead. A space, a hyphen, any other character, or a box that sets `word-break`, `line-break`, `hyphens` or `overflow-wrap` keeps those rules. Fullwidth letters such as `ＡＬ` count as other characters, since they take class ID, which breaks between them. A designer who types a text with a space into such a label sees one line where a browser would wrap it. A box that hugs its width is as wide as its text on one line, since a kit frame always has room to spare, so its label hugs. `white-space: nowrap` keeps the text on one line at its own width, so the label hugs, as every published label does.

A part can show an image, as an `<img>` shows its `src`. Its definition names the bytes of a PNG file, the one format the kit ships, and the build writes them base64 encoded into the part's fill as an image paint, with their SHA-1 in lowercase hex. On 2026-10-22 a real file named Avatar's stored portrait by exactly that hash (probe P9b), so the plugin compares a held paint with it and Plan stores no image. `object-fit: cover` scales the image to cover the box and crops what overflows, which an image paint at FILL draws. Any other fit stays unmapped, and a box with no `object-fit` stops the build, since CSS's initial `fill` stretches the image, which no image paint draws. The image covers the box, so the build reads no `background-color` under it, and one the box sets stays unmapped. Avatar's portrait is `components/avatar-portrait.png`, the docs demo's SVG portrait drawn once as a 96px PNG, twice the largest Avatar, since Figma stores no SVG image. `avatar-kit.ts` says how it was drawn, and the compare renderer reads the same file.

`truncate` sets `overflow: hidden`, `text-overflow: ellipsis` and `white-space: nowrap`. `text-overflow` applies only to a block box, so there, at a fixed or filling width, the label fills the width and ends in an ellipsis after one line. A flex or grid box clips its text item with no ellipsis, so its label hugs and the box clips it. `line-clamp-2` makes the box a `-webkit-box` column that hides its overflow and clamps its wrapping text at `-webkit-line-clamp: 2`, so the label fills the width and ends in an ellipsis after two lines. One decision covers the box and its label: the build draws such a box as a column that sets its text from the top left only where every one of those declarations holds and the box holds just its label, and leaves the box's display and the clamp unmapped together otherwise. In a box that hugs its width the text never overflows, so the ellipsis drops. A box that hugs its width up to a `max-width` wraps or cuts its text off at that limit, while a text in a hugging Figma frame keeps its own width past the frame's limit (P7), so a wrapping, truncating or clamping label there stays unmapped. `white-space` and `text-align` inherit, so a `truncate` on a box keeps a part's label on one line, while the clip and the ellipsis stay on the box, and a box without text of its own drops its `text-overflow` and `-webkit-line-clamp`. Any other `white-space`, and an ellipsis without the other two declarations, stays unmapped.

`text-align` sets a label's lines at the left, in the center or at the right of its box, and `start` and `end` read as left and right. No class says where a native control places its text, such as an `<input>` that centers its value down its box, so a definition can name it in its label's `placement`, across as `start`, `center` or `end` and down as `top`, `center` or `bottom`. The label hugs its height, so the placement down sets the box's alignment, which moves the label to the top, the middle or the bottom of the box. The placement across sets the box's alignment too, which places a label that hugs its width. A label that fills the width also takes it as its own text alignment, and the box's alignment keeps the text in place when a designer makes it hug. A `text-align` still sets the lines across. A label with neither sets its lines from the top left, as CSS sets a box's text.

A placement's `lines` says the control sets its text in lines itself, whatever the box's `display` says. The text is no line box or anonymous item of the box's own, so the rules above do not apply to it.

- `single` sets the text on one line across the content box, as an `<input>` sets its value, whatever `white-space` says. The label fills the width and ends in an ellipsis after one line, the overflow the owner chose where a browser clips the value, and the box's `white-space`, `text-overflow` and `-webkit-line-clamp` drop.
- `wrap` wraps the text at the content box's width, as a `<textarea>` wraps its value. The label fills the width with its height following its lines, and ends in no ellipsis. A `<textarea>` honours its own `white-space`, so `white-space: normal` reads as the wrap, and any other value stays unmapped, as do `text-overflow` and `-webkit-line-clamp`.

A box that hugs its width stops the build, since such a control takes its width from its `size` or `cols` attribute, which no Figma field holds.

A label shows one text in every cell, which a TEXT property of the set can set, or a text per cell through `charactersFor`, which no property sets, since a TEXT property holds one default. Labels on two parts can name two properties. Two labels that name one property list it once and must start with the same text, and the build stops on two different texts and names both labels.

A part can be optional behind a BOOLEAN property of the set, as a docs demo leaves out a description. Its definition names the property and the value it starts with in `optional`. The set lists the property once, and the part's frame links its `visible` to it, so a designer shows or hides the part from the properties panel. Two parts that name one property must start it the same, and the build stops on two defaults and names both parts. Hiding a part hides every part inside it, so the build also stops on an optional part when a class of the set reads, through a `data-slot` inside a `:has()`, whether the part or a part inside it is there, as `item-described:` reads whether Item holds a description, and names the class and the `:has()`. Such a selector restyles its box once the part is gone, while a BOOLEAN property only hides the part's layer, so the part's presence takes a variant axis instead, whose facts hold the class. The check reads every rule that names the class, whatever its selector starts with, since Tailwind compiles `item-described:self-start` to `:where(:has( > [data-slot="item-content"] > [data-slot="item-description"])) > .item-described\:self-start`. `components/css-selector.ts` scans the selectors, as it does for the specificity count, through escapes, quoted values and nested parentheses. A rule it cannot read, or one that tests a `data-slot` other than by its whole value, such as `[data-slot^=chip]`, stops the build too.

A label's `leadingSpace` says the markup holds a space before the characters, as Meter's value holds one after its icon. A box that sets its text in lines puts that space between a start icon and the characters, one space advance of the label's font wide, which the build draws as the box's gap. Roboto's space is 508 of its 2048 units per em at Regular and 509 at Medium, as the `hmtx` tables of `@fontsource/roboto` 5.3.0 hold it, so Meter's 14px value sits 3.47px after its icon. With no icon before it the space starts the line, and in a flex box it starts the text's anonymous item, and either way it collapses, so the box keeps its own gap. The build stops where the space would sit beside more than one icon, or the label's size is no literal. A designer who retypes the value keeps the gap, which a space in the characters would not survive.

A part can carry a style attribute, as Base UI's `MeterIndicator` writes `inset-inline-start: 0; height: inherit; width: 85%` on a meter's fill. Its definition gives the declarations per cell in `styleFor`, and they cascade above every class, as a style attribute beats every rule of a style sheet, so the fill's `h-full` loses to them and leaves no row. `inherit` takes the parent's computed value, inherited or not, so the fill's height is the bar's 6px, and the coverage table records the bar's `h-1.5` with what the fill read. `inset-inline-start` and `inset-inline-end` read as `left` and `right`, where a left-to-right page puts them, and cascade with them, so the fill's `left-0` loses too. The coverage table lists each declaration under the part, with `inline style` in place of a class.

A part with `absolute top-1/2 left-1/2 -translate-x-1/2 -translate-y-1/2` centers itself on its containing block. The offsets put its corner at the block's center, and the -50% translate moves it back by half its own size. The build draws it as a layer its parent's auto layout centers, and requires the parent to center its one layer on both axes. The parent must also sit centered in the containing block, which the build does not check. Radio's indicator is a 16px box centered in its `relative` root, so the dot lands at the root's center, as in the browser.

A part with `absolute top-0 left-0` sits outside its parent's auto layout, as an absolute layer at the parent's top left, as a meter's fill sits in its bar. CSS takes an absolute box out of its parent's flow and resolves its offsets and percentages against its containing block, the padding box of its nearest positioned ancestor (CSS 2.1 §10.1). The build reads the pattern only where the parent is positioned, so the parent is that block, and has no padding or border, so the block's corner is the frame's. The part's width must be a share of the parent's width, fixed or filled, and its height the parent's whole height, as `100%` or `inherit` take it. CSS sizes the block after its own limits, so a bar that fills a 256px column up to `max-w-[128px]` gives an 85% fill 108.8px, and a limit the build cannot read leaves the share unmapped. The width keeps its share as the parent grows, which Figma's SCALE constraint draws, and the height keeps both edges, which STRETCH draws. On 2026-10-22 a real file kept such a layer's share through a FILL bar and an instance resize (P8). A `min-*` or `max-*` on the part bounds its share, which CSS holds as the parent grows and the constraints would carry past, so such a part stays unmapped, and its row names the bound. Out of the flow, the part is no layer of its parent: every layout reader of the box, the `100%` and stretch rules above, the label's rules and the grid's one item, counts only the layers in its flow. Every other use of `position`, `top` or `left` stays unmapped, and a translate maps only as the next paragraph says.

A part that its parent's flex row holds alone can move along the row with a translate, as Switch's thumb does. A row that leaves `justify-content` unset packs the part at the start of its content box, and the translate moves the part from there, a percentage taking the part's own width. The build reads a move of 0 as the row's start alignment, MIN, and a move by the content width less the part's width as its end alignment, MAX. The default thumb's `calc(100% - 2px)` is 14px, and the track's content box is 32px less its two 1px borders, so 14px puts the 16px thumb flush with the end. Any other move stays unmapped, and so do a vertical move, a move in a row with no fixed width, and a move in a row whose `justify-content` is set, unless it is `flex-start` and the move is 0. A move in any other layout, such as a grid that centers its one layer, stays unmapped.

A part with `scale` draws its paint at that share of its size around its center and keeps its layout size. A part whose classes set `scale` in any cell becomes a transparent slot at its layout size, which keeps the part's name and centers a layer named `dot`. The dot holds the part's fill, stroke, corner, shadows, opacity and layers at the scaled size. Every cell then has the same layer tree, slot and dot, whether the scale holds or not, so Switch's off thumb is a 12px dot in a 16px slot and its on thumb a 16px dot. Only a scale the same on both axes maps, on a part with fixed sides, literal lengths, no shadow and no layers of its own, since Figma cannot scale a bound length or a child. Every other transform but `rotate`, which the next paragraph reads, stays unmapped.

`rotate` turns a part or an icon about its center and leaves its layout as it was. Tailwind 4 compiles `rotate-180` to `rotate: 180deg` and `-rotate-90` to `rotate: calc(90deg * -1)`, and the build reads those two forms and `none`. Figma counts a layer's `rotation` counterclockwise, from -180 to 180. On 2026-10-22 a real file read `relativeTransform` `[[0, -1], [1, 0]]` for a layer at -90, a clockwise turn in Figma's y-down space (PQ), so `rotate: 90deg` is -90 and `rotate: 180deg` is 180. A layer carries its `rotation` in the cells that turn it, as an open caret does. A turn of the root stays unmapped, since a variant sits in its component set outside any auto layout, and so does a turn in another unit or about an axis.

- `enabled-hover:` and `hover:` hold on hover, and `focus-visible:` on focus. `fuse.css` gates `enabled-hover:` on an enabled element, and `hover:` has no gate. `tailwindcss-react-aria-components` compiles `hover:` to `:hover`, or to `[data-hovered]` on an element marked `data-rac`, which React Aria stamps while the pointer is over it, as on a Calendar day cell. A cell draws one state, so no cell is hovered and disabled at once, and the two hold in the same cells.

- `data-horizontal:` holds on Separator at `orientation=horizontal` and `data-vertical:` at `orientation=vertical`. `fuse.css` defines both on the `data-orientation` Base UI stamps.
- `placeholder:` holds on Input and Textarea at `content=placeholder`, where the control holds a placeholder and no value, so `::placeholder` paints. The field box's read-only arm `[&[readonly]:not(:disabled)]` holds at `state=readonly`, where both render `readonly`. A disabled `<input>` or `<textarea>` is natively disabled and Base UI never marks it `aria-disabled`, so both omit `aria-disabled:`, as Toggle does. They also omit `entry-floor:`, which raises a field's text to 16px for a coarse pointer or iOS WebKit, since the kit draws a desktop with a fine pointer.
- `has-data-[icon=inline-start]:` holds while an icon of the cell carries `data-icon="inline-start"`. A start icon does, and so does the spinner's span while pending. `has-data-[icon=inline-end]:` holds with an end icon.

A shared state variant holds only where the set's `state` axis has the value that renders it. When the axis lacks that value, the variant stays unmodelled and its classes land in the coverage table as unmapped, so the gate fails instead of the variant holding in no cell. A set with no invalid state drops `aria-invalid:` and `data-invalid:` instead, as every set drops `enabled-active:` and `aria-expanded:`, which describe states no standalone component shows. A child selector styles the icons it reaches, each with its own cascade. On Button that is the root's own leading icon, which `hidden` leaves out while pending, so the spinner takes its place and an end icon stays. An icon can also carry classes of its own, as the `<svg>` does in the markup, such as the recipe's `icon` slot on Loader's spinner, `animate-spin size-4`. They cascade with the child selectors that reach the icon, each by its specificity, so a box's `[&_svg]:size-4` (0,1,1) beats the icon's own `size-6` (0,1,0). `[&_svg:not([class*='size-'])]` skips an icon whose own classes hold `size-`. The coverage table lists an icon's own classes under the icon's layer name.

Tailwind's own compiler compiles each class and its bare utility against `fuse.css`, and the build reads the rules from the syntax tree Tailwind returns. The build applies the classes that hold in a cell as the browser applies rules in one cascade layer: by the specificity of the full class's compiled selector, then by its place in Tailwind's output. `components/specificity.ts` counts specificity as CSS Selectors Level 4 does, where `:where()` adds nothing and `:is()`, `:not()` and `:has()` add their most specific argument. A variant does not always add specificity. `aria-invalid:` adds an attribute, and `fuse.css` wraps the attribute of `data-checked:` in `:where()`, so a checked invalid Radio icon button strokes with the `error` of `aria-invalid:` and `data-invalid:`, though Tailwind emits `data-checked:border-primary` later. A value that equals the web code syntax of a synced variable binds that variable, so `px-(--control-px-button-md)` binds both side paddings to `control-px-button-md`. A radius rung compiles to the same `calc()` that the sync writes as its code syntax, so it binds too, and the compact and checkbox corners compile to the `min()` of `radius-compact` and `radius-checkbox`. A box's own custom property substitutes into its other values, so the field box's `rounded-(--field-corner)` reads the `clamp()` its `[--field-corner:…]` class declares, which binds `radius-field-box`. `rounded-full` compiles to `calc(infinity * 1px)`. CSS scales down corner radii whose sum exceeds a side, so it draws any radius above half the box's shorter side as that half. The build writes that half as a literal when both sides are fixed, 8px on Radio's 16px circle and 4px on its 8px dot. On 2026-10-22 a real file drew a 100px radius on a 16 × 16 frame and on a 64 × 16 frame the same as an 8px one, and stored 100 (probe P10), so Figma draws a radius above half the shorter side as that half, as CSS does. When one side is fixed and the other hugs or fills, the build therefore writes half the fixed side, and Figma draws it as CSS does whichever side ends up shorter. A box that fixes neither side has no length to halve, so its `rounded-full` stays unmapped. A `color-mix()` toward `transparent` binds the role tint whose code syntax it equals, so `bg-error/10` binds `error/10`. A mix without a synced tint stays unmapped. A length that depends on a percentage, such as `calc(4px + 100%)` in either operand order, stays unmapped too, since a Figma number field cannot hold a share of the containing block. Only a width or height of exactly `100%` reads, as a sizing. `w-fit` compiles to `width: fit-content`, the width of what the box holds when its container has room to spare, which a kit frame always has, so Label's `w-fit` reads as a hug. A `max()` of a variable and a length binds the variable when the variable holds at least that length in every mode, and a percentage floor never binds. xs uses `max(var(--control-h-xs), 24px)` as its 24px target floor, and `control-h-xs` is 24px or more at both densities, so it binds `control-h-xs`. A shadow's blur and spread bind the same way, so the outline shadow binds the two outline shadow lengths. Values compare with the fallbacks of synced variables dropped, as Tailwind's own substitution leaves them. A background that is a literal color at alpha 0, such as `bg-transparent`, becomes no fill, because it paints nothing in CSS, and the coverage table records it as a literal. Any other value must evaluate to a number or a color, or it stays unmapped. `@elmeragroup/color` reads both the comma form of `rgb()` and the space form Tailwind compiles an arbitrary color to, such as `rgb(0 0 0/0.05)`.

The root inherits the text color and font family of the host page. The build applies the `font-sans text-foreground` that the docs layout sets on `<body>` before any recipe class, so the outline Button's label binds `foreground`. A definition's `inheritedFor` names the declarations an element between the page and the root sets in a cell. The page's and those declarations then compute a style of their own, the ancestor's after the page's since it sits nearer, and the root inherits its computed values as a part inherits its parent's. So an ancestor's `var()` resolves against the ancestor's custom properties, the root's `currentcolor` takes the inherited color, and every class of the root's own beats them. An ancestor's declaration the root overrides drops. The invalid cells of Input and Textarea inherit `color: var(--error)` from the invalid Field root's `data-invalid:text-error`, so a typed value draws in `error`, while the placeholder's own `placeholder:text-muted-foreground` wins in the placeholder cells.

Each root and each part also gets the base-layer rule of `fuse.css`, `border-color: var(--border, currentcolor)`, which gives every border the border role. The build reads the rule from Tailwind's compile of `fuse.css`, by its arm for every element except a native form widget without a `data-slot`, and stops when the rule or its `border-color` is gone. Every part is a span, so the arm also matches a part without a `data-slot`. The rule sets the color on the element itself, so the build keeps it apart from the inherited page declarations and applies it after them and before every recipe class, since any utility beats the base layer. The outline Badge sets `border` and no color, so its stroke binds `border`, and `coverage.md` names the rule as `fuse.css base layer`. A root that draws no border drops the rule. A border that neither a class nor the rule colors stays unmapped, so the gate fails instead of the stroke vanishing.

`underline` underlines the label, and `underline-offset-*` sets the underline's offset in pixels. A cell that draws no underline drops the offset.

The icon library comes from the same React components apps render. Node cannot load the bespoke icons' TSX, so the build bundles a small module with rolldown that renders each icon with `react-dom/server`. A Phosphor icon renders at 16px. A bespoke icon renders at its own size, and the plugin scales it to fit 16px. The library keeps an icon only when it paints with `currentColor` alone. Figma cannot read `currentColor`, so the markup paints the icon black and the plugin binds its color.

`coverage.md` lists every declaration with what became of it, and the part whose classes set it, so one class on two parts gives two rows. A declaration a part inherits and reads lands under the part that set it. Each declaration in a computed style names the part and class that set it, and the build settles a cell's coverage once it has mapped every layer, so a class that only a part two levels down reads still counts as read. Bound and literal declarations reached a Figma field. A dropped declaration has no Figma form, such as a cursor, a transition or the animations of Skeleton's `animate-pulse` and Loader's `animate-spin`, or belongs to a state no cell shows. `tabular-nums` sets `font-variant-numeric`, which has no Figma form either. The markers `group`, `peer` and their named forms emit no CSS and drop. A custom property draws nothing itself, and the box's own reads of it count already, so one that nothing reads only passes its value down. It drops on a box that holds no part or icon, as the field box's `--shell-inner`, `--shell-corner` and `--inner-corner` do on Input and Textarea, and stays unmapped on a box with parts. A local value of a synced variable, such as `[--card:#f00]` beside `bg-card`, stays unmapped too. The browser paints the local value, while the build keeps a synced variable as its `var()` and binds it. `position: relative` drops, because it only anchors positioned descendants, which auto layout does not need. The centered part and the absolute part at its parent's top left land as literal, and any other position stays unmapped. `align-self: auto` drops on the root, which sits in no flex row, as Separator's `data-vertical:self-auto` does, and any other `align-self` on the root stays unmapped. `vertical-align` drops on the root, which sits in no line of text, as Avatar's `align-middle` does. It drops on an icon too, since Figma has no line of text and the box's auto layout places the icon. Meter's `align-text-bottom` sets its icon about 0.2px lower in the 14/20px line than the value's row centers it. An icon's `display: inline-block` reads as shown, and `none` leaves it out. An outline in a literal color at alpha 0, such as Meter's `outline-transparent`, paints nothing, so its style, width, offset and color drop, as a transparent background becomes no fill. Any other outline stays unmapped. `aspect-ratio` drops when both sides are fixed, as Radio's `aspect-square` is beside its `size-4`, since the ratio then sizes neither side, and stays unmapped otherwise. The plugin typings let a plugin read a text layer's `openTypeFeatures` and give no setter for `TNUM`, so the Kbd label keeps the font's default numerals. An unmapped declaration is one the build cannot express yet, and a test holds the count at zero.

### How the plugin decides what to write

- Plan and Apply run the same planning pass. The pass checks the kit against the file, matches each node and records every write as an operation, and it writes nothing. Plan lists the operations. Apply finishes the pass and loads every font the text writes need, so a duplicate key, a missing variable, a variable of the wrong type or a font this machine cannot load stops the run before any write. Then it performs the operations in order. Plan loads the fonts too, so it fails where Apply would. A label the run creates takes its family from the file's variable, which the pass resolves through the modes the new label will read.
- Each field planner compares the node with the spec and records an operation only when they differ, so a second run over an applied file plans nothing. A fill, stroke or shadow matches only with the `NORMAL` blend mode the plugin writes. A text field counts as bound only when every character binds the variable.
- Writes that depend on each other share one operation. A resize or a width or height binding turns a box's hugging or filling axis fixed, so the operation that writes a length writes both axes' sizing again after it. A label's font write comes first among its writes and needs only the new font, so the plugin can replace a font this machine lacks. The spec sets the style as a literal, so the font write also clears any variable a character binds to `fontStyle` or `fontWeight`. A new node is one operation that creates the node and everything the spec puts inside it, so Plan lists it once. A new page is the exception: Plan lists it, and then each set, preview or icon library the run creates on it, because the plugin plans a page's nodes in the outer pass.
- A bound paint matches by its binding alone, because Figma sets a bound paint's opacity from the variable's alpha. Two runs on a real file, on 2026-10-19, wrote `error` at 10% and read it back at 100%, which is why the kit binds role tints.
- An image paint names its image by a hash, and Figma stores the image apart from the layers. On 2026-10-22 a real file named the stored portrait by the SHA-1 of its bytes, read a written image paint back with that hash and Figma's defaults for every other field, and read the same once that readback was written again (probes P9 and P9b). The spec carries the hash, so a held image paint matches by its hash and its scale mode, besides the visibility, blend mode and opacity every paint is held to, and Plan stores nothing. A designer's filters or rotation on the paint stay. Apply stores the image with `createImage` in the operation that writes the paint, and stops before the write when Figma names it by another hash.
- The kit check holds each image to what Figma stores: a PNG whose signature and IHDR chunk are whole, from 1 to 4096 pixels on a side, the limit Figma's reference states. On 2026-10-22 a real file stored the first 100 bytes of a PNG and refused its 8-byte signature alone with `Image type is unsupported` (P9b), so Figma reads the header, not the whole file. The check also requires the spec's hash to be the SHA-1 of the bytes. A new layer stores its image only when the operation that creates it runs, after earlier writes, so the check refuses such an image before the first write.
- The build makes every variant root clip its content, through the box's `clips`, because Figma draws a drop shadow's spread only from a frame that clips and has a visible fill. A fill at alpha 0 does not count: on 2026-10-20 the focus rings of ghost and link held their 2px spread over one and drew nothing. A root with a spread shadow and no fill therefore gets black at alpha 0.0015, which Figma counts and which changes no 8-bit channel. A transparent background reaches the plugin as no fill, so a Toggle's focus ring gets the clear fill too. The plugin also sets a shadow's geometry again after it binds the shadow's color. Two runs stored the spread as 0, and the third, which did this, kept it.
- A variant root is an auto layout along the spec's `direction` that places its layers as the spec's `primaryAlign` and `counterAlign` say. `SPACE_BETWEEN` along the direction puts the spare room between the layers. On 2026-10-22 a real file kept it through an `itemSpacing` write and a binding, so the plugin writes the spacing after the alignment as before. The typings give the counter alignment no stretch, and allow a baseline only in a row. Every published root is a row. Each centers its layers on both axes, except Switch's, whose thumb's translate places it at the start or the end. A part below the root is a frame layer with the same box fields, and it can hold frames of its own. The build makes such a frame show its overflow unless it sets `overflow: hidden`, as a CSS box does, and the plugin writes `clipsContent` from `clips` on every box. A part gets no clear fill, because no part below a root casts a spread shadow yet.
- A box's `sizing` makes each axis fixed at a length, hugging its content, or filling the room its parent's auto layout gives it. The plugin writes it through `layoutSizingHorizontal` and `layoutSizingVertical`, which Figma reads as a projection of the sizing modes, a text's auto resize and the parent's grow or stretch. On 2026-10-22 the real file's Button roots read hugging across and fixed down, their labels hugging both ways, and the Separator and Switch boxes fixed both ways. The build writes a fill only where a part's `100%` or a column's stretch meets a definite length, so no fill sits in a hugging parent.
- The plugin writes a box's direction, then its alignments, then its fixed lengths, then its sizing, then its limits. A direction change keeps each sizing mode in its role along or across the direction. On 2026-10-22 a row 40 tall that hugged its width hugged its height once it became a column, and stood 14 tall. So the plan compares the spec with the sizing the box will read in its new direction, and a turn rewrites the box's fixed lengths after it. A turn also moves the fill of each layer inside the box to the other axis, so it rewrites those layers' sizing and fixed lengths too, labels included. On the same file a resize or a width binding turned a filling child fixed, which is why the sizing follows the lengths in their operation. No probe has shown what a box stores in its sizing modes, or how it sizes, when it first gets an auto layout, as every new box does, so a box without one writes its sizing whatever its modes predict.
- A text's `sizing` sets its auto resize. A text that hugs both ways is `WIDTH_AND_HEIGHT`, one whose width fills or is fixed and whose height hugs is `HEIGHT`, and one fixed both ways is `NONE`. The plugin writes, in one operation, the auto resize, then `layoutSizingHorizontal` and `layoutSizingVertical`, then a fixed width or height, then `textTruncation`, then `maxLines`. The label's font comes first, in an operation of its own. On 2026-10-22 a real file turned a `WIDTH_AND_HEIGHT` text that filled a row into `HEIGHT`, kept a filling text `HEIGHT` when asked for `WIDTH_AND_HEIGHT`, and gave a resized `HEIGHT` text a fixed width with its height still on its lines. So a new auto resize moves the text's hug, and the operation writes the sizing and any fixed width or height after it whatever the text reads now, since a hugging text's size also follows a font the run writes first. On the same file a `maxLines` written while truncation was off changed nothing, truncating at the ending alone read one line, and `maxLines` null under the ending showed every line. So the plugin writes the maximum after the truncation, and writes it again whenever the truncation changes. The text's `align` sets `textAlignHorizontal` and `textAlignVertical` after that operation. On 2026-10-22 all 420 labels of a real file's Button and Icon button sets read `textAlignHorizontal` LEFT and `textAlignVertical` TOP, with `WIDTH_AND_HEIGHT` and truncation `DISABLED` (probe P0b). The plugin wrote no alignment when it created those labels, so a new text sets its lines from the top left, and a Plan writes no alignment on a published label.
- A frame's `absolute` takes it out of its parent's auto layout. The plugin writes `layoutPositioning` ABSOLUTE, then the frame's `constraints`, `x` and `y`, in one operation before the frame's size, since Figma refuses FILL on an absolute layer. On 2026-10-22 a real file kept an absolute layer's place, size and constraints, threw `FILL cannot be set on absolute positioned auto-layout children` for it, left it out of a hugging parent's size, and scaled its width and stretched its height with its parent, in a variant and in an instance (P8). The typings say turning a layer absolute or back moves it, so a turn writes its constraints and place whatever they read. A layer the auto layout places goes back to `AUTO`. The kit check refuses an absolute frame that fills an axis. A parent that resizes in a run moves and resizes its absolute layers by their constraints when its resize runs, after the plan compared those layers. So when the plan writes a field that can resize a box, its direction, sizing, lengths, limits, padding, spacing or stroke, or one of a box above it, the box's absolute layers write their constraints, place and size whatever they read, and one Apply converges. A hugging box whose layers change size resizes too, which the plan does not track.
- A frame's or an icon's `rotation` turns it. On 2026-10-22 a real file kept a 16px icon's box in its auto layout slot at 180, with its `absoluteBoundingBox` and its row's size unchanged, while its `x` and `y` moved from 34 and 0 to 50 and 16 with the transform's origin, and came back at 0 (PR). So the plugin writes and matches a layer's `rotation` alone, never its `x` and `y`, and two rotations a whole turn apart match. Figma lays a turned layer out by its turned box: on the same day a 20 × 10 frame at -90 made its hugging row 10 × 20 (PQ), where CSS's `rotate` leaves the layout as it was. So the kit check takes a half turn on any layer and a quarter turn only on a layer with two equal fixed sides, as every icon has, and refuses every other turn and a turned absolute frame, which the plugin places by an `x` and `y` that a turn moves.
- A variant root sits in its component set, which has no auto layout, so it cannot fill. On 2026-10-22 a real file threw `FILL can only be set on children of auto-layout frames` for one. It also threw for hug on a frame without auto layout inside one, and for fill on a frame outside any auto layout. The kit check refuses a root that fills, and a frame or text that fills an axis its parent hugs, since Figma would shrink that layer to its smallest size.
- A box's `limits` set `minWidth`, `maxWidth`, `minHeight` and `maxHeight`, each a literal or a bound variable, and the plugin removes a limit the spec drops. On 2026-10-22 a real file kept `maxWidth` on a hugging frame and on a text, which wrapped at it, kept `minHeight` on a column root, and read a bound `maxWidth` as the variable's value. The kit check refuses a limit on an axis the box fixes, because Figma clamps the fixed length to the limit and the plan would resize the box on every run. CSS resolves a `width` against its own `min-width` and `max-width`, so such a limit belongs in the fixed length, and the build folds it in there.
- A bound shadow is written with the color its variable takes in the node, and matches only while it stores that color. Figma draws the color a binding stores. A new binding stores the variable's value, but an effect written again with the binding it already holds keeps the color written. On 2026-10-20, 28 focus rings bound to `ring` drew black where `ring` is gray.
- Each axis lists the recipe's default first, and the plugin keeps each set's variants in spec order. Figma makes the top-left variant the set's default, so an instance a designer places starts as the default Button.
- Figma keeps a variant property's values in an order of its own, which the plugin cannot change. A new value goes last, and moving the variants or renaming a value leaves it where it is, as a real file showed on 2026-10-20. A set the plugin creates lists its values in spec order. The test file's Button set gained xs and lg in a later run, so its size menu reads default, sm, xs, lg until the set is created again.
- The plugin draws each icon component from its markup with `createNodeFromSvg`. A run on a real file on 2026-10-20 showed that this returns a frame the size of the SVG, painted white and clipping, whose layers take their names from the elements' `id`s. The plugin moves the layers into the component, scales them to fit and centers them, and keeps a hash of the markup in shared plugin data, so a changed icon is drawn again. Each icon flattens to one vector named `glyph`, whose fill binds `foreground`, and the glyph scales with its component. The plugin sets an icon's size with `resize`, which applies the glyph's constraints, so an icon a designer scaled comes back to 16px with its glyph. Figma's reference pages say `resizeWithoutConstraints` leaves the children as they are, which would leave the glyph at the scaled size.
- An icon layer is an instance of an icon component, linked to the set's swap property, so a designer swaps the icon from the properties panel. The swap properties offer every icon in the library. The layer overrides its glyph's fill with the label's color, as a Fuse icon takes `currentColor`. Every glyph has the same name, so the override holds across a swap: on 2026-10-20 a destructive Button swapped from Plus to Star kept its glyph bound to `error`. The swap leaves the instance with explicit overrides of the icon's name and the glyph's fill, even after swapping back. Resetting the overrides of the nested icon through the Plugin API also drops the variant's color, and the glyph reverts to `foreground`.
- A set's BOOLEAN property shows or hides the frames that link their `visible` to it. The plugin adds a property the set lacks with `addComponentProperty`, gives one it holds the spec's default, and links each optional frame's `visible` to the property's id, as it links a label's characters to a TEXT property. On 2026-10-22 a real file returned the property's name and an id from the add, kept the link on a layer in each of two variants, and listed the property on an instance at its default (PB). Setting it false on the instance hid the layer and its 8px gap, so the hugging instance went from 102 to 24px wide. A property that starts false hides the variant's own layer too: a hugging component of two layers and a 4px gap went from 54 to 20px wide (PQ). The probe environment sets `figma.skipInvisibleInstanceChildren`, under which an instance's `children` leaves a hidden layer out. The plugin never sets it, so it runs with the typings' default, false, and an instance lists the hidden layer, which reads `visible` false. No plugin code walks into an instance a set's BOOLEAN property can hide a layer of: the snapshot export stops at each preview instance, and only an icon instance's glyph is read, which no property hides. The plan finds each property's id by its name, so the kit check refuses a set that gives two properties one name.
- A change line shows what the layer holds after `holds`, so the list Apply shows for a field that does not stick tells what Figma kept.
- The variant grids and the page layouts read sizes when their operations run. A plan that changes a component set therefore lays out its grid again. A plan that changes anything on a page places the page's sets in a row again and stacks its previews below them. The `Icons` page holds the library alone, which needs no layout.
- The plugin reads only the variable collections the kit names, and stops when two local collections share one of those names.
- Every node the plugin creates carries a key in shared plugin data under the `fuse` namespace. The plugin finds a node by its key first, so a designer can rename a layer. A node without a key matches by name once, and the plugin then writes the key onto it.
- A frame layer's layers match among that frame's children alone, so a key needs to be unique only among its siblings, and a designer can rename a nested layer too. A layer the spec moves to another frame is one delete in the old frame and one create in the new one, so the layer gets a new node id.
- The plugin stops when two nodes share a key, such as after a designer duplicates a variant. It never deletes a node without a key, and warns about one that sits among the kit's variants, layers, icons or preview instances. It deletes a keyed node the spec no longer lists.
- It edits the component set and its variants in place, so their node ids and component keys survive and instances in other files keep following them.
- A kit page carries a key too, such as `page/button`, and the plugin finds a page by its key alone, never by its name. A page a designer named `Button`, such as one imported from another file, stays theirs, and the plugin creates its own `Button` page beside it.
- The plugin loads every kit page before it reads one, as the manifest's `dynamic-page` access requires. It finds a set, a preview or the icon library by its key on any kit page. A node it finds on another kit page moves to the page the spec puts it on, and Plan lists the move as one line, such as `move Button to the Button page`. The move keeps the node, so its id, its variants' ids and its component key survive. It deletes a keyed node the spec no longer lists on any kit page.
- A run that moves a node takes two phases, because a node reads its variable modes through its page, and a ring color or a variant's size can differ between pages. Apply first creates the missing pages, deletes the stale keyed nodes and makes the moves. Then it plans the rest of the kit against the file as moved and applies it, so one Apply converges. Plan writes nothing, so it lists the first phase and ends with `plan the rest of the kit again once the 3 moves land`. Apply's change list holds both phases. A run without a move takes one phase.
- A kit page the spec no longer lists, such as `Fuse components` (`page/components`), where the kit sat before each component got a page, goes once the kit's nodes have left it. When it still holds a layer without a key, it stays, and the run warns. Figma refuses to remove the page it shows. On 2026-10-22 a real file threw `Removing this node is not allowed` for that page and removed it once another page showed. So before it deletes the page Figma shows, the plugin shows the first component page. After Apply, Figma shows the first component page.

### Comparing with the browser

`figma:compare` checks the kit against the real Fuse components. It renders every instance in the preview frames with its Fuse component in Chromium and compares the two pictures cell by cell.

1. Build Fuse when `packages/fuse/dist` is missing or older than its sources, with `pnpm --filter @elmeragroup/fuse build`. The comparison renders the components and loads `styles.css` and `themes.css` from that build, and it warns when the sources are newer.
2. Run the plugin and press Export snapshots. The plugin exports each instance in the preview frames of every kit page as a PNG at 2x, cut to its render bounds so that a focus ring outside the box is included. It records each instance's box and render bounds and the modes its preview frame resolves. Figma resolves a mode only for a collection the frame's layers bind or alias into, so the export adds each mode the frame or its page pins, such as the density a Badge preview pins though no Badge layer binds a density variable. The UI downloads the result as `fuse-kit-snapshots.json`. The export writes nothing to the file.
3. Run the comparison. pnpm runs the script in this package's directory, so pass an absolute path:

   ```sh
   pnpm --filter @elmeragroup/fuse-figma figma:compare ~/Downloads/fuse-kit-snapshots.json
   ```

   The report goes to `.cache/figma-compare/` in this package, or to the directory `--out` names. `--threshold` sets pixelmatch's threshold, 0.1 by default. The run needs Playwright's Chromium, which `pnpm --filter @elmeragroup/fuse-figma exec playwright install chromium` installs.

The browser renders one page per preview:

- The page stamps the preview's theme the way Fuse applies one: `data-theme` and `data-density` on `<html>`, and `data-theme-variant`, `data-theme-brand` and `data-theme-segment` on `<body>`. A brand mode maps to its brand by display name, and `Auto` density maps to the variant's default.
- It names the layers in the order `styles.css` declares them, then loads Tailwind's preflight in the `base` layer, Fuse's standalone `styles.css` and `themes.css`, and sets `font-sans text-foreground` on `<body>` as the docs layout does. Roboto comes from `@fontsource/roboto`, which serves Google's Roboto, the family Figma renders. Preflight loads before `styles.css`, as in a Tailwind-source host, because its `border: 0 solid` and Fuse's base border rule share the `base` layer and the later one wins. In the other order the outline Badge draws its border in the text color. The run checks every element in a cell that holds text, an input's value or placeholder included, and stops when a face that text uses has not loaded, so the text never falls back to a system font.
- `styles.css` holds only the classes Fuse's own source uses. A standalone-CSS host compiles the classes it passes to a component in its own Tailwind build, so a renderer names those classes in `hostClasses`. The run compiles them against `fuse.css` with the compiler the spec build uses, keeps only the rules that select them, and the page puts those rules in the `utilities` layer after `themes.css`, as the host's build would. Separator names its demo lengths this way, Skeleton its demo shapes, and Avatar its demo sizes.
- The run parses each variant key against the definitions in `components/kit-registry.ts`. Each cell is the element its definition's renderer builds from the Fuse build, rendered to static HTML. The page turns off animations and transitions, so a spinner stays at 0°.
- The page measures, forces and crops one element per cell: the one element in the slot whose `data-slot` is the definition's `slot`, at any depth. A radio renders inside its `RadioGroup`, so its root is not the slot's child.
- A root whose element carries no `data-slot`, as React Aria's Link and Calendar day cell render, names the element in the definition's `element`, a tag and the attributes the element carries, each with a value or `true` for any value. The page measures the one element in the slot that selector matches, such as `a[data-rac]`, and `slot` names only the root layer. Fuse gets no `data-slot` for the kit's sake, since a new one changes the DOM its consumers render.
- The page forces `:hover` for `state=hover`, and `:focus` and `:focus-visible` for `state=focus`, through the Chrome DevTools Protocol. It compares the styles of each forced element and its descendants with the same cell at `state=rest`. When forcing changed nothing, it hovers or focuses that element for real before the screenshot.

The Button renderer, `compare/button-cell.ts`, renders both Button sets. `icon=start` adds `<Plus data-icon="inline-start" />` and `icon=end` adds `<ArrowRight data-icon="inline-end" />`. An icon button holds `<Plus />` and has an `aria-label`. Disabled sets `disabled` and pending sets `isPending`.

The Confirm button renderer, `compare/confirm-button-cell.ts`, renders `<ConfirmButton variant size>Delete</ConfirmButton>`, and disabled sets `disabled`. ConfirmButton arms only on a press, which static markup cannot make, and it writes its own `data-armed` after the props it passes to Button. So an `armed=on` cell passes `render={<button data-armed="true" />}`, whose props Base UI merges over its own. The root then carries `data-armed="true"` as a first press leaves it, and every other attribute stays as at rest, since the cell gives no armed label or `aria-label`. A disabled cell renders disarmed, as ConfirmButton does.

The Toggle renderer, `compare/toggle-cell.ts`, renders both Toggle sets. `pressed=on` sets `defaultPressed` and disabled sets `disabled`. `icon=start` and `icon=end` add a `<Star>` marked `inline-start` or `inline-end`. An icon toggle holds `<Star data-icon="inline-start" />` and has an `aria-label`.

The Badge renderer, `compare/badge-cell.ts`, renders `<Badge variant size>Badge</Badge>`.

The Kbd renderer, `compare/kbd-cell.ts`, renders `<Kbd>K</Kbd>` for `content=text` and `<Kbd><Backspace /></Kbd>` for `content=icon`.

The Radio icon button renderer, `compare/radio-icon-button-cell.ts`, renders `<RadioIconButton value="list" aria-label="List"><List /></RadioIconButton>` alone in a `<RadioGroup>`. `checked=on` sets the group's `defaultValue` to `list`, disabled sets the button's `isDisabled`, and invalid sets the group's `isInvalid`. `RadioGroup` renders its own `Field.Root`, so an invalid `Field.Root` around the group does not reach the radio.

The Radio renderer, `compare/radio-cell.ts`, renders `<RadioGroupItem value="a" aria-label="Option" />` alone in a `<RadioGroup>`. `checked=on` sets the group's `defaultValue` to `a`, disabled sets the item's `disabled`, and invalid sets the group's `isInvalid`, as for Radio icon button.

The Checkbox renderer, `compare/checkbox-cell.ts`, renders `<Checkbox aria-label="Accept" />`. `checked=on` sets `defaultChecked`, `checked=mixed` sets `indeterminate`, and disabled sets `disabled`. Invalid wraps the checkbox in `<Field.Root invalid>`, which marks it `aria-invalid="true"` and `data-invalid`.

The Switch renderer, `compare/switch-cell.ts`, renders `<Switch aria-label="Notifications" />`. `size` sets `size`, `checked=on` sets `defaultChecked`, and disabled sets `disabled`. Invalid wraps the switch in `<Field.Root invalid>`, as for Checkbox. The page turns transitions off, so the thumb sits at its final place.

The Separator renderer, `compare/separator-cell.ts`, renders `<Separator orientation className="data-horizontal:w-64 data-vertical:h-4 data-vertical:self-auto" />`, with the lengths `separator-kit.ts` merges. Fuse's `styles.css` compiles none of those three classes, so the renderer names them as host classes, and the browser draws the lines 256 × 1 and 1 × 16.

The Skeleton renderer, `compare/skeleton-cell.ts`, renders `<Skeleton className="h-4 w-48" />` for a line and `<Skeleton className="size-10 rounded-full" />` for a circle, with the shapes `skeleton-kit.ts` merges. Fuse's `styles.css` lacks `w-48`, so the renderer names every shape class as a host class, and the browser draws a 192 × 16 line and a 40 × 40 circle. The page turns animations off, so no pulse runs and the block draws at full opacity, as the kit does.

The Loader renderer, `compare/loader-cell.ts`, renders `<Loader size aria-label="Loading" />`, as the docs demos label it. The label fills the visually hidden span, so the markup holds no client child. The page turns animations off, so the spinner sits at 0°, as the kit draws it.

The Label renderer, `compare/label-cell.ts`, renders `<Field.Root disabled><Field.Label>Email</Field.Label></Field.Root>`, with `disabled` set only on the disabled cell. The page measures the label, the one element with `data-slot="field-label"`. A disabled root marks itself and the label `data-disabled`.

The Input renderer, `compare/input-cell.ts`, renders `<Input>` in a `<div>` 384px wide, the preview width `field-box-kit.ts` gives Input and Textarea, since the page's slot gives the input's `w-full` no width to take. `content=placeholder` sets `placeholder`, and `content=value` sets `defaultValue`, which the markup holds as `value`, both to `name@example.com`. Read-only sets `readOnly`, and disabled sets `disabled`, which Base UI marks `data-disabled` too. Invalid wraps the input in `<Field.Root invalid>`, as for Checkbox, which marks it `aria-invalid="true"` and `data-invalid` and passes the root's `error` text color down. Each slot on the page is 400px wide, so the box fits with the crop's 8px padding on both sides and its ring stays clear of the next slot.

The Textarea renderer, `compare/textarea-cell.ts`, renders `<Field.Control render={<Textarea />}>` inside a `<Field.Root>`, as the docs' Field demo does, in a `<div>` 384px wide, as for Input. A plain `<textarea>` carries no `data-disabled` or `data-invalid`, while Base UI stamps both on a Field control. `Field.Control` marks its element `data-slot="field-control"`, so the renderer passes the textarea's own `data-slot="textarea"` back through it. No Fuse style reads either slot. `content=placeholder` sets `placeholder`, and `content=value` sets `defaultValue`, which the markup holds as the textarea's own text, both to `Tell us more…`. Read-only sets `readOnly`, and disabled sets the control's `disabled`, which Base UI marks `data-disabled` too. The root stays enabled there, since the kit draws no disabled Field around the textarea. Invalid sets the root's `invalid`, which marks the textarea `aria-invalid="true"` and `data-invalid` and passes the root's `error` text color down. Preflight sets `textarea { resize: vertical }` and Fuse's Textarea keeps it, so Chromium draws a resize grip in the bottom-right corner of a Textarea cell. The kit draws no grip.

The Avatar renderer, `compare/avatar-cell.ts`, renders `<Avatar.Root className={size}>` with the size class `avatar-kit.ts` merges, and names the four size classes as host classes. A fallback cell holds `<Avatar.Fallback>AL</Avatar.Fallback>`. An image cell holds `<Avatar.Image keepMounted src={portrait} alt="" />` and no fallback, since Base UI's static markup holds no `<img>` without `keepMounted`, and a fallback beside it would put two filling parts in the circle. The `src` is `components/avatar-portrait.png` as a data URI, so the page needs no route for it and draws the pixels Figma draws, and the page's load waits for it to decode.

The Meter renderer, `compare/meter-cell.ts`, renders `<Meter label="Storage used" mode value maxValue valueLabel />` with the docs Modes demo's value for the cell's level, in a `<div>` 256px wide, the preview width `meter-kit.ts` gives Meter, which the block-level root fills. Meter reads its locale from `LocaleProvider`, which throws without one, so the cell renders inside `<LocaleProvider locale="en-US">`, the locale the docs set. `valueLabel` holds the cell's text, such as `85%`, so the value is plain text after the icon and its space, where `Meter.Value` would wrap it in a span of its own. Base UI adds a visually hidden `<span role="presentation">` to the root, which the page draws nothing for.

To compare a new component set:

1. Add its definition and preview cells to `KIT` in `components/kit-registry.ts`. Name an interactive axis `state`, with `rest` among its values, so the page can force hover and focus and find the resting twin. A set with no state, such as Badge, leaves the axis out, and the page forces nothing on its cells.
2. Add a renderer module beside `compare/button-cell.ts`. It exports a `CellRendering` whose `element(cell)` returns the real Fuse element for a parsed cell. Set the states the markup draws, such as disabled, pressed or checked, through props. Name in `hostClasses` any class the cells pass that Fuse's own source does not use, such as a docs demo's length.
3. List the module in `compare/cell-renderers.ts` with the definition's key and the `dist/` entry the module imports. The run checks that the entry exists before it loads the module.
4. Add a markup test beside the renderer whose oracle is the component's public contract, as `compare/button-cell.test.ts` does. `compare/kit-markup.test.ts` checks that every definition has a renderer, and checks the definition against the renderer's markup for every preview cell: the cell renders one measured element, each attribute variant, such as `disabled:` or `aria-pressed:`, holds exactly where the measured element carries the attribute, each attribute variant a part's own classes name holds exactly where that part's element carries it, as Switch's thumb carries `data-checked` and `data-unchecked`, the parts the cell shows match the measured element's descendants, and the `iconsFor` of the root and of each part the cell renders list the measured element's `<svg>` descendants in order. Each icon sits under the part that lists it, its nearest ancestor that is the root or a part, as a child of that part or nested deeper, with its `data-icon`. An icon slot that names classes of its own, as Loader's spinner does, must name the `<svg>`'s `class` attribute exactly. A part with a `data-slot` matches the element that carries it, below its parent part's element. A part with none, such as Radio's dot or Meter's header, matches by place, as the one child element of its parent part beside the parts with a `data-slot` and Base UI's visually hidden `<span role="presentation">`, which is no `<svg>` and carries no `data-slot`. A part with no `data-slot` can name its element in `element` instead, as a root does, and matches the element below its parent part's element that the selector matches. A part with a `styleFor` must carry exactly those declarations in its `style` attribute, in order, and a part without one no `style`, so the fill widths Figma draws are the ones Base UI writes. A group variant holds exactly where an ancestor of the measured element matches it, as `group-data-disabled/field:` holds below a Field root that carries `data-disabled`. The root and each part hold their label's characters where the cell shows the label, as their own text, after a space where the label's `leadingSpace` says so. In a cell where the label's `textAttribute` names an attribute, they hold them there and no text of their own, as an `<input>` holds its placeholder in `placeholder` and its value in `value`. A `<textarea>` holds its placeholder in `placeholder` and its value as its own text. Attribute values read with React's entities decoded, as text does. A box that shows an image is an `<img>` whose `src` is a data URI of the image's bytes, and a box that shows none carries no `src`. It fails when a definition's facts, states or recipe conditions name an attribute or group variant its lists lack, so add a new one, such as `data-checked:`, with the attribute it selects. `placeholder:` holds where the element has a placeholder and no value, in `value` or, on a `<textarea>`, as its own text.

`report.html` opens from disk. It starts with a summary per preview and then lists every cell worst first. Each cell shows three pictures: Figma's export, the browser's crop, and the diff, which marks differing pixels red and anti-aliasing yellow. Figma's export and the browser's crop sit over the theme's background with the boxes' top-left corners aligned. Filters select a preview, a value of each variant axis, or only the flagged cells. `report.json` holds the same rows.

- Check box sizes first. Δ is Figma's box minus the browser's, in pixels. The `size` flag marks a side that differs by half a pixel or more, and such a cell goes to the top. `subpixel-size` marks a smaller difference, beyond Chromium's 1/64 px layout rounding.
- Mismatch is the percentage of the browser box's area, at 2x, whose pixels differ. The tolerant count leaves out the pixels that pixelmatch takes for anti-aliasing, and the raw count includes them. Figma and Chromium draw text differently, so a matching cell still shows some mismatch along the label. Mismatch away from text and edges points at a real difference.
- A Textarea cell differs in its bottom-right corner, where Chromium draws a resize grip and the kit draws none. That mismatch is expected.
- `png-size` marks an export whose size differs from its render bounds. `state-by-interaction` marks a cell that needed a real hover or focus. `state-missing` marks a cell whose state the browser could not show, so its browser picture is wrong. `no-figma-image` marks an instance Figma drew nothing for.
- A hover or focus cell whose built variant equals its resting twin's is unchanged by design, such as a pressed Toggle on hover, which `aria-pressed:` and `enabled-hover:` paint with the same `muted`. When the browser shows no change for it either, the cell gets no `state-missing` flag, and the report notes it as unchanged by design. The run builds the component sets with `buildComponentSets()` in its own process, so the expectation follows the recipes the browser renders.
- The report lists an instance it cannot render as skipped, such as one whose variant has an axis the comparison does not know.

The first comparison of the test file, on 2026-10-20, covered 756 cells in the 12 previews:

- Every height matched, and every Icon button matched to the pixel apart from anti-aliasing.
- Every Button was wider in Figma, by less than a pixel: 0.41px at 12px type, 0.47px at 14px and 0.61px at 18px. Figma rounds an auto-width text layer up to a whole pixel. Its Roboto matches the browser's, so three labels in a row are 125px wide in Figma and 124.59px in Chromium. The rounding moves the right edge and nothing else. The worst cell differs by 2% of its pixels, all of it that edge and text anti-aliasing.
- A fixed label width could match the fraction, but then the label would not grow when a designer edits it, so the kit keeps auto width.

`figma:compare --self-check` tests the comparison itself. It renders every cell of the kit's preview frames in each of two themes and saves them as a fake snapshot whose render bounds reach 3 pixels past each box. It paints a square into the kit's first hover cell and widens the box of its first focus cell by a pixel, in registry order, and then it compares the snapshot with a second render. It passes when those two cells lead the report and every other cell matches exactly.

The tests run the whole command line against `test/in-memory-figma.ts`. That fake file applies batches with the REST API's documented rules, stores numbers as 32-bit floats and resolves aliases the way Figma renders them. Where the documentation is silent, the fake does what a real Enterprise file did on 2026-10-16. It replaces code syntax on an update, it checks for an alias cycle after each value a batch sets, and it refuses any cycle, even one that closes only across modes. It deletes a collection with its modes and variables and keeps an alias into it until a later value in the batch replaces it, as a real Enterprise file did on 2026-10-19 when one batch deleted `Fuse themes` and then rewrote the `Fuse tokens` aliases into it. It also applies the scope rules on the REST API's [variable types page](https://developers.figma.com/docs/rest-api/variables-types/). It rejects a scope the page does not list for the variable's type, such as `GAP` on a color, `ALL_SCOPES` beside another scope, and `ALL_FILLS` beside another fill scope. It follows a real Enterprise file where that file departed from the page on 2026-10-16. It keeps `FONT_STYLE` on a number variable and stores `FONT_WEIGHT` there as `FONT_STYLE`. It stores a description with `&`, `<`, `>`, `"` and `'` HTML-escaped, as a real Enterprise file did on 2026-10-19. Tests can also make it answer with a status, drop a connection, or hold values and types newer than the sync.
