# @elmeragroup/fuse-figma

Syncs the Fuse design tokens into a Figma file's local variables. The repository is the master for theming data, so the sync writes code into Figma and never reads design decisions back. It is a private workspace package with no build step. Node runs the TypeScript directly.

It also builds the Fuse components plugin, a proof of concept that creates the Button, Confirm button, Toggle, Badge, Kbd, Kbd group, Radio icon button, Radio, Radio row, Radio group, Checkbox, Switch, Separator, Skeleton, Loader, Label, Field description, Field error, Field legend, Field title, Input, Input group, Text field, Textarea, Textarea field, Avatar, Avatar group, Meter, Pagination link, Pagination edge, Pagination ellipsis, Pagination row, Breadcrumb link, Breadcrumb page, Breadcrumb ellipsis, Breadcrumb separator, Breadcrumb trail, Select trigger, Select field, Menu group label, Menu separator, Select item, Select popup, Select (open), Popover content, Popover (open), Dropdown menu item, Dropdown menu checkbox item, Dropdown menu radio item, Dropdown menu sub trigger, Dropdown menu popup, Dropdown menu sub content, Dropdown menu (open), Combobox item, Combobox empty, Combobox popup, Combobox (open), Command item, Command list, Empty, Calendar day, Link, Item, Item link, Alert, Accordion item, Sidebar menu button, Sidebar menu sub button, Sidebar group label, Sidebar menu badge, Sidebar group, Sidebar header, Sidebar footer, Sidebar sub menu, Sidebar menu item with badge, Sidebar, Navigation menu bar trigger, Navigation menu vertical trigger, Navigation menu bar link, Navigation menu row link, Navigation menu popup, Number field stepper, Number field and File upload dropzone component sets from their recipes and an icon library from Fuse's icons. [Components plugin](#components-plugin) describes it.

## What lands in Figma

The sync owns six variable collections, matched by name.

| Collection        | Modes                          | Variables                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Fuse tokens`     | `Light`, `Dark`                | 159 variables. Designers bind one per contract token such as `primary` or `radius`, one per radius rung such as `radius-md`, one per role tint such as `error/10`, and one per formula over tokens such as `radius-compact`. Three more per formula over tokens and density metrics, such as `radius-inner/lg-pad-sm/dense`, are hidden from pickers. |
| `Fuse variant`    | `Internal`, `External`         | 360 variables: `<scheme>/<token>` for each `Fuse tokens` variable, and `density/<metric>` for each density metric and each formula over metrics alone. Hidden from pickers.                                                                                                                                                                           |
| `Fuse segment`    | `Private`, `Company`           | 632 variables, `<scheme>/<variant>/<token>` for each `Fuse tokens` variable. Hidden from pickers.                                                                                                                                                                                                                                                     |
| `Fuse brand`      | One per brand, 7               | 1264 variables, `<scheme>/<variant>/<segment>/<token>` for each `Fuse tokens` variable. They hold the theme values. Hidden from pickers.                                                                                                                                                                                                              |
| `Fuse primitives` | `Value`                        | 25 variables, the neutral ramp and the brand accents. They hold the same value in every theme. The neutral ramp is hidden from pickers, and the brand accents stay bindable.                                                                                                                                                                          |
| `Fuse density`    | `Auto`, `Dense`, `Comfortable` | 53 variables, one per density metric: control (`control-h-md`), row (`row-h`), surface (`surface-pad-lg`, `surface-gap-md`) and label (`label-text`), and one per formula over metrics, such as `empty-pad-desktop`, or over tokens and metrics, such as `radius-inner/lg-pad-sm`. Designers bind these.                                              |

Each theme axis is one collection, so a designer previews a theme by picking each axis in the frame's Appearance panel, as in the docs theme picker. `Fuse tokens` gets `Light` or `Dark`, `Fuse variant` gets `Internal` or `External`, `Fuse segment` gets `Private` or `Company`, and `Fuse brand` gets the brand, such as `Fjordkraft`. A frame that sets no mode for a collection gets its first mode, so an unset frame shows internal Fjordkraft private in light. Figma resolves an alias that crosses into another collection with the frame's mode for the target collection, inherited from any ancestor. A child frame can therefore change one axis and keep the others.

Every `Fuse tokens` variable takes the same four hops. `primary` in `Light` aliases `light/primary` in `Fuse variant`, which aliases `light/external/primary` in `Fuse segment` under `External`, which aliases `light/external/company/primary` in `Fuse brand` under `Company`. That variable holds each brand's value for the external company theme. The path segments are the lowercase code values, so the hidden variables keep their names whichever axes a token varies on.

A brand mode is the brand's display name. Telinet allows only the private segment and Fjordkraft Företag only the company segment, so their modes read `Telinet (private only)` and `Fjordkraft Företag (company only)`. Figma cannot disable a mode, so such a brand holds its only segment's values under the other segment too: Telinet in `Company` shows Telinet private. The docs picker moves the segment instead.

`Fuse density` defaults to `Auto` in a file the sync creates. `Auto` aliases `density/<metric>` in `Fuse variant`, which holds the metric in the variant's default density, so a frame follows its variant the way apps do: internal themes dense and external themes comfortable. `Dense` and `Comfortable` hold their own pixels for frames that pin a density.

A file synced before `Auto` existed already has `Dense` and `Comfortable`. The REST API appends a new mode and cannot reorder modes or change the default, so `Auto` lands last there and `Dense` stays the default. Figma's default mode is the left-most column of the variables view, so move the `Auto` column all the way to the left, by dragging its header or through the header's right-click menu, to make it the default.

Earlier syncs wrote a `Fuse themes` collection with one mode per theme slug, such as `external-fkas-private`. The sync deletes a local collection with that name, and `check` reports it as drift. Frames pinned to a `Fuse themes` mode lose that pin, and designers set the four axis modes instead. The sync never deletes a library collection or a collection extension with that name.

The token values come from `resolveThemeCatalog` in `@elmeragroup/fuse/theme-catalog`. It resolves every theme in both schemes from `composeTheme`, the same composition that generates `themes.css`, and hands the sync each value already read: an sRGB color, a length in pixels, a font family or a font weight, plus the one `var()` hop when the value is a reference. The catalog throws on a token value it cannot read, because token values are Fuse source, and a Fuse test resolves every theme and scheme so CI catches such a value first. The sync maps the resolved values as follows.

- A color becomes an sRGB color, with alpha kept and the channels unrounded. The tokens write `oklch()` or `#rrggbb` literals, and the catalog reads exactly those two forms through `@elmeragroup/color`, which clips a color outside the sRGB gamut.
- `var(--name)` becomes an alias to the matching variable. A role reference points at the role with the same scheme, variant and segment in `Fuse brand`, and a primitive reference points into `Fuse primitives`.
- A `rem` length becomes the catalog's pixels at a 16px root.
- A radius rung becomes the pixels `fuse.css` computes for it, such as `--radius-md: calc(var(--radius) - var(--radius-step, 0px))`, because Figma variables cannot compute. The catalog computes each rung per theme from the theme's `radius` and `radius-step` and the rung's step count, and the sync writes those pixels per brand mode. Internal themes step 0px, so every rung equals `radius`. External themes step 2px, so `external-fkas-private` with a 12px radius gets 6, 8, 10, 12 and 16px from `radius-xs` to `radius-xl`. CSS clamps a negative `border-radius` to 0, and so does the catalog. The sync leaves out `radius-popover`, because no component uses that rung and Fuse popups use `radius-md`.
- A density metric comes from the catalog in pixels per density, read from the same metrics the `fuse.css` density blocks must equal. Heights, including `row-h`, get the width and height picker. Paddings, including the `row-px`, `row-py` and `surface-pad-*` paddings, and gaps, including the `surface-gap-*` tiers, get the gap picker. The type pairs, `control-text` and `control-leading` for controls and `label-text` and `label-leading` for labels such as selection row text, get the font size and line height pickers.
- A font stack becomes its first family name, which the catalog reads.
- A font weight, such as `selection-title-weight`, becomes its number, from 1 to 1000, and gets the font weight picker. The sync sends that picker as `FONT_STYLE`. Figma's REST documentation lists `FONT_WEIGHT` for number variables, but a real file stores `FONT_WEIGHT` as `FONT_STYLE`, so a sync that sent it would never read back what it wrote.
- A derived role, such as `secondary-hover`, becomes the literal color that composition computes, because Figma variables cannot mix colors.
- A role tint, such as `error/10`, holds its role's color at the tint's alpha in every theme. A Figma paint takes its opacity from the alpha of the variable it binds, so a component cannot bind `error` at 10%, and `bg-error/10` binds `error/10` instead. The tint's code syntax is the `color-mix(in oklab, var(--error) 10%, transparent)` that Tailwind compiles the utility to. `ROLE_TINTS` in `fuse-variable-set.ts` lists the tints the component kit binds. A tint appears in its role's pickers, and its description names the role and the percent, since the catalog has no entry for it.
- A formula variable holds what a recipe's formula over theme tokens or density metrics gives. Figma variables cannot compute, so `FORMULA_VARIABLES` in `fuse-variable-set.ts` computes each one, and its code syntax is the formula as Tailwind compiles the recipe's class, which the kit binds. The kit's builder reads Tailwind's own theme variables as their values, so the code syntax writes `var(--spacing)` as `0.25rem` and `var(--leading-snug)` as `1.375`.
  - What a formula reads decides where it lands. A formula over tokens alone lands in `Fuse tokens` with a value for each theme. A formula over metrics alone lands in `Fuse density` as a metric does: `Dense` and `Comfortable` hold its pixels, and `Auto` reads `density/<name>` in `Fuse variant`. A formula over tokens and metrics lands in `Fuse density` too, but each of its modes aliases a hidden `Fuse tokens` variable, `<name>/auto`, `<name>/dense` or `<name>/comfortable`. That variable takes the four hops of every `Fuse tokens` variable and holds what the formula gives for each theme at its density, and `auto` holds each theme at its variant's default density. Figma resolves each hop with the frame's mode for that collection, so one bound variable follows both the frame's theme and its density. A formula that reads a metric lands in `Fuse density` even when the metric holds one value at both densities, so a later density change cannot move its variable to another collection, which would unbind the layers that use it.
  - The outline Button's shadow lengths, `button-outline-shadow-blur` and `button-outline-shadow-spread`, hold what `max(0px, 4px - 2 * var(--button-outline-width, 1px))` and `min(0px, 2px - 2 * var(--button-outline-width, 1px))` give for each theme's outline width: blur 2 and spread 0 at the internal 1px outline, which is Tailwind's `shadow-xs`, and blur 0 and spread -2 at the external 2px outline, which paints nothing outside the border. They get the effect picker.
  - The compact corner, `radius-compact`, holds what `compactCornerClass` in `corner-radius.ts` gives, `min(radius-md, max(10px, radius - 1000 * radius-step))`. Internal themes step 0px, so it equals `radius`, 8px for Fjordkraft. External themes step 2px, so it is `radius - 2px` capped at 10px: 4px for Elmera's 6px radius and 10px for TrøndelagKraft's 16px. The xs Toggle rounds with it, and it gets the corner radius picker.
  - The checkbox corner, `radius-checkbox`, holds what `checkboxCornerClass` in `corner-radius.ts` gives, `min(radius-md, 4px)`. Every theme's `radius-md` is at least 4px, so it holds 4px in each. The Checkbox box rounds with it, and it gets the corner radius picker.
  - The field box corner, `radius-field-box`, holds what `fieldCornerClass` in `corner-radius.ts` gives, `clamp(radius - 1000 * radius-step, radius-field, radius + 1000 * radius-step)`. Internal themes step 0px, so both bounds equal `radius` and it holds `radius`, 8px for Fjordkraft. External themes step 2px, so the bounds lie 4000px apart and it holds `radius-field`. Every theme sets `radius-field` to `var(--radius)`, so that is 6px for Elmera and 16px for TrøndelagKraft. Fuse rounds Input, Textarea and the other field boxes with that class, and the variable gets the corner radius picker.
  - An inner corner is the `--shell-inner` that a shell in `inner-corner/` publishes and `rounded-inner` reads, `max(0px, rung - border - padding)`. Shells of several components compile to the same formula, and the kit binds by code syntax, so each corner is named for its shell's rung, border and padding. `radius-inner/lg-pad-8px` reads tokens alone: a floating Sidebar's group in the icon rail pads 8px inside `radius-lg`, which leaves 0 in internal themes, 4px for Fjordkraft's external 12px radius and 8px for TrøndelagKraft's 16px. The others read `surface-pad-md`, `surface-pad-sm`, `surface-gap-sm` or `control-px-icon-md` too: `radius-inner/sm-pad-md` inside a default Accordion item, `radius-inner/lg-pad-md` inside a Toast or an Accordion item with the lg radius, `radius-inner/xl-pad-md` inside an Accordion item with the xl radius, `radius-inner/lg-border-pad-md` inside a card Accordion item or a SelectionItem, `radius-inner/xl-border-pad-md` inside a card Accordion item with the xl radius, `radius-inner/lg-pad-sm` inside a floating Sidebar's header, footer or group, or a Select group, `radius-inner/md-pad-sm` inside a DropdownMenu popup or a Combobox list, `radius-inner/xl-gap-sm` inside a Command list, and `radius-inner/field-border-pad-addon-button` on a button in an Input group addon. `radius-inner/md-pad-sm` is 4px in internal themes, 6px for Fjordkraft's external theme and 10px for TrøndelagKraft's at both densities, as Fuse's concentric-corners browser test measures a dropdown row. TrøndelagKraft's external theme gives `radius-inner/xl-border-pad-md` 7px dense and 3px comfortable. They get the corner radius picker.
  - Empty's desktop padding, `empty-pad-desktop`, is twice `surface-pad-lg`, 32px dense and 48px comfortable. The space above an open Accordion panel's text, `accordion-panel-pt`, is `surface-gap-lg` plus 6px, 22px and 30px. Both get the gap picker. One snug line of label text, `label-line-snug`, is `label-text` times 1.375, 19.25px and 22px, which is how tall an Alert's icon box is beside a description. It gets the width and height picker. A menu row's room for its 16px indicator and the 8px gap beside it, `row-indicator-room`, is `row-px` plus 24px, 32px dense and 36px comfortable, and gets the gap picker. The end padding of a row with a trailing indicator and the start padding of an inset row compile to that one formula, and the kit binds by code syntax, so both bind it. An Input group addon that holds a button pads its outer side by `addon-px-button`, `control-px-icon-md` less the 4px its negative margin takes back, 4px dense and 8px comfortable, with the gap picker. The kit folds the margin into that padding and binds the variable whose formula is the same sum of variables and pixels. The button rounds with `radius-inner/field-border-pad-addon-button`, the field box corner less its 1px border and that padding. Item's own media line reads `text-sm` and `leading-snug`, two Tailwind theme values every theme shares, so the kit's builder reads it as a literal 19.25px and the sync holds no variable for it.
- The variables designers bind in `Fuse tokens`, `Fuse primitives` and `Fuse density` carry web code syntax. A token, primitive or metric carries its `var()`, such as `var(--primary)`. A radius rung carries the `calc()` that `fuse.css` declares, such as `calc(var(--radius) - 3 * var(--radius-step, 0px))`. `fuse.css` declares the rungs in `@theme inline`, so Tailwind inlines them into its utilities, and the built CSS declares no `--radius-sm` property. A test requires every `var()` in the code syntax to name a property that the built `styles.css` or `themes.css` declares.
- A color appears only in the pickers for where Fuse paints it. The catalog gives each color role and primitive its paints from `TOKEN_PAINTS` and `PRIMITIVE_PAINTS` in `@elmeragroup/fuse`, and a source contract holds the library's own color classes to them. A `surface` gets the frame and shape fill pickers, an `ink` gets the text fill, shape fill and stroke pickers, because icons take the text color, and a `line` gets the stroke picker. A role with every fill gets `ALL_FILLS`. `feature-foreground` is a surface only, so the text fill picker leaves it out.
- The neutral ramp gets no picker scope. It holds one value in every theme and scheme, so a layer bound to it breaks dark mode and brand switching. It stays an alias target, as the hidden collections do. The brand accents keep the fill pickers and their foregrounds the text pickers, for artwork that shows several brands.
- Font families get the font family picker. Figma's REST documentation says scopes currently apply only to FLOAT and COLOR variables, but a real file keeps `FONT_FAMILY` on a STRING variable.
- Each length token names its picker scope in a table in `fuse-variable-set.ts`, so a new length token does not compile until someone picks one. `radius`, `radius-button`, `radius-field` and the radius rungs get the corner radius picker, `button-outline-width` gets the stroke picker, the paragraph line heights, `paragraph-leading-sm`, `paragraph-leading-base` and `paragraph-leading-lg`, and the heading line heights, `heading-1-leading` to `heading-3-leading`, get the line height picker, and the heading sizes, `heading-1-size` to `heading-3-size`, get the font size picker.
- `radius-step` gets no picker scope. It is a length, but it spaces the radius rungs and switches between the internal and external variants, so no layer rounds with it. It keeps its code syntax, `var(--radius-step)`.
- Every variable designers bind in `Fuse tokens`, `Fuse primitives` and `Fuse density` carries the catalog's description, which Figma shows when a designer hovers the variable. The descriptions live beside the tokens in `@elmeragroup/fuse`, and the docs tokens page shows the same text. The hidden variables carry an empty description. A real file stored `&`, `<`, `>`, `"` and `'` in a description HTML-escaped on 2026-10-19, through the REST API and the Plugin API alike, so the sync refuses a description that holds one of them.

## Running it

The Variables REST API needs an Enterprise plan. Create a personal access token under Settings → Security in Figma. The token needs the `file_variables:read` and `file_variables:write` scopes and belongs to a Full seat with edit access to the target file. Figma caps these tokens at 90 days, and a plan access token cannot write variables.

Copy `packages/fuse-figma/.env.example` to `packages/fuse-figma/.env`, which git ignores, and fill in the token and the file key:

```sh
FIGMA_TOKEN=figd_...
FIGMA_FILE_KEY=AbCdEf123   # the part after /design/ in the file URL
```

Then run one of these commands from the repository root:

```sh
pnpm --filter @elmeragroup/fuse-figma figma:check   # print the plan, write nothing, exit 2 when Figma differs
pnpm --filter @elmeragroup/fuse-figma figma:sync    # apply the plan
```

`--file-key <key>` overrides `FIGMA_FILE_KEY`, and a branch key targets a Figma branch. `figma --help` lists every flag.

`check` exits 2 when the file differs from the tokens and 1 when it cannot run, for example when the token has expired, so a CI job can tell the two apart. It groups the plan by collection and kind of change. A group of up to 10 changes lists each variable and mode, and a larger group prints its count.

The token travels in the `X-Figma-Token` header. The sync masks that header on the trace spans Effect's HTTP client records, and a failed request keeps only its method and URL.

After a sync, publish the library in Figma. The REST API cannot publish, so consuming files see the new values only after someone publishes by hand.

## How a sync decides what to write

The sync reads the file, plans one change batch and sends it. Figma applies a batch completely or rejects all of it. The sync then reads the file again and fails unless the plan is now empty, so a successful run means the file was checked.

- It matches collections, modes and variables by name and updates them in place. Ids survive, so every layer bound to a Fuse variable stays bound.
- A mode keeps its id only while the tokens keep its name. The sync deletes a mode the tokens no longer name and creates the modes they add, and it never renames one into another, because a dropped brand and an added one are unrelated. Frames pinned to a deleted mode lose that pin. Renaming a brand's display name in code is therefore a delete and a create in Figma, and designers repin the frames that used the old name.
- Mode order does not matter to the plan. A collection whose modes the file holds in another order than the tokens counts as in sync, because the REST API cannot reorder them.
- The sync orders mode changes so that no collection goes over Figma's 40 modes or runs out of modes while the batch applies. It deletes the stale modes before creating new ones. When no existing mode survives, it keeps the last stale mode until the first new mode exists. The only mode it renames is the one Figma gives a new collection, which becomes the collection's first mode.
- Inside the six Fuse collections, the tokens are authoritative. The sync deletes any mode or variable the tokens do not define, and the next sync resets any value a designer edited.
- It never touches another collection in the file, except that it deletes a local collection named `Fuse themes`, which earlier syncs wrote. The sync skips library collections, collection extensions and deleted variables that layers still reference, even when their names match.
- It refuses to change a variable's type, because Figma can only do that by deleting the variable and unbinding every layer that uses it. The error names the variable to delete by hand.
- Renaming a token in code is a delete and a create in Figma, so layers bound to the old name lose their binding.
- It refuses to sync tokens whose aliases form a cycle. A cycle counts even when each alias closes it in a different mode, because the modes a layer combines decide whether Figma would loop.
- It writes the values of each alias target before the values that alias it. Figma applies values in order and refuses a batch that passes through a cycle after any one value, even when the batch ends without one. This order never passes through a cycle, even when the tokens reverse an alias.
- A value shape or variable type newer than the sync does not stop a read. A variable the sync owns gets such a value rewritten, and a type it does not know is a type conflict.
- It owns every variable's description, so the next sync resets a description a designer wrote. It sets web code syntax on the variables designers bind in `Fuse tokens`, `Fuse primitives` and `Fuse density`, and sends no code syntax for the hidden values in `Fuse tokens` or for the `Fuse variant`, `Fuse segment` and `Fuse brand` variables, which only feed aliases. An update replaces a variable's code syntax, so when the sync sets the web entry, it sends the file's Android and iOS entries with it.
- The sync retries a read that hits a rate limit, a server error or a network failure. It waits as long as `Retry-After` asks and logs a warning for each retry. It retries a write only after a 429, because a write that failed on the server may still have been applied. When `Retry-After` asks for more than 60 seconds, the sync fails at once and reports the wait.

The alternative was kumo-figma's approach, which deletes every variable and recreates it on each run. That gives every variable a new id and breaks the bindings in existing designs.

### How the spec is built

The build calls each recipe from the workspace-only `@elmeragroup/fuse/recipe-catalog` entry for each cell of its matrix. It sorts every class by its variants and maps them onto the cells as the component renders them. `fuse.css` and Tailwind fix most of what a variant means, so one shared table in `components/state-table.ts` holds that meaning for every component set. A definition such as `button-kit.ts`, `confirm-button-kit.ts`, `toggle-kit.ts`, `badge-kit.ts`, `kbd-kit.ts`, `radio-icon-button-kit.ts`, `radio-kit.ts`, `checkbox-kit.ts`, `switch-kit.ts`, `separator-kit.ts`, `skeleton-kit.ts`, `loader-kit.ts`, `label-kit.ts`, `field-text-kit.ts`, `input-kit.ts`, `textarea-kit.ts`, `avatar-kit.ts`, `meter-kit.ts`, `pagination-kit.ts`, `breadcrumb-kit.ts`, `select-trigger-kit.ts`, `empty-kit.ts`, `calendar-day-kit.ts`, `link-kit.ts`, `item-kit.ts`, `alert-kit.ts`, `accordion-kit.ts`, `sidebar-kit.ts` or `navigation-menu-kit.ts` adds only the variants its own states render, facts for variants only it uses, and its own omissions. The build stops when a definition gives a shared variant a second meaning. A definition also names the cells that show its label, so the Kbd's icon cap drops the text classes as a cell with no text. A set can draw a component that wraps another. ConfirmButton passes `confirmButtonVariants` to Button as its `className`, which Button merges after `buttonVariants` with `cn`, so `confirm-button-kit.ts` merges the two recipes the same way and imports Button's label sizes and omissions from `button-kit.ts`. A set can also draw a component that borrows another's recipe. Pagination's link and edges are `<a>` elements that `pagination.tsx` styles with `buttonVariants` and `paginationVariants`, so `pagination-kit.ts` merges the two recipes as that file does and imports Button's omissions. A component can style an element through a `className` function that React Aria calls with its render props, as `Calendar` styles each day with `cellVariants`, and as `Link` adds the state focus ring and the rac-target disabled face to `linkVariants`. Its definition's `classesFor` gives each cell the classes that function returns for the render props of the cell's state, such as `isFocusVisible` in the focus cells.

A definition can declare parts below its root, such as a checkbox's indicator. A part has its own classes, the cells it appears in, and its own parts, icons and label. Its layer takes its `data-slot` as its name, or its key when the element has none, as Radio's dot does. A part's children sit in DOM order: its parts first, then the start icons, the label and the end icons, and last the parts whose `after` names the label. A flex box that holds no icon or label of its own lays its parts out in order-modified document order (CSS Flexbox 1 §5.4): by `order`, lowest first, with the DOM breaking ties, so Command's search addon, which follows its input in the DOM, draws first through `order-first`. Elsewhere `order` stays unmapped, and the markup check reads the DOM order either way. A part can name `facts`, the variants only its own element carries, as Base UI stamps `data-orientation` on the Sidebar panel's separator while the panel's root carries none. The part's classes read them over the set's table. A part with facts holds no parts, and a fact cannot give a variant the set's table already gives a meaning: the build stops on either. The markup check reads them on the part's element. Each part becomes a frame layer and cascades its own classes. It inherits its parent's computed `color`, `font-family`, `font-size`, `font-weight`, `font-style`, `line-height`, `letter-spacing`, `white-space-collapse`, `text-wrap-mode`, `text-wrap-style`, `text-align` and `overflow-wrap`, and every custom property whose `@property` does not say `inherits: false`, at the rank the host page has on the root. Tailwind registers every `--tw-*` property with `inherits: false`, so a part takes their initial values. An icon inherits from the part that holds it the same way, so it takes its glyph color from the part's text color, and a size the part gives through a custom property reaches it. A box's `*:data-[slot=x]:` classes style each child part whose `data-slot` is `x`, as Select's trigger lays out its value. Tailwind compiles them to `:is(.… > *)[data-slot="x"]`, at (0,2,0), so they cascade with the part's own classes by that specificity and beat a bare class of the part's own. A slot no part of the definition carries, a bare `*:` and a variant after the slot stay unmapped, and a definition that omits `*`, as Label omits the Field card it can wrap, drops them. A box's `[&_img]:` classes style each `<img>` part below it, at any depth, a part with no `data-slot` whose `element` names the `img` tag, as Item's image media sizes and fits the picture a consumer puts in it. Tailwind compiles them to `.… img` at (0,1,1), so they cascade with the part's own classes by that specificity. Where no such part sits below the box, they stay unmapped. A box's `[&>input]:` classes style its direct child parts that are `<input>` elements, which Tailwind compiles to `.… > input`. A part with a `data-slot` declares its tag in `tag` for that, as Input group's control does, so the root pads it beside an inline addon. A part that declares no tag, or one deeper down, takes none, and the class stays unmapped. A box's `[:where(&>*)]:` classes style each of its direct child parts, frames and instances alike. Tailwind compiles them to `:where(.… > *)`, at (0,0,0), so a part's own class beats them, as an avatar's own ring would beat the one its Avatar group gives every avatar. The build reaches parts only, so a box that also holds a direct icon would leave that icon without the class. A box's `**:` classes style every element below it, at any depth: each part and each icon of the box and of its parts. Tailwind compiles them to `:is(.… *)`, which weighs the class and its variants, so a vertical Navigation menu trigger's `data-popup-open:**:text-accent-foreground` (0,2,0) beats its caret's own `text-muted-foreground` (0,1,0), and its `enabled-hover:**:` arm (0,1,0) beats it by its later place in Tailwind's output. The box itself and its own text, a text node and no element, keep the box's color. An ancestor's `**:` reaches the root and everything below it. A `**:` class that no element below its box takes in any cell drops, as the row link's does around its bare text, and one that reaches the element a box holds its label in stays unmapped, since the kit draws no layer for that element. A variant after `**:` stays unmapped too. A class that styles every child of its box but the last, as Tailwind compiles `space-y-4` to `:where(.space-y-4 > :not(:last-child))`, drops on a box that holds one element child, since `:last-child` matches that child, as Pagination's root holds its one row. Every element child counts, drawn or not, so the build counts a box's children only where its definition names in `undrawnChildren` how many it holds beside its parts, its icons and the element of its label, as the visually hidden `<span>` of Breadcrumb's ellipsis would be, and the markup check holds that count to the markup. On a box whose definition leaves it unset, the class stays unmapped. Between two or more children it sets a margin the kit does not draw, so it stays unmapped, and on an element around the root it drops with that element's reason. A negative `space-x-*` in a left-to-right flex row is the exception. Anywhere else, and for any other `space-*`, the class stays unmapped. `color: currentcolor` computes to the color the part inherits, so the checkbox indicator's `text-current` keeps the root's `primary-foreground`, and the coverage table records the class with what it resolved to. A class compiled below a context, as Tailwind compiles `in-data-popup-open:` to `:where([data-popup-open]) .class` and `fuse.css` compiles `item-described:` with the child combinator, holds where the definition's facts say its context holds. `[:where(&)]:` compiles a class to `:where(.class)`, which tests nothing of the cell and weighs nothing, so the class holds in every cell and loses to any plain class of the box, as a Sidebar row's `[:where(&)]:rounded-md` yields to a consumer's corner. Both together compile to a context inside the weightless `:where()`, as `in-data-[slot=navigation-menu-popup]:[:where(&)]:rounded-inner` compiles to `:where(:where([data-slot="navigation-menu-popup"]) .class)`, which weighs nothing and holds where its context holds. A variant does not always add specificity. `aria-invalid:` adds an attribute, and `fuse.css` wraps the attribute of `data-checked:` in `:where()`, so a checked invalid Radio icon button strokes with the `error` of `aria-invalid:` and `data-invalid:`, though Tailwind emits `data-checked:border-primary` later. `fuse.css`'s `item-described:` puts the class after a parent context, `:where(:has( > [data-slot="item-content"] > [data-slot="item-description"])) > .class`, so the rule weighs what the class alone weighs, (0,1,0), and the build places the class where that rule sits in the output. A value that equals the web code syntax of a synced variable binds that variable, so `px-(--control-px-button-md)` binds both side paddings to `control-px-button-md`. A radius rung compiles to the same `calc()` that the sync writes as its code syntax, so it binds too, and the compact and checkbox corners compile to the `min()` of `radius-compact` and `radius-checkbox`. A box's own custom property substitutes into its other values, so the field box's `rounded-(--field-corner)` reads the `clamp()` its `[--field-corner:…]` class declares, which binds `radius-field-box`. `rounded-full` compiles to `calc(infinity * 1px)`. CSS scales down corner radii whose sum exceeds a side, so it draws any radius above half the box's shorter side as that half. The build writes that half as a literal when both sides are fixed, 8px on Radio's 16px circle and 4px on its 8px dot. On 2026-10-22 a real file drew a 100px radius on a 16 × 16 frame and on a 64 × 16 frame the same as an 8px one, and stored 100 (probe P10), so Figma draws a radius above half the shorter side as that half, as CSS does. When one side is fixed and the other hugs or fills, the build therefore writes half the fixed side, and Figma draws it as CSS does whichever side ends up shorter. A box that fixes neither side has no length to halve, so its `rounded-full` stays unmapped. A `color-mix()` toward `transparent` binds the role tint whose code syntax it equals, so `bg-error/10` binds `error/10`, and Item's muted row binds `muted/50`. A mix of a variable without a synced tint stays unmapped, and a mix of a literal color reads as that color at the mix's share of its alpha. A length that depends on a percentage, such as `calc(4px + 100%)` in either operand order, stays unmapped too, since a Figma number field cannot hold a share of the containing block. Only a width or height of exactly `100%` reads, as a sizing. `w-fit` compiles to `width: fit-content`, the width of what the box holds when its container has room to spare, which a kit frame always has, so Label's `w-fit` reads as a hug. A `w-fit` box that holds only its text in a column's stretch fills it instead, as the parts paragraph says. A `max()` of a variable and a length binds the variable when the variable holds at least that length in every mode, and a percentage floor never binds. xs uses `max(var(--control-h-xs), 24px)` as its 24px target floor, and `control-h-xs` is 24px or more at both densities, so it binds `control-h-xs`. A shadow's blur and spread bind the same way, so the outline shadow binds the two outline shadow lengths. Values compare with the fallbacks of synced variables dropped, as Tailwind's own substitution leaves them. A background that is a literal color at alpha 0, such as `bg-transparent`, becomes no fill, because it paints nothing in CSS, and the coverage table records it as a literal. Any other value must evaluate to a number or a color, or it stays unmapped. `@elmeragroup/color` reads both the comma form of `rgb()` and the space form Tailwind compiles an arbitrary color to, such as `rgb(0 0 0/0.05)`.

### How the plugin decides what to write

- Plan and Apply run the same planning pass. The pass checks the kit against the file, matches each node and records every write as an operation, and it writes nothing. Plan lists the operations. Apply finishes the pass and loads every font the text writes need, so a duplicate key, a missing variable, a variable of the wrong type or a font this machine cannot load stops the run before any write. Then it performs the operations in order. Plan loads the fonts too, so it fails where Apply would. A label the run creates takes its family from the file's variable, which the pass resolves through the modes the new label will read.
- The pass runs as an Effect. The structural walk (pages, sets, variants, layers, instances and previews) is a set of generators that read the run's file, variables and glyph font as services and record into the `Plan` service. The field planners below them stay synchronous and record into the recorder their `Run` holds, so Effect wraps the walk and not each field comparison. An operation's write is an Effect. One that plans a new node's contents or an instance's later stages when it runs captures the services in scope when the pass records it, and plans into a recorder of its own. The run turns off Effect's cooperative yields, so it hands the thread back to Figma only where it awaits Figma.
- The build runs the half of the kit check that reads only the kit, `checkKitSpec` in `src/components/kit-check.ts`, so `figma:plugin` fails on a spec that contradicts itself before Figma sees it. The plugin runs it again at the start of each pass, beside the checks against the file's variables in `plugin/src/check-kit.ts`.
- Each field planner compares the node with the spec and records an operation only when they differ, so a second run over an applied file plans nothing. A fill, stroke or shadow matches only with the `NORMAL` blend mode the plugin writes. A text field counts as bound only when every character binds the variable.
- Writes that depend on each other share one operation. A resize or a width or height binding turns a box's hugging or filling axis fixed, so the operation that writes a length writes both axes' sizing again after it. A label's font write comes first among its writes and needs only the new font, so the plugin can replace a font this machine lacks. The spec sets the style as a literal, so the font write also clears any variable a character binds to `fontStyle` or `fontWeight`. A new node is one operation that creates the node and everything the spec puts inside it, so Plan lists it once. A new page is the exception: Plan lists it, and then each set, preview or icon library the run creates on it, because the plugin plans a page's nodes in the outer pass.
- The kit draws ⇧ (U+21E7) and ⌘ (U+2318) in Inter, the spec's `glyphFont`, since Roboto, the family `font-sans` resolves to, has neither. A browser falls back to a system font for a missing glyph and Figma does not: on 2026-10-26 a Roboto text `⇧⌘P` drew `P` alone, with a combined 13px blank advance for the two glyphs, and reported no missing font, where Inter drew both (G1). Each run of those glyphs in a label's characters takes Inter at the label's own style, and the other characters keep `font-sans`. `setRangeFontName` with another family unbinds the family on its range alone, so the text reads as two segments, Inter unbound beside Roboto bound (G2). A font write, on a range or the whole text, keeps a character's family binding where its family stays, drops it where the family changes, and binds no character (G8, G9, G10). A whole-text family binding binds only the characters already in the variable's family and changes no font, so it leaves the Inter ranges as they are (G10). A range bound to a variable that holds Inter keeps that binding through a write of Inter, and a null range binding unbinds it and keeps the font (G11). The plan reads a text's segments. It compares the label's font and family binding on the characters outside the ranges, and the ranges on their own. It writes the label's font first, then the family binding, then the ranges, which a whole-text font write gives Roboto, and then unbinds any range that still binds a family. Linking a text's characters to its TEXT property resets the whole text to the style the range writes left alone, one Roboto segment bound, at whichever end the glyphs sit, and the ranges set after the link stay (G3, G7). An instance at the property's default shows its main's ranges (G4). A TEXT write on an instance resets its text the same way, whatever the value, the default included (G5, G7), and a range set on the instance's text after the write stays until the next write, listing no font override (G6). So the plan sets the ranges on a main after its characters, and on an instance's linked text after its TEXT writes. The kit check refuses a label that shows a glyph and sets a literal family, and a nested TEXT value that shows one. ### Comparing with the browser

`figma:compare` checks the kit against the real Fuse components. It renders every instance in the preview frames with its Fuse component in Chromium and compares the two pictures cell by cell.

1. Build Fuse when `packages/fuse/dist` is missing or older than its sources, with `pnpm --filter @elmeragroup/fuse build`. The comparison renders the components and loads `styles.css` and `themes.css` from that build, and it warns when the sources are newer.
2. Run the plugin and press Export snapshots. The plugin exports each instance in the preview frames of every kit page as a PNG at 2x, cut to its render bounds so that a focus ring outside the box is included. It records each instance's box and render bounds and the modes its preview frame resolves. Figma resolves a mode only for a collection the frame's layers bind or alias into, so the export adds each mode the frame or its page pins, such as the density a Badge preview pins though no Badge layer binds a density variable. The UI downloads the result as `fuse-kit-snapshots.json`. The export writes nothing to the file.
3. Run the comparison. pnpm runs the script in this package's directory, so pass an absolute path:

   ```sh
   pnpm --filter @elmeragroup/fuse-figma figma:compare ~/Downloads/fuse-kit-snapshots.json
   ```

   The report goes to `.cache/figma-compare/` in this package, or to the directory `--out` names. `--threshold` sets pixelmatch's threshold, 0.1 by default. The run needs Playwright's Chromium, which `pnpm --filter @elmeragroup/fuse-figma exec playwright install chromium` installs.

The browser renders one page per preview:

- The page stamps the preview's theme the way Fuse applies one: `data-theme` and `data-density` on `<html>`, and `data-theme-variant`, `data-theme-brand` and `data-theme-segment` on `<body>`. A brand mode maps to its brand by display name, and `Auto` density maps to the variant's default.
- It names the layers in the order `styles.css` declares them, then loads Tailwind's preflight in the `base` layer, Fuse's standalone `styles.css` and `themes.css`, and sets `font-sans text-foreground` on `<body>` as the docs layout does. Roboto comes from `@fontsource/roboto`, which serves Google's Roboto, the family Figma renders. Preflight loads before `styles.css`, as in a Tailwind-source host, because its `border: 0 solid` and Fuse's base border rule share the `base` layer and the later one wins. In the other order the outline Badge draws its border in the text color. The run checks every element in a cell's measured element that holds text, an input's value or placeholder included, and stops when a face that text uses has not loaded, so the text never falls back to a system font. Text a renderer draws around the measured element, such as the month heading of the Calendar a day cell sits in, which takes the theme's heading font, Neo Sans in Fjordkraft's external themes, stays out of the check, since the comparison never shows it.

2. Add a renderer module beside `compare/button-cell.ts`. Only a parent part that holds such a part matches one by place, so the bare `<span>` Base UI puts around a Dropdown menu row's Check belongs to the indicator, which lists the Check as an icon inside a span. An empty element whose `data-slot` names a part the cell does not render is no part where its box counts undrawn children, as a checkable row's indicator `<span>` waits empty while unchecked. A part with no `data-slot` can name its element in `element` instead, as a root does, and matches the element below its parent part's element that the selector matches. A part with a `styleFor` must carry exactly those declarations in its `style` attribute, in order, and a part without one no `style`, so the fill widths Figma draws are the ones Base UI writes. The elements around the measured element carry each ancestor the definition's `ancestorsFor` names, outermost first, with its `data-slot` and exactly its classes, and no other element with a `data-slot` sits between the outermost of them and the root, so a renderer that drops Textarea's Field root or puts Breadcrumb's separator in an item fails. An element outside the outermost ancestor, such as `Breadcrumb.Root`, which carries no class, is not checked. A group variant holds exactly where an ancestor of the element it styles matches it, as `group-data-disabled/field:` holds below a Field root that carries `data-disabled`. For a variant the root's own classes name that is an ancestor of the measured element, and for one a part or an icon names it can be the measured element itself, as Select's caret turns below its open trigger. A peer variant holds exactly where a sibling before the measured element matches it, as `peer-data-active/menu-button:` holds after an active Sidebar menu button. A `has-[>…]:` variant holds exactly where the element that names it holds the child it reads, as an Input group's root holds its own disabled control and its addon a `<button>`, and an instance part's `has-[>…]:` or `group-has-…:` fact holds where the instance's element, or a group around it, holds that child or descendant. The root and each part hold their label's characters where the cell shows the label, as their own text, after a space where the label's `leadingSpace` says so. In a cell where the label's `textAttribute` names an attribute, they hold them there and no text of their own, as an `<input>` holds its placeholder in `placeholder` and its value in `value`. A `<textarea>` holds its placeholder in `placeholder` and its value as its own text. Where the label's `textElement` names a child element, the box holds no text of its own, and the one child that selector matches holds the characters and carries no `class` or `style`, as Pagination edge's bare `<span>` holds `Previous`. Attribute values read with React's entities decoded, as text does. A box that shows an image is an `<img>` whose `src` is a data URI of the image's bytes, and a box that shows none carries no `src`. It fails when a definition's facts, states or recipe conditions name an attribute or group variant its lists lack, so add a new one, such as `data-checked:`, with the attribute it selects. `placeholder:` holds where the element has a placeholder and no value, in `value` or, on a `<textarea>`, as its own text. `invalid:` holds where an element marked `data-rac` carries `data-invalid`. On a root marked `data-rac`, `hover:` and `enabled-hover:` hold exactly where the renderer's `forcedAttributes` carry `data-hovered`.

`report.html` opens from disk. It starts with a summary per preview and then lists every cell worst first. Each cell shows three pictures: Figma's export, the browser's crop, and the diff, which marks differing pixels red and anti-aliasing yellow. Figma's export and the browser's crop sit over the theme's background with the boxes' top-left corners aligned. Filters select a preview, a value of each variant axis, or only the flagged cells. `report.json` holds the same rows.

- Check box sizes first. Δ is Figma's box minus the browser's, in pixels. The `size` flag marks a side that differs by half a pixel or more, and such a cell goes to the top. `subpixel-size` marks a smaller difference, beyond Chromium's 1/64 px layout rounding.
- Mismatch is the percentage of the browser box's area, at 2x, whose pixels differ. The tolerant count leaves out the pixels that pixelmatch takes for anti-aliasing, and the raw count includes them. Figma and Chromium draw text differently, so a matching cell still shows some mismatch along the label. Mismatch away from text and edges points at a real difference.
- A Textarea or Textarea field cell differs in its bottom-right corner, where Chromium draws a resize grip and the kit draws none. That mismatch is expected.
- `png-size` marks an export whose size differs from its render bounds. `state-by-interaction` marks a cell that needed a real hover or focus. `state-missing` marks a cell whose state the browser could not show, so its browser picture is wrong. `no-figma-image` marks an instance Figma drew nothing for.
- A hover or focus cell whose built variant equals its resting twin's is unchanged by design, such as a pressed Toggle on hover, which `aria-pressed:` and `enabled-hover:` paint with the same `muted`. The comparison takes each `Fuse tokens` color both variants bind at its value in the preview's theme, from the theme catalog, so a cell whose colors differ only by name is unchanged by design in a theme that gives the two tokens one color: a hovered Sidebar menu badge paints `sidebar-accent-foreground` where it paints `sidebar-foreground` at rest, and the internal themes give both one color. The page tries no real hover or focus on such a cell. When the browser shows no change for it, the cell gets no `state-missing` flag, and the report notes it as unchanged by design. The run builds the component sets with `buildComponentSets()` in its own process, so the expectation follows the recipes the browser renders.
- The report lists an instance it cannot render as skipped, such as one whose variant has an axis the comparison does not know.

The first comparison of the test file, on 2026-10-20, covered 756 cells in the 12 previews:

- Every height matched, and every Icon button matched to the pixel apart from anti-aliasing.
- Every Button was wider in Figma, by less than a pixel: 0.41px at 12px type, 0.47px at 14px and 0.61px at 18px. Figma rounds an auto-width text layer up to a whole pixel. Its Roboto matches the browser's, so three labels in a row are 125px wide in Figma and 124.59px in Chromium. The rounding moves the right edge and nothing else. The worst cell differs by 2% of its pixels, all of it that edge and text anti-aliasing.
- A fixed label width could match the fraction, but then the label would not grow when a designer edits it, so the kit keeps auto width.

At the comfortable density, the Combobox popup and its rows are 8px narrower in the browser than in the kit: 366px and 358px, against the kit's 374px and 366px. Base UI sizes the popup from the `<input>` inside the Input group, and the caret addon beside the `<input>` is 8px wider at comfortable. A Figma width follows density only through a synced variable, and a variable for this width would bake in the kit's 384px Input group, so the kit draws the dense widths at both densities.

`figma:compare --self-check` tests the comparison itself. It renders every cell of the kit's preview frames in each of two themes and saves them as a fake snapshot whose render bounds reach 3 pixels past each box, each PNG holding every device pixel its render bounds touch, so a 3px ring on a box of fractional width keeps its last column. A client cell's render bounds reach the browser crop's whole 8px padding instead, so a popup's shadow stays in its PNG, as Figma's export holds a node's effects. It paints a square into the kit's first hover cell and widens the box of its first focus cell by a pixel, in registry order, and then it compares the snapshot with a second render. It passes when those two cells lead the report and every other cell matches exactly. The kit's client cells, popups and open composites among them, go through the same mount, measure and forced-state paths twice and pass the markup check on the mounted page. A `Select item` cell at rest must also show no fill just inside its start edge, and a highlighted one the theme's `accent`, as Fuse's built `focus:bg-accent` paints it. On 2026-10-24, hand-written overlay fixtures that the kit's Popover, Dropdown menu and Select sets have since replaced showed two failures. Without the mount's settle step and the page's check of it, the highlighted Select item read `state-missing`, since its resting twin kept the focus Base UI gave it. With the Dropdown menu item's `focus:bg-accent` and `focus:text-accent-foreground` rules removed from the built `styles.css`, the self-check flagged the highlighted item `state-missing` in both themes.

The tests run the whole command line against `test/in-memory-figma.ts`. That fake file applies batches with the REST API's documented rules, stores numbers as 32-bit floats and resolves aliases the way Figma renders them. Where the documentation is silent, the fake does what a real Enterprise file did on 2026-10-16. It replaces code syntax on an update, it checks for an alias cycle after each value a batch sets, and it refuses any cycle, even one that closes only across modes. It deletes a collection with its modes and variables and keeps an alias into it until a later value in the batch replaces it, as a real Enterprise file did on 2026-10-19 when one batch deleted `Fuse themes` and then rewrote the `Fuse tokens` aliases into it. It also applies the scope rules on the REST API's [variable types page](https://developers.figma.com/docs/rest-api/variables-types/). It rejects a scope the page does not list for the variable's type, such as `GAP` on a color, `ALL_SCOPES` beside another scope, and `ALL_FILLS` beside another fill scope. It follows a real Enterprise file where that file departed from the page on 2026-10-16. It keeps `FONT_STYLE` on a number variable and stores `FONT_WEIGHT` there as `FONT_STYLE`. It stores a description with `&`, `<`, `>`, `"` and `'` HTML-escaped, as a real Enterprise file did on 2026-10-19. Tests can also make it answer with a status, drop a connection, or hold values and types newer than the sync.
