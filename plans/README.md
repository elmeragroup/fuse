## Findings considered and rejected

From the branch audit (2026-08-21). Recorded so they aren't re-audited:

- **`turbo lint` depends on `@elmeragroup/ui#build`** — deliberate and documented
  (`turbo.json` comment, theming.md §7.7); verdict was "revisit if lint latency bites."
  Not a finding.
- **`demo-stage-comfortable.css` export resolves to `dist`** — same trade as the
  pre-existing `themes.css` export; `turbo dev` already depends on builds.
- **`themeAxisDeps` optional-axis reads / `NestedThemeValidator` hook-order shape** —
  documented design (ADR 0003, theming.md §7.6): validation must throw only after hooks
  register.
- **Unescaped attribute interpolation in `applyHostRootAttributes`** — inputs are
  compile-time internal constants in a build-time Vite adapter; not attacker-reachable.
- **`LEGAL_THEMES` type precision trade** (`as const` tuple → `readonly ThemeInput[]`) —
  conscious decision noted in the thermo-nuclear review; nothing consumes literal element
  types.
- **Reimplement `.DemoStage` comfortable density as Tailwind utilities** — rejected for
  plan 003. The values are generated from the library's signed density contract and the
  `.DemoStage[data-density="comfortable"]` selector is normative; the docs app must import
  that artifact rather than copy or reinterpret it.
