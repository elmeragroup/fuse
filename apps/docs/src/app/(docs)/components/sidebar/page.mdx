On mobile, the navigation sheet includes a visible close button above its content.

<Prose>

`Sidebar.Provider` writes the desktop open state to the `sidebar:state` cookie on every change, so a server layout can read it with `cookies()` and pass `defaultOpen` for a first paint that matches.

</Prose>

<Prose>

A Sidebar inside a box on the page, such as an embedded app pane or a demo, takes `bounds="container"` on `Sidebar.Provider`. It fills the box's height, so the box needs a defined height. The desktop rail stays inside the box. The Provider writes no cookie, so a host that wants the state kept passes `open` and `onOpenChange`. ⌘B, or Ctrl+B, toggles it only from inside the Sidebar, so a page Sidebar around it keeps the shortcut everywhere else. The mobile Sheet still switches on the viewport's width. The demos below use it.

</Prose>

<Prose>

Below 768px `Sidebar.Root` becomes a Sheet. Its open state is session-only and starts closed. A host that closes it from outside, such as after a navigation, passes `openMobile` and `onOpenMobileChange` to `Sidebar.Provider`. The Trigger, ⌘B, the Sheet's own dismissal and `useSidebar().setOpenMobile` then report through `onOpenMobileChange`, and the host decides.

</Prose>
