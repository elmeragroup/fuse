<Prose>

`DateRangePicker` lives at `@elmeragroup/ui/react-aria/date-range-picker`. The
`react-aria/` prefix is the quarantine marker: this module is replaced alongside
`DatePicker` when base-ui ships a popover-backed range picker, and the bare path is
reserved for that successor. The composite face is optional `label` /
`description`, `errorMessage` as a `ReactNode` or `(ValidationResult) => ReactNode`,
and `shouldForceLeadingZeros` defaulting to `true`. `value`, `defaultValue` and
`onChange` speak the RAC range shape, `{ start, end }`, and the remaining RAC
DateRangePicker props (`minValue` / `maxValue`, `granularity`,
`isDateUnavailable`, `allowsNonContiguousRanges`, `startName` / `endName`,
`isOpen` / `onOpenChange`, …) pass through. There is no preset pane here — that
stays a `DatePicker` feature.

The two rows are the same `DateInput` segment row `DateField` renders, and the
popover holds the same `RangeCalendar` grid — so segment editing, keyboard range
selection and RTL behaviour all match those entries. The en dash between the rows
is decoration: React Aria names the rows on the segments themselves ("month, Start
Date" / "month, End Date"), so nothing is announced twice. Wrap locale-dependent
usage in `UiProviders` from `@elmeragroup/ui/react-aria/ui-providers`.

`onChange` reports whole ranges only, so typing one row and stopping reports
nothing. In the calendar the first click anchors the range and the second commits
it and closes the popover; Escape cancels an in-progress selection, dismisses the
popover and returns focus to the trigger. A read-only picker keeps its popover
shut and fills the field with the muted surface.

</Prose>

<Prose>

An end before its start is invalid on its own, as are endpoints outside `minValue`
/ `maxValue` or on an unavailable date. All of them drive `FieldError`, which takes
either a node or a function of the `ValidationResult`.

</Prose>

<Prose>

The popover portals into the nearest `ThemeScope`, so it inherits the theme of the
surface that opened it, and `container` overrides that target when you need a
specific one. Interacting with the popover never dismisses the overlay hosting the
picker: anchoring and committing a range inside a dialog leaves the dialog open.

</Prose>
