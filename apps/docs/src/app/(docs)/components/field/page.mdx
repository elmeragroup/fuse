<Prose>

`Field.Error` without children shows the field's own message instead: an error from `Form`'s `errors` under the field's name, a `validate` result, or the browser's constraint message, which is in the browser's language rather than the app's. Pass children, or a `validate` that returns your own copy, when the message has to be localized or validation lives outside the field.

Put `Field.Error` directly after the control, ahead of any `Field.Description`, so the message sits right under a field in error. The labeled composites, such as `TextField` and `SelectField`, place theirs there too.

</Prose>

<Prose>

A `Field.Description` inside a `Field.Set` but outside any `Field.Root` describes the fieldset through `aria-describedby`. Inside a `Field.Root`, it describes that field's control instead.

</Prose>

<Demo slug="field" id="set-description" title="Field set description" file="field-set-description.tsx">
  <FieldSetDescriptionDemo />
</Demo>

<Prose>

`Field.Legend` renders a `div`, so a grid `Field.Set` places it in the first cell. Pass `render={<legend />}` to render a native legend instead. The browser keeps a fieldset's first `legend` out of the grid, so the first field takes the first cell, and the legend still names the set.

</Prose>
