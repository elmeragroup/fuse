<Prose>

`NavigationMenu.Root` renders a `<nav>` landmark, so name it with `aria-label`. It also
renders the popup that every `NavigationMenu.Content` opens into. Moving between triggers
resizes that one popup rather than opening a second. `side` and `align` place it against the
open trigger, under it by default.

A trigger opens on hover, on click, and on Enter or ArrowDown. Escape closes the panel
and returns focus to the trigger. Mark the current page's link with `active`, which sets
`aria-current="page"`. For a router link, pass it through `render`.

For a menu of actions, use DropdownMenu.

</Prose>

A link can hold more than a label. Give it a title and a one-line description, and lay a
panel's links out in a grid.

A `NavigationMenu.Root` inside a `NavigationMenu.Content` is a submenu. It renders a `<div>`
rather than a second landmark, and it opens its own popup. Set `orientation="vertical"` and
`side="right"` so it opens beside its trigger while the outer panel stays open.

An `inline` submenu renders no popup. Place a `NavigationMenu.Viewport` beside its list, and
the open item's content shows there, so the panel swaps as the pointer moves down the list.
The arrow keys move focus between triggers, and Enter or Space shows the focused trigger's
content. Its triggers have no caret, because the content is always in view. `defaultValue`
opens the first item with the outer panel. Below the `sm` breakpoint the list stacks above
the viewport.

For client-side routing, pass your router's link to `NavigationMenu.Link` through `render`.
The link keeps its `active` state and `aria-current`.
