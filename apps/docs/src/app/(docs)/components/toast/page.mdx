These examples render notifications inside their own preview areas so different examples can run together. In an application, use one provider and viewport for the shared notification stack. Handle the promise returned by `toastManager.promise`; the error toast does not consume its rejection. A `type` returned from `success` or `error`, such as `"warning"`, sets the settled status and its priority. Omit `loading` to show no toast until the promise settles. A loading toast the user closes stays closed when the promise settles.

## Viewport placement

From the `sm` breakpoint up, `placement` on `Toast.Viewport` puts the stack at the top or bottom edge, aligned left, center or right. The default is `"bottom-right"`. A top placement stacks downward and slides toasts in from above. Toasts dismiss by swiping toward the edge they sit on and toward their side, or right for a centered stack; set `swipeDirection` on `Toast.Root` to choose other directions. On narrower screens every placement sits at the bottom, spans the screen width and swipes down or right.

## Toasts outside React

Code outside the React tree, such as a timer or a query-cache listener, raises toasts through a manager from `Toast.createToastManager()`. Create it at module scope and pass it to `Toast.Provider` as `toastManager`. The manager queues calls made before the provider connects, including calls made before it mounts and calls from mount effects in its subtree, and replays them in call order once it connects. `add` returns the toast id at once, so a queued toast can still be updated or closed. Mount the manager in one provider at a time.
