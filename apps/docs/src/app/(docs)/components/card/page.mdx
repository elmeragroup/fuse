A card pads its sections, and spaces them, with a surface tier. The default size takes the medium tier, 16px comfortable and 12px dense, which Items and Accordion items pad with too, so the text in a card starts on the same edge as theirs. `size="lg"` takes the large tier, 24px comfortable and 16px dense, for a card that holds long prose or acts as a page's main panel. A card nested in a large card takes its own size.

A card draws its 1px edge in the theme's `--card-border` and casts a small shadow in `--card-shadow`. Internal themes draw the edge in `--border` and the shadow in black at 5%. External themes draw neither, so a white card stands on the page tint by its fill alone, and a card on a card-coloured surface, such as a nested card, has no outline. A border colour class or a shadow size class such as `shadow-md` on the card still wins, and a shadow colour class tints the card's own shadow. To change the edge or shadow colour, override `--card-border` or `--card-shadow` on the `ThemeScope` or on any element around the cards.

A vertical card's body can be split into stacked sections of equal weight with `Card.Section`, under one optional `Card.Header`. Each section pads every side with the card's tier, so it follows the card's `size`, and a 1px line in the theme's `--card-section-divider` runs above every section that has a part above it, from edge to edge. Internal themes draw the line in `--border`, and external themes in the page tint, `--background`, so the card reads as split into segments. The first and last sections round with the card's corners, so a fill or a hover fill follows them. A `Card.SectionMedia` before a `Card.Content` makes the section a two-column grid with the icon centred beside the content. Inside a section, `Card.Content` is that column and drops its own padding, since the section pads.

Sections are the whole body, so put no `Card.Content` or `Card.Footer` beside them. A footer after sections takes no line and no top padding, so it reads as part of the last section; put that content in a last section instead. Sections take no `direction`: a horizontal card pads itself, so sections belong in a vertical card.

`Card.SectionButton` makes a whole section one button. It stacks, divides and rounds like a `Card.Section`, renders `<button type="button">`, takes a hover fill and a pointer cursor, and draws its focus ring inside its own edges, so the sections around it cannot cover it. `render={<a href="/terms" />}` makes it a link; mark an unavailable link `aria-disabled="true"`, and it dims and does not navigate. A trigger composes it as it composes `Button`: `<Dialog.Trigger render={<Card.SectionButton />}>`. Hold text, an icon or a `Card.SectionMedia` in it, and no other control. `Card.Section` itself stays a static, server-rendered part.
