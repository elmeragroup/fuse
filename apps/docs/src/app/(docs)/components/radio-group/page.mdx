<Prose>

`RadioGroup` is the labeled composite: `label` / `description` / `errorMessage`
(`ReactNode`), `isPending`, `isDisabled` / `isInvalid` / `isReadOnly` /
`isRequired`, and `onChange(value)` as a `string`. Controlled `value` is
`string | null`; `null` is passed through to the primitive so the group stays
controlled with nothing selected.

The header row renders when `label || isPending` is truthy. `isPending={false}`
with no label does not emit an empty legend. The pending indicator is Phosphor
regular `SpinnerGap` (`size-3 animate-spin`) and is decorative — announce
pending in a consumer live region if it must be spoken.

Base-ui's radio-group primitive accepts `name`, so `RadioGroup` sets `name`
directly on that primitive. `CheckboxGroup` threads `name` through Field
instead because its primitive has no `name`. Both faces still expose
`name?: string`.

`RadioItem.Title`, `.Description`, `.Content`, `.Actions`, and `.SubSection`
are the **same objects** as `SelectionItem.*`. Direct `RadioItem.SubSection`
children stay outside the row label so interactive content does not change
selection. Wrapping one in a Fragment hides it from that filter.
`controlPosition` passes through to `SelectionItem.Shell`.

The 16px radio expands its hit target with `after:-inset-x-3 after:-inset-y-2`
— adjacent interactive elements need clearance. A checked radio in an invalid
group keeps the primary border (`aria-invalid:aria-checked:border-primary`).

`RadioIconButton` is mechanically icon-only, so `aria-label` is required.
Its resting surface is `bg-card`. The `size` map is decorative, not a density
rung.

</Prose>
