<Prose>

`DateRangePickerField` from `@elmeragroup/fuse/date-range-picker` is the Temporal replacement for the interim [React Aria DateRangePicker](/components/date-range-picker), with its prop names, `startName` and `endName` included. Its value is `{ start, end }`, each end a `Temporal.PlainDate`, `PlainDateTime` or `ZonedDateTime` object, typed as [DateField's](/components/temporal-date-field) value is; `onChange` hands back this runtime's range once both ends hold a value, and `null` as soon as a whole range loses an end, as React Aria reports it; the other end stays in its input. Build a value in a client component: a Temporal object a server component passes reaches the client as ISO text, which the component refuses with a `TypeError`. [Temporal for dates](/quick-start#temporal) shows a server component handing its text to a client component that builds the value.

Fuse reads `globalThis.Temporal`. Import `@elmeragroup/fuse/temporal-polyfill` once in your app's entry, on the server and in the browser.

Type each end into its segments, or open the calendar: the first day pressed anchors the range and the second completes it and closes the popup. Typing the start's last segment moves on to the end's first, and Backspace in the end's first empty segment goes back. Escape drops a half-picked range first and closes the popup on the next press. An end typed before its start, or a start typed past its end, commits and shows as invalid on the end once focus leaves: "Start date must be before end date."

</Prose>

## Dates and times

With a time `granularity` the popup shows a start and an end time input under the calendar, with the field's `hourCycle` and `hideTimeZone`. Typing an end's time changes only that end's time. With `shouldCloseOnSelect={false}` and no range yet, a range picked in the calendar is held until both ends have a time typed there, then commits; closing the popup first commits it with midnight for an end without one. Composing the parts, put `DateRangePicker.StartTimeInput` and `DateRangePicker.EndTimeInput` in the popup after the calendar.

## Presets

`presetGroup` takes `DateRangePicker.Presets`, a radio group of your keys: map the chosen key to a range and set the picker's value, or give a preset its range as `dateValue`, `{ start, end }`, which every press sets through `onValueChange` with the reason `"preset-press"`, as `DatePicker`'s presets do. With a preset pane, focus leaving the calendar drops a half-picked range instead of completing it, since leaving the grid then means reaching for a preset.

## In a form

Each end is a Field of its own: the start submits its ISO text under `startName` and the end under `endName`, a `Form` error under either name shows in the picker's one error and focuses that end's first segment, and a required empty end blocks the submit. The label, the description and the error belong to the whole picker and describe both ends.

</Prose>

## Parts

`DateRangePicker.Root` holds the range and the open state, with `onValueChange` and `onOpenChange` passing cancelable details as `DatePicker.Root`'s do; the range adds the calendar's `"outside-press"` and `"focus-out"` reasons. Compose `DateRangePicker.Label`, `DateRangePicker.Group` with `StartInput`, `Separator`, `EndInput` and `Trigger`, then `Error`, `Description`, `Popup`, `Calendar`, `StartTimeInput` and `EndTimeInput`.

## Accessibility

- **One group, two named ends.** The field box is a `group` named by the label; the segments are named by their unit, their end and the label: "month, Start Date, Stay".
- **One error for both.** Each end's own message and the form's errors under both names merge into one error, which describes the group and both ends.
- **The calendar.** The trigger and the `dialog` are named "Calendar Stay". The range calendar names the range's ends with the whole range.
