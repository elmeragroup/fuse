<Prose>

The whole row is a `Field.Label`, so clicking the title or description toggles the
plugged-in control. `SelectionItem.SubSection` is pulled **outside** that label by
identity (`child.type === SelectionItem.SubSection`) on **direct** children only —
interactive content in the band must not select the row. Wrapping a SubSection in a
Fragment, another component, or an HOC hides it from the filter; it then renders
inside the label and clicks toggle the control. That fragility is kept from the
reference, not fixed.

`controlPosition="end"` puts the control after the row children. The sub-section
indent spacer derives its width from the actual control slot so a trailing or wide
custom `control` still lines the extra content up with the text column.

Stacked shells drop the shared top border (`not-first:border-t-0`) and a checked
non-first row repaints that edge in `primary` by pulling itself up one pixel
(`-mt-px`) instead of a z-index lift. A `className` margin override can break the
repaint.

</Prose>
