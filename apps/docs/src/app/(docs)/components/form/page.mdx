## Usage

{/* prettier-ignore */}
```tsx
import { Form } from "@elmeragroup/fuse/form";
import { TextField } from "@elmeragroup/fuse/text-field";

<Form onFormSubmit={(values) => save(values)}>
  <TextField label="Email" name="email" isRequired />
</Form>
```

## Composition

<Prose>

Put each control in a `Field.Root`, or use a field component such as `TextField`, which renders its own. `Form` finds the fields by `name`: it shows `errors` on them and passes their values to `onFormSubmit`. The fields show their constraint messages through `Field.Error`, and the browser's own bubbles stay off.

When a schema decides validity and a change in one field can make another valid, use a plain `<form noValidate>` instead. Run the schema in your submit handler and pass each field its result: `isInvalid` and `errorMessage` on `TextField`, or `invalid` on `Field.Root` and the message as the children of `Field.Error`. A field still checks its native constraints when the user presses Enter in it, so for a rule the schema can relax, pass `aria-required` or `inputMode="email"` instead of `isRequired` or `type="email"`. A plain form does not focus the first invalid field, so move focus there yourself.

</Prose>
