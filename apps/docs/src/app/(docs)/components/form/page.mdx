<Prose>

`errors` maps the names of the controls to one message or several, typically what a server returned after a submit. A `Field.Error` without children shows the error under its control's name, and so does `TextField` when it gets no `errorMessage`. Editing a field clears its error, and a new `errors` object, such as the next response, shows them again. After a submit, `Form` focuses the first field the new errors mark.

`onFormSubmit` receives the values of the fields inside the form and prevents the native submit; leave it out to submit natively or to a form action. The browser's own validation bubbles stay off: the fields show their constraint messages through `Field.Error` instead.

</Prose>

<Prose>

The interim react-aria fields, such as `DatePicker`, read React Aria's own form context and do not see `errors`. Pass them `errorMessage` and `isInvalid`.
